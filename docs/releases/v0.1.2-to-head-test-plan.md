## 3. 版本差异专项测试用例 (Test Suites)



### Suite 1: SQL 编辑器与 4-Modal 执行策略



#### 用例 TC-SQL-01: 4 模式执行策略（Current / All / Selection / Ask）

- **测试目标**：验证不同执行模式对多语句文本的切割与执行准确性。
- **前置条件**：打开包含 3 条不同 SQL（`SELECT 1; SELECT 2; SELECT 3;`）的查询面板。
- **操作步骤**：
  1. 切换执行模式为 **Current**，光标放置在第 2 句，点击运行（或按快捷键 `Cmd+Enter`）；
  2. 选中文本中的第 1、2 句，切换模式为 **Selection** 并运行；
  3. 切换模式为 **All**，点击运行；
  4. 切换模式为 **Ask**，点击运行，观察弹出的选择对话框并确认。
- **预期结果**：
  - Current 模式仅执行第 2 句，结果集仅包含第 2 句的数据；
  - Selection 模式仅执行被高亮的前两句；
  - All 模式按顺序依次执行 3 句并呈现对应的结果页签；
  - Ask 模式调起 `ExecutionStrategyAskModal`，用户选定模式后无缝执行。



#### 用例 TC-SQL-02: 绑定参数安全拦截（防止静默执行 NULL）

- **测试目标**：验证未赋值的参数占位符被前置拦截，防止意外写入 NULL。
- **测试数据**：`UPDATE users SET status = :status WHERE id = :user_id;` 或 `SELECT * FROM tbl WHERE id = ?;`
- **操作步骤**：
  1. 在编辑器中输入上述含有占位符的 SQL；
  2. 故意不向参数面板填充值，直接触发执行。
- **预期结果**：
  - `validateBindParams` 立即阻断执行并高亮报错；
  - 拦截提示明确标出缺失的参数名称（如 `:status`, `:user_id`），网络/数据库未产生任何实际调用；
  - 填入合法参数值后，执行成功。



#### 用例 TC-SQL-03: 高危 SQL 两阶段风控门禁 (Dangerous SQL Gate)

- **测试目标**：验证无 WHERE 约束的破坏性操作能被安全拦截并要求确认。
- **测试数据**：`DELETE FROM customers;` 及 `DROP TABLE logs;`
- **操作步骤**：输入测试 SQL 并尝试执行。
- **预期结果**：
  - 触发 `useQueryExecutionGate` 拦截，弹出红色高危警示弹窗；
  - 强制展示预计影响风险与表名称，用户必须显式点击“我已知晓风险，继续执行”方可提交。



#### 用例 TC-SQL-04: DML 状态反馈与影响行数（解决 PG 提示误导）

- **测试目标**：验证执行 INSERT/UPDATE/DELETE/DDL 时状态卡片准确展示。
- **操作步骤**：连接 PostgreSQL，执行 `INSERT INTO demo (name) VALUES ('zen');`。
- **预期结果**：
  - 结果区不再展示“暂无可显示的行 此查询没有返回任何行”；
  - 展示 `ExecutionSummaryCard`：显示“执行成功”、“受影响行数: 1”及毫秒级耗时。



#### 用例 TC-SQL-05: SQL Snippets 插入与可配置格式化

- **测试目标**：验证内置代码片段与美化工具。
- **操作步骤**：
  1. 在工具栏点击 Snippet 菜单，选择常用模版（如 `SELECT * FROM ... LIMIT 10`）；
  2. 输入未缩进的凌乱 SQL，点击格式化按钮（Beautify）。
- **预期结果**：代码片段准确插入光标处；格式化规范对齐关键字大写与换行缩进。



#### 用例 TC-SQL-06: 查询资产中心（历史直达 Tab、Pin 结果集）

- **测试目标**：验证历史查询与结果固定的可用性。
- **操作步骤**：
  1. 在 `ConnectionWorkspaceHome` 页面点击一条最近执行过的历史卡片；
  2. 在结果集上方点击 Pin 按钮，然后执行一条新的查询。
- **预期结果**：
  - 点击历史卡片后，直接在当前连接下开辟新查询 Tab 并预填该 SQL，光标自动聚焦；
  - 被 Pin 的结果集在新查询执行后保持保留，新结果以追加 Tab 形式呈现，互不覆盖。



#### 用例 TC-SQL-07: Pro 特权扩展与社区版 Fallback 对比验证

- **测试目标**：验证双版本架构隔离有效性。
- **操作步骤**：分别启动 Community 版与 Pro 版。
- **预期结果**：
  - **Community 版**：编辑器运行基础智能补全，无 Pro Gutter 运行按钮与外键联查，控制台无报错；
  - **Pro 版**：成功激活 `@datazen/extension-sql-editor-pro`，支持外键智能 JOIN 补全、列补全与 Gutter 执行按钮。

### Suite 2: 数据库结构比对与迁移引擎 (Schema Diff IR & DAG)



#### 用例 TC-SD-01: 方言中立 Migration IR 与比对生成

- **测试目标**：验证不同结构（新增列、修改类型、主键变更）能准确映射为统一 IR。
- **测试数据**：源表具有新列与自增主键，目标表无该列。
- **操作步骤**：发起 PostgreSQL 到 PostgreSQL 的结构对比。
- **预期结果**：
  - 生成精确的 `MigrationOperation::AddColumn` 与主键调整计划；
  - 依赖关系识别正确，外键表排在被引用主表之后。



#### 用例 TC-SD-02: 依赖图 DAG 拓扑排序与循环依赖探测

- **测试目标**：多张具有互相关联外键的表比对迁移。
- **操作步骤**：构造 A 依赖 B，B 依赖 C 的多表 DDL 进行 Diff。
- **预期结果**：
  - 部署计划中表的生成顺序严格为 C -> B -> A；
  - 若存在双向外键循环依赖，系统主动降级拆解为“先建表无外键 -> 再 ALTER 补全外键”，避免建表失败。



#### 用例 TC-SD-03: 部署任务取消与 JobRegistry 控制

- **测试目标**：验证大规模 DDL 部署时的中止能力。
- **操作步骤**：对包含 50+ 个对象的部署任务点击“取消”。
- **预期结果**：部署任务优雅终止，未执行的语句不再下发，界面实时呈现已完成/已取消状态。



#### 用例 TC-SD-04: 类型收窄与非空风险预警

- **测试目标**：将 `VARCHAR(255)` 修改为 `VARCHAR(50)`，或将可空字段改为 NOT NULL。
- **预期结果**：Diff 结果列表清晰打上“类型收窄风险（Type Narrowing Risk）”或数据截断黄色告警标签。

### Suite 3: 深度安全整改与后端健壮性 (Security & Panic Defense)



#### 用例 TC-SEC-01: SQL Guard 注释剥离与隐蔽注入防御

- **测试目标**：验证无法通过注释绕过只读/安全模式检查。
- **测试语句**：
  ```sql
  SELECT 1; /* DROP TABLE users; */
  -- UPDATE account SET balance = 0;
  SELECT /**/ 1;
  ```
- **预期结果**：
  - `strip_sql_comments` 准确清洗注释；
  - 只读模式下若试图在注释之外嵌入写入动词均被拦截，而包含无害注释的查询正常执行；
  - 空注释 `/**/` 不产生语法解析崩溃。



#### 用例 TC-SEC-02: IPC 错误全局敏感信息自动脱敏

- **测试目标**：验证连接失败或报错时凭据不外泄。
- **操作步骤**：故意输入错误的数据库连接密码并连接。
- **预期结果**：返回的 IPC 错误 JSON 中，密码参数被遮罩为 `*`**，本地磁盘物理路径被安全脱敏。



#### 用例 TC-SEC-03: 读写锁中毒恢复与并发稳定性

- **测试目标**：验证单任务异常不会导致后端死锁。
- **操作步骤**：通过测试 Harness 模拟单一执行线程 panic。
- **预期结果**：其他并发查询与连接会话正常响应，锁中毒被自动清除，应用无卡死崩溃。



#### 用例 TC-SEC-04: Workflow 调度器槽位防泄漏

- **测试目标**：验证异常任务下工作流槽位正常释放。
- **预期结果**：发生失败后，`InFlightGuard` 自动重置并发计数，后续工作流排队任务顺畅执行。



#### 用例 TC-SEC-05: 备份导入防覆盖主密钥保护

- **测试目标**：导入已有的全量数据备份包。
- **预期结果**：若导入包中含有密钥文件，系统默认阻止覆写本地 `.key`，必须勾选显式同意选项。

## 4. 自动化测试执行流水线与命令手册

为保证 CI/CD 与本地开发质量闭环，执行以下标准化测试指令：

### 4.1 本地快速全量质检 (Full Local Quality Gate)

```bash
# 运行集成自检（代码格式、类型检查、多语言同步、单元测试）
pnpm ci:local
```



### 4.2 前端与驱动 UI 单元测试

```bash
# Host 前端单元测试
npx vitest run

# 驱动专属 UI 单测 (packages/drivers/*/ui)
pnpm test:unit:drivers

# 连续旅程测试专项验证
npx vitest run src/windows/connection/__tests__/queryExecutionJourney.test.tsx
npx vitest run src/components/sql-editor/completion/__tests__/sqlTypingJourney.test.ts
```



### 4.3 后端 Rust 核心与契约单测

```bash
# Host 后端测试 (含 SQL Guard, Safe Locks, Workflow, IPC)
cargo test -p datazen --lib

# AI API 契约测试
cargo test -p datazen-ai-api --lib

# 驱动端契约与 MigrationRenderer 测试 (PostgreSQL / MySQL / SQLite)
cargo test -p datazen-driver-postgres
cargo test -p datazen-driver-mysql
cargo test -p datazen-driver-sqlite
```



### 4.4 端到端 E2E 自动化测试

```bash
# 1. 编译 Webdriver 专用的 Debug App
pnpm tauri:build:webdriver

# 2. 运行快速 Smoke E2E
pnpm e2e:minimal

# 3. 运行 SQL 编辑器专项新增 E2E
```

## 6. 发布准出验收门禁 (Exit Criteria)

在将本版本作为正式 Release 发布前，必须无条件满足以下全部门禁：

1. **测试通过率 100%**：
  - Host 前端 Vitest 全部通过（0 Failures）；
  - Rust 后端 `cargo test --workspace` 全部通过；
  - 5 大新增 SQL Editor E2E 及 Host 契约矩阵全部 Green。
2. **安全与零 Panic 审计**：
  - 生产代码路径 0 未受保护的裸 `unwrap()` / `expect()`；
  - SQL Guard 注释剥离测试用例（含空块注释与复合注释）全覆盖；
  - IPC 错误日志脱敏测试无一泄漏明文密码。
3. **架构与洁净室规范**：
  - 社区版（Community）编译包在未注入 Pro 扩展时，功能退化为合法 Fallback，无任何未定义导入或启动报错；
  - 宿主与数据库驱动彻底解耦，无特定数据库类型硬编码；
  - 单文件代码规范符合 `AGENTS.md`（无单个超出规范规模的巨型单文件）。
4. **多语言完整性**：
  - 执行 `node scripts/i18n-sync-check.mjs` 检查通过，所有领域包中英文 Key 100% 对齐。
