## 3. 核心模块详细差异对照

### 3.1 SQL 编辑器与查询工作区 (SQL Editor & Query Panel)

在 `v0.1.2` 中，`QueryPanel.tsx` 为接近 2,000 行的臃肿单文件，执行策略简陋，缺乏参数校验，且对 DML 执行反馈存在误判。本次更新彻底重构了编辑器架构：

1. **架构组件化拆分**：
   - 拆分为 `QueryEditorSection.tsx`（编辑器视口）、`QuerySidebarSection.tsx`（侧边元数据/历史）、`QueryTransactionModals.tsx`（事务弹窗群）、`useQueryExecutionGate.tsx`（风控门禁）。
2. **4 模式执行策略 (4-Modal Execution Strategy)**：
   - 新增 `ExecutionStrategySelect.tsx`，支持：
     - `current`：自动识别光标所在 SQL 语句并仅执行该句；
     - `all`：执行当前编辑器中的全量批处理；
     - `selection`：仅执行鼠标高亮选中的 SQL 片段；
     - `ask`：弹出 `ExecutionStrategyAskModal.tsx` 让用户交互确认。
3. **参数化查询安全防御 (Bind Parameters Guard)**：
   - 实现 `validateBindParams.ts` 与 `sql_guard/params.rs`：对未赋值的 `:param` 和 `?` 占位符进行前置拦截，阻止向数据库隐式传入 NULL 导致灾难性误更新。
4. **高危 SQL 拦截与风控 (Dangerous SQL Gate)**：
   - `queryExecutionRisk.ts` 与 `QueryPanel.dangerousSql.test.tsx`：识别无 WHERE 条件的 `UPDATE/DELETE` 或 `DROP TABLE`，触发二次强制弹窗确认。
5. **DML/DDL 状态反馈重构**：
   - 解决 PostgreSQL 执行非查询语句提示“暂无可显示的行”问题，新增 `isMutationExecution.ts` 与 `ExecutionSummaryCard.tsx`，准确展示影响行数（`affectedRows`）及耗时。
6. **轻量资产中心与生产力**：
   - 首页/工作区历史 SQL 卡片支持直接点击并在新 Tab 中开辟查询；
   - 支持结果集固定（Pin Result Tab）；
   - 内置代码片段系统（`builtinSnippets.ts`, `SnippetMenuButton.tsx`）；
   - 可配置的 SQL 代码格式化（`formatEditorDocument.ts`）。
7. **语法分析与 AST 语义层**：
   - 新增词法扫描器 `scanner.ts`、语句边界探测 `statementRanges.ts`、作用域模型 `scopeModel.ts`、子句解析器 `clauseParsers.ts`、表关联反查 `relationResolver.ts`。

### 3.2 结构比对与迁移引擎 (Schema Diff & Migration IR)

在 `v0.1.2` 中，Schema Diff 采用硬编码各方言 DDL 生成，缺乏统一的中间抽象，部署任务不可控：

1. **方言中立中间表示 (Migration IR)**：
   - 新建 `src-tauri/src/schema_diff/ir.rs` 与 `operations.rs`，将表增删、列变更、约束/索引调整抽象为标准化结构体。
2. **依赖图 DAG 拓扑排序 (Dependency Ordering)**：
   - 新增 `dependencies.rs`，依据外键依赖、自引用、索引从属关系构建有向无环图（DAG），实现跨表迁移的严格有序部署与环路探测。
3. **驱动端 MigrationRenderer 契约下沉**：
   - 在 `packages/driver-api` 中定义 `SchemaMigrationRenderer` 与 `MigrationCapabilities`，各驱动（Postgres, MySQL, SQLite）负责将 IR 渲染为特定方言 DDL。
4. **部署控制与事务治理**：
   - 新增可取消部署任务（Shared `JobRegistry`），提供部署进度实时事件推送；
   - 抽象 `TransactionScope`（`services/transaction.rs`），统一多语句 DDL 事务回滚边界。
5. **风险分析与 UI 展示**：
   - 自动检测并提示“类型收窄风险（Type Narrowing Risk）”、非空约束施加与主键修改风险；
   - 前端增加部署前提要求（Requirements）与回滚完整性（Rollback Completeness）提示。

### 3.3 数据库驱动体系与契约 (Driver API & Drivers)

1. **`DatabaseDriver` Trait 能力扩充 (`packages/driver-api/src/traits.rs`)**：
   - 新增 `supports_stream()` 契约，支持大数据集流式读取；
   - 新增 `schema_migration_renderer()` 与 `migration_capabilities()`；
   - 新增 `ddl_atomicity()`，标识数据库是否支持 DDL 事务性回滚；
   - 新增 `sync_taxonomy()`（数据同步分类法，划分支持同族同步的引擎分类）。
2. **Driver Command 架构拆解**：
   - 将原单文件 `src-tauri/src/commands/driver_command.rs`（1573行）拆解为 `execute.rs`, `streaming.rs`, `discovery.rs`, `resolve.rs`, `helpers.rs`, `types.rs`，提升可维护性。
3. **驱动实现对齐与加固**：
   - **PostgreSQL**：实现 `SchemaMigrationRenderer`，支持全量 DDL 渲染与事务性回滚声明；
   - **MySQL**：实现 `SchemaMigrationRenderer`，显式拒绝不安全的 Nullability 转换渲染；
   - **SQLite**：实现表重建式迁移操作与能力声明；
   - **Redis**：完善 `redis_flush_gate` 安全拦截，深化键运维能力。
4. **测试独立化隔离**：
   - 驱动专属的方言测试已从 Host 剥离，完全下沉至各驱动 crate（`packages/drivers/<id>/`）。

### 3.4 后端服务健壮性与深度安全整改 (Rust Backend & Security)

针对生产环境可能出现的 Panic、敏感信息泄漏及注入漏洞，实施了 Wave 1 & Wave 2 共 12 个专项治理：

1. **SQL 安全网剥离注释防御 (SQL Guard)**：
   - 重构 `src-tauri/src/sql_guard/`：实现 `strip_sql_comments` 预处理，消除利用 `/* ... */` 或 `--` 伪装绕过只读/安全模式阻断 DML/DDL 的漏洞，修复 `/**/` 空块注释边界。
2. **IPC 敏感信息全局自动脱敏 (IPC Redaction)**：
   - `commands/error.rs` 中全局重载 IPC 错误序列化逻辑，自动使用正则表达式模糊化密码、Token、API Key 以及本地绝对路径。
3. **读写锁中毒恢复与消除 `block_on` (Panic-Locks Remediation)**：
   - 全面清理 `unwrap()` / `expect()`；
   - 在多线程读写锁中增加 `poison_recovery` 机制，防止单一任务 Panic 导致全局锁死；
   - 将同步阻塞的 `block_on` 替换为异步非阻塞的 `tokio::spawn`。
4. **工作流调度器槽位防泄漏**：
   - 在 `workflow/scheduler.rs` 中引入 RAII `InFlightGuard` 与 `catch_unwind`，保证异常状态下并发运行槽位安全归还。
5. **主密钥覆盖保护**：
   - 在备份恢复流程中，拒绝静默覆盖本地 `.key`，必须通过显式确认开关（`allow_key_overwrite`）。

### 3.5 多模型 AI 支持与模型级安全门控 (AI & Multi-Model)

1. **多模型档案管理 (Model Profiles)**：
   - 前端新增 `ModelProfileCard.tsx`、`ModelProfileDialog.tsx`、`ModelProfileListItem.tsx`，支持用户同时配置多个 Provider（OpenAI, Anthropic, DeepSeek, Ollama, 自定义端点）。
2. **模型级独立数据安全门控**：
   - 后端重构 `ai_config.rs` 与 `safety.rs`，允许针对本地私有模型（如 Ollama）或受信内网模型配置差异化的 `aiStrictEgress` 策略，支持在安全前提下携带样例数据进行深度分析。
3. **Markdown 格式化 Prompt 与统一解析器**：
   - 废弃原始 `.txt` 模板，全面升级为 `.md` 模板；
   - 实现 `PromptResolver`：优先级为 用户自定义覆盖 -> 驱动特化覆盖 -> 资源文件 -> 编译期内嵌英文。

## 5. 破坏性变更与兼容性评估 (Breaking Changes)

| 变更项 | 影响范围 | 升级/适配建议 |
| :--- | :--- | :--- |
| **Wapps 术语变更** | 原 extension 插件开发者 | 依赖的 IPC 事件从 `extensions:changed` 变更为 `wapps:changed`；运行路径统一为 `wapps/` |
| **IPC 错误脱敏** | 依赖正则解析 IPC 报错的脚本 | IPC 错误不再输出明文绝对路径与连接密码，需适配通用的错误编码与脱敏提示 |
