# 数据浏览使用手册

> 适用于表数据标签页与查询结果标签页里的数据网格。讲的是**界面上正在发生什么**，以及「为什么它不让我做」。
> 实现细节见 [数据表网格实现事实](../architecture/frontend/data-table.md)；查询结果写回的服务端规则见 [查询结果写回](../architecture/backend/result-write.md)。

---

## 1. 两种网格

|              | 表数据标签页                     | 查询结果标签页                              |
| ------------ | -------------------------------- | ------------------------------------------- |
| 打开方式     | 连接树里点表名                   | 执行一条 SQL                                |
| 数据来源     | 每页一次读取（默认 50 行）       | 一次执行的结果快照                          |
| 能否修改     | 取决于连接、驱动、对象类型与主键 | 取决于这条 SQL 的来源是否可定位到表中的一行 |
| 改动如何生效 | 先暂存，再「预览 → 提交」        | 直接写入（一次一格），之后需要重跑查询      |

页脚、选择、键盘、复制、外键跳转在两种网格里**完全一致**。

### 外观设置（数据浏览节）

设置页「数据浏览」节的四个外观项，两种网格一起生效：

- **网格密度**：紧凑 / 标准 / 宽松，改的是行高。标准就是此前一直的样子——密度按「在网格自己的默认行高上加减」工作（表数据网格默认 28px、查询结果网格 32px，紧凑各减 6、宽松各加 8），所以两种网格各自的节奏不会被互相抹平。
- **交替行背景**：默认开（奇数行有浅色条）。关掉后所有行同一底色；悬停、选中、高亮这些**状态**底色是另一条通道，不受这个开关影响。
- **行号**：默认开（左侧 `#` 列）。关掉后多出一列数据的位置，但行号列里的「点击选行」按钮也一起没了——行选择仍可以点击行本体完成，多选/范围选改用 `⌘/Ctrl` 点行和 `⇧` 点行。
- **自动隐藏滚动条**：默认关（滚动条常驻）。开启后只有鼠标悬停或键盘焦点在网格上时才显示滚动条——看数据时多出两条数据的宽度，滚动时它们又都在。

四个设置项默认值都等于「设置出现之前的界面」：全新安装看到的就是一直以来的网格。仪表盘小部件、工作流步骤结果等**辅助表格**不吃这四个设置——它们的高度是各自布局算好的，全局密度变化不该替它们做主。

## 2. 选择

- **单击**单元格：选中该格。
- **拖动**：选中一个矩形区域。
- **Shift + 单击**：从当前锚点扩展到点击位置。
- **⌘/Ctrl + 单击**：把这一格加入选择（或在已加入时移除）。点在已选区域内不会取消。
- **点行号列**：按行选择；`Shift` 选连续多行，`⌘/Ctrl` 选不连续多行。再次单击唯一被选中的那一行会**取消选择**。
- 状态栏会显示选择覆盖的行数与列数，形如「3 行 × 2 列」。
- `Esc` 清空选择并取消正在进行的拖动。编辑器打开时 `Esc` 只作用于编辑器。

行选择与格选择是两种模式，切换时会互相替换；格选择覆盖的行只用于状态栏与批量动作，不会显示成「已选行」。

## 3. 键盘

网格在 Tab 序里只占**一个位置**：`Tab` 进入网格，`Tab` 再离开网格（不会逐格穿行）。键盘焦点始终在网格上，选中的格子由高亮表示。

| 按键                | 作用                                               |
| ------------------- | -------------------------------------------------- |
| 方向键              | 移动一格                                           |
| Shift + 方向键      | 扩展选择范围                                       |
| ⌘/Ctrl + ← 或 →     | 跳到本行第一个 / 最后一个单元格                    |
| Home / End          | 跳到本行第一个 / 最后一个单元格                    |
| ⌘/Ctrl + Home / End | 跳到网格第一个 / 最后一个单元格                    |
| PageUp / PageDown   | 上下移动一屏（保留一行重叠，翻页后仍能看到上下文） |
| Enter 或 F2         | 编辑当前单元格                                     |
| ⌘/Ctrl + A          | 全选当前页的行                                     |
| Esc                 | 清空选择                                           |
| Tab / Shift + Tab   | 离开网格                                           |

到边界再按方向键时，选择**保持不动**，不会丢失，也不会让页面滚动。方向键不会把光标带进行号列。

## 4. 复制与粘贴

复制有三个入口，写出来的文本**完全一样**（同一套转义规则）：右键菜单、`⌘C` / `Ctrl+C`、以及「复制选中单元格」。粘贴只有一条路：`⌘V` / `Ctrl+V`，或右键菜单的「粘贴到选中单元格」。

### 4.1 复制

先选中单元格区域（点一格，`Shift` + 点另一格），然后：

| 入口                                                         | 得到的内容                         |
| ------------------------------------------------------------ | ---------------------------------- |
| `⌘C` / `Ctrl+C`                                              | 选中区域的制表符分隔文本（无表头） |
| 右键 → 复制选中单元格                                        | 同上                               |
| 右键 → 复制选中单元格为 → TSV / TSV带表头 / CSV / JSON       | 四种既定格式，CSV 恒带表头行       |
| 右键 → 复制选中单元格为 → 纯文本 / HTML 表格 / Markdown 表格 | 三种新格式，见下                   |

三种新格式各有用途：

- **纯文本**：制表符 + 换行直接拼接，**不做任何引号转义**——值里有引号、有逗号都原样保留。适合粘进「所见即所得」的纯文本目标（聊天窗口、代码注释），那些地方显示 CSV 引号只会碍眼。
- **HTML 表格**：以 `text/html` 写入剪贴板（同时带一份制表符纯文本兜底）。粘进 Notion / Excel / Google Sheets / 邮件正文会变成**真正的表格**——带加粗表头、可继续编辑，而不是一串 `<table>` 源码。值里的 `< > &` 会正确转义。
- **Markdown 表格**：GitHub 风格管道表（表头行 + `---` 分隔行 + 数据行）。粘进 GitHub / GitLab 的 Markdown、Notion 的 Markdown 粘贴模式直接渲染成表格。单元格里的 `|` 转义成 `\|`、换行转成 `<br>`（两处都支持渲染回原字符）。

**区域**是从起点到终点的矩形：中间没被点到的格子也会一起复制，和电子表格一致。按住 `⌘`/`Ctrl` 追加的多选区不参与复制，菜单标签会以 `(N…)` 提示。

只要选中了行（行号槽变蓝），右键菜单里原有的「复制行 / 复制选中行 / 复制列名 / 复制整列数据 / 复制为 JSON / 复制为 CSV / 复制为 SQL INSERT / 复制为 UPDATE」照旧可用，它们也走同一套转义。

**转义规则只有一套**：TSV/CSV 的引号规则（值含分隔符、引号或换行时整格加引号、内部引号翻倍）、Markdown 的 `\|` 与 `<br>`、HTML 的实体转义——「复制为 CSV」和「导出 CSV」用的是同一个序列化内核，导出文件和剪贴板内容不会在转义上分叉。

### 4.2 粘贴

选中目标区域的左上角单元格，再粘贴。规则如下：

- **行列对齐**：粘进来几行几列，就从左上角往下往右铺开；超出当前页时**自动扩展到页尾**（不会写进不存在的行），所以粘一大块通常意味着「先翻页到合适位置」。
- **同一个表复制出去的，按列名对齐**：在一行里复制了「姓名、城市」两列，粘回来时落在这张表的同名列上，与列顺序无关。
- **从别处（Excel、文本编辑器、另一张表）粘进来的，按位置对齐**，并且**一定先问你**——因为这时无法确认这块数据属于这张表。
  判断依据是「剪贴板里现在还是不是上次从这里复制出去的那段内容」：只要中间在别处复制过，即使你之前在本表复制过，也一律按外部粘贴处理、先问你。宁可多问一次，也不把数据写进你没瞄准的列。
- **大块会先确认**：超过 2 000 格时弹出确认框，避免手一抖把整页覆盖。
- **`NULL` 与空串是两回事**：文本里的 `NULL` 或 `\N` 写 SQL 的 NULL，真正的空单元格写空串。往不允许 NULL 的列里粘空值时，那一格会被拒绝并告诉你原因，其余格子照常写入。
- **自增列整列跳过**：不覆盖数据库自己生成的值。
- **粘贴不会直接写库**：和单元格编辑一样进入暂存区，可以预览、回滚，再一起提交。

### 4.3 失败会说明原因

粘贴被拒绝时，网格上方会出现一行说明（空剪贴板、内容过大、行列不齐、引号没闭合、越界、这一列不可写、跨表等），被逐格拒绝的单元格会标红。畸形文本**一条都不会写**，你之前的暂存修改也不会被清掉。

两个格式上的注意点：值里含制表符、换行或引号时，整格会被 `"` 包裹、内部的 `"` 双写，所以这类值粘回来仍然是同一格；对象类型的值按 JSON 文本复制（`"{""a"":1}"`），粘回来内容不变。

菜单里还有「设为 NULL」「设值」「恢复此行」「删除行」「按值筛选」等项，它们不是复制，改的是暂存状态或打开别的对话框。

## 5. 编辑单元格

1. **双击**单元格，或选中后按 `Enter` / `F2`。
2. 编辑器按列类型自动选择：文本、数字、布尔、日期/时间、JSON、长文本、二进制、枚举。
3. 输入后按 `Enter` 写入；`Esc` 取消并保留原值。
4. `Tab` 会**写入并移动到下一个单元格**（`Shift + Tab` 移动回上一个），不是放弃输入。
5. 布尔列与枚举列没有「回车确认」这一步：选中选项即写入。

值得知道的细节：

- **中文输入法选词时的回车不会提交编辑**，只确认候选词；要提交请在选词结束后再按回车。
- 编辑器失去焦点时（比如去点别处）会尝试写入，但以下情况**不算离开**，不会写入：点击编辑器自己的下拉列表、日期弹层；右键打开菜单（菜单可能正要改这一格）。
- 输入不合法时编辑器下方会显示原因并**拒绝应用**：数字格式、整数、布尔、日期时间、JSON、UUID 各有提示；往不允许 `NULL` 的列里留空会提示「此列不允许 NULL」，而不是悄悄写入空值。
- **空值有两种意思**：「设为 NULL」写 SQL 的 NULL；「设为空字符串」写长度为 0 的文本。两者不相等。
- 枚举列不会自动拉取候选值，点「加载候选值」才会去查（最多显示前 200 个相异值）。
- 二进制列与「值过大」的单元格不能就地编辑，会直接说明原因。
- **翻页、改排序、改筛选、刷新之前，如果编辑器里有没写完的内容，界面会先尝试写入；写不进去就会阻止这次导航**，以免你的输入被静默丢掉。

## 6. 暂存与提交（表数据标签页）

编辑不会立刻写库，而是先进入暂存区：

- 有改动时出现「N 项未保存更改」的条，以及**预览 / 提交 / 回滚**。
- **预览**打开「待提交变更预览」：列出将要执行的语句（新增 → 更新 → 删除的顺序）、参数、计划指纹，以及警告。预览里的 SQL **只是预览**，实际执行时参数会重新绑定。
- **提交**会先让你确认：有插入时是「提交 {插入数} 项插入、{更新数} 项更新和 {删除数} 项删除？」，没有插入时是「提交 {更新数} 项更新和 {删除数} 项删除？」。确认后整批在一个事务里执行。
- **回滚**丢弃全部暂存改动，并刷新当前页。
- 被标记删除的行显示为整行划掉；被改动的单元格有角标，悬停可看到「原值 → 新值」。
- 其他页面上也有未保存改动时，条上会提示「其他页面还有 N 个单元格已更改」——回滚会一起丢弃它们。

两种额外的连接状态：

- **手动事务**：面板上可以「开始事务」，之后每次提交都会并入这个事务，直到你「提交事务」或「回滚事务」。结束手动事务之前，别处的查询看不到这些改动。
- **连接只读**、**驱动不支持写入**、**视图**、**没有主键**：这四种情况面板不会进入可编辑状态，原因显示在条上或单元格的提示里。

如果预览之后你又改了别的东西，旧预览会失效——重新预览一次即可，这是为了避免「看到的是 A、提交的是 B」。

## 7. 插入行

- 工具条「插入行」（`⌘/Ctrl + I`），或在所有数据行下面的空白区域双击，都会新增一个草稿行。
- 草稿行带「新增」标记，**不属于当前页的数据**，因此排序、筛选、翻页都看不见它，重新读取页面也不会把它弄丢（它随提交一起走）。
- 每个可编辑列可以选择「默认值」（不写这一列，交给数据库）或「设为 NULL」（显式写 NULL）。这两者不同。
- 一个字段都不填也能提交：这一行会按数据库的默认值插入（`DEFAULT VALUES`）。如果表里有「不允许 NULL 且没有默认值」的列，数据库会拒绝这条插入，错误会显示在提交结果里。
- 在草稿行上 `⌘/Ctrl + D` 复制该行；「放弃此行」删除它。
- `Esc` 只会丢弃**空白**草稿行；填过内容的会保留，避免误删。

提交后：

- 能定位到新行时会短暂高亮（约 1.5 秒）。
- 定位不到时会明确提示「无法自动定位新行的主键，页面已刷新」。这不是失败——数据已经写入，只是界面没法确认哪一行是新的（常见于没有回读主键能力的数据库，或主键是 UUID 之类的不可比较值）。
- 复合主键、非数值主键的表更容易出现「定位不到」，属于已知限制。

## 8. 过滤与排序

### 过滤

- 工具条「筛选」里添加条件：列、操作符、值。可选操作符取决于**列的类型**和**当前数据库是否支持**。
- 条件可以从第二条开始选择「并且 / 或者」。
- 条件没填完时该行会标出「需要值，未应用」，**应用按钮不可用**。即使绕过按钮，未完成的条件也不会被悄悄忽略——否则结果集会变宽，而你以为筛过了。
- 点「应用」后回到第 1 页重新读取。

### 排序

- 双击表头：升序；再双击：降序；再双击：又回到升序。**双击不能取消排序**，并且会把该列**替换成唯一排序列**——想快速回到单列排序就用它。
- 表头右侧的小箭头在该列升序/降序之间切换（同样是替换整个排序）。
- **多列排序（列头右键）**：列头右键菜单里有「排序（多列）」→「升序 / 降序」，把该列**追加**到排序列表末尾——**列表里已有的列不会丢**：先按 name 排，再加 age，name 仍然是第一排序列。这是 TablePlus 至今没修好的地方（加第二列丢第一列，issue #2843），我们做对了。
  - 排序列表的顺序就是 `ORDER BY` 的顺序。排了多列时，每个参与排序的表头都会显示自己的**序号徽标**（1、2、3…），箭头方向对应该列自己的方向。
  - 对已在列表里的列再选「升/降序」：**位置不变，只改方向**。
  - 「从排序中移除」把该列从列表里去掉（该列不在列表里时置灰）；「清除全部排序」一次清空（没有任何排序时置灰）。
- **排序随表持久化**：排序列表（顺序和方向）按「连接 + 库 + 模式 + 表」记住——重开标签页、重开应用，这张表的排序都会恢复成上次离开时的样子。清除全部排序会把记住的记录一并清掉。列被删掉导致排序失效时，读取会报出数据库的错误，用右键「清除全部排序」即可恢复。
- 想回到默认顺序，仍可用页脚里的**排序**下拉：「跟随设置」（跟随全局设置）、「主键升序 ↑」、「主键降序 ↓」、「不排序」。这个选择只影响当前标签页、不会保存，并且会清掉当前的显式排序列表。
- 复合主键的表不能选「主键降序」——页脚下拉只生成「单列主键整体倒序」这一种场景，悬停会说明原因。复合主键要倒序时，用列头右键的多列排序把键列逐个加成降序。
- **NULL 怎么排**：排序子句不写 `NULLS FIRST/LAST`，沿用各库自己的默认——PostgreSQL / Oracle：升序时 NULL 在最后、降序时 NULL 在最前；MySQL / MariaDB / SQLite：NULL 恒当最小值（升序在最前、降序在最后）。需要精确控制 NULL 位置时，用查询页签写 `ORDER BY … NULLS FIRST/LAST`。

当既没有显式排序、默认排序又设为「不排序」时，页脚会提示：**「未设置排序——跨页的行可能重复或被跳过。」** 这是真的：没有稳定顺序时，第 2 页可能重复第 1 页的行。需要稳定的翻页就设置一个排序（或保留主键默认序）。

## 9. 列工具

列头这一条带上，除了排序，还有四件事：拖拽换位、冻结、列宽、列统计。前两件改变你**看**数据的方式，后两件帮你**量**数据。

### 拖拽重排

- 按住列头拖到另一列上松手，两列之间的位置就换了。拖动时目标列会亮出左侧的竖线，指明落点。
- 拖拽换的是**显示顺序**，不动数据库里列的定义；导出、复制的列顺序跟随当前显示顺序。
- 显示隐藏列（`visibleColumns`）的面板依旧管哪些列出现，重排只管出现的顺序。

### 冻结前 N 列

- 列头右键 →「冻结到此列」：从第一列到这一列全部钉在左侧，横向滚动时它们不动，行号槽也一起钉住。最后一根冻结列的右缘有一道加粗的缝，标出滚动边界。
- 「冻结到此列」在恰好冻到这一列时置灰（再点也是同一个状态）；「取消冻结」在本来就没冻结时置灰。
- 冻结的是**前 N 列**，不是任意列——想冻结第 3 列，先把第 1、2 列一起冻上。这是同一个「从左数到第几列」的语义，不会出现中间漏一列的怪姿态。
- 冻结只影响当前标签页的阅读姿势，**不持久化**：换张表、重开标签页，冻结清零。列宽和列序会记（见下），冻结不会——一张表有两种读法时，不该替你决定用哪种。

### 列宽与列序持久化

- 拖宽/拖窄某一列、拖拽换位，都按「连接 + 库 + 模式 + 表」记住——和排序的记法（§8）同一把钥匙。重开标签页、重开应用，这张表的列宽和列序恢复成上次离开时的样子。
- 自动列宽（双击列缝之类）产生的宽度同样照记。
- 列后来被删掉、存过的名字失效时，失效的部分被忽略，不会报错、也不会挡住其余记忆恢复。
- 清掉的办法：把列宽全部恢复默认、顺序拖回原样后，记录自动删除；或者换连接重开（记忆按表身份隔离）。

### 列统计

- 列头右键 →「列统计」：弹出该列的六个数字——**行数、非空值数、NULL 数、去重数（COUNT DISTINCT）、最小值、最大值**；数值类型列再多一个**平均值**。
- 统计由数据库**服务端聚合**（一条 `SELECT COUNT(*), COUNT(col), COUNT(DISTINCT col), MIN(col), MAX(col) [, AVG(col)] FROM 表`），不是拿当前页算的——一亿行的表也是一次往返出六个数，绝不会把整表拉回来。
- 平均值只对数值列请求：文本列的 `AVG` 在 PostgreSQL 上根本不存在，硬问会把整条语句问挂——一条 `AVG(text)` 不该连累另外五个数。列类型认不出来时同样不问，五个数照给。
- 某个值数据库给不出（比如全 NULL 列的最小值）时显示「—」，绝不显示一个编造的 0。
- 统计语句不进查询历史：那是机器生成的 SQL，你的历史应该只属于你自己。

## 10. 翻页与行数

页脚左侧是行数区间与降级提示，右侧依次是默认排序下拉（仅表数据标签页）、计数按钮、每页条数（25 / 50 / 100 / 200 / 500）与上一页 / 下一页。

**没有跳页输入框**：只能一页一页往前/往后。这是有意的——快速分页按「上一页/下一页」维护位置，任意跳页只能退化成从头数行。

行数有三种显示方式，含义不同：

| 显示               | 含义                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| `1-50 / 12,345`    | 精确总数                                                              |
| `1-50 / 约 12,345` | 估算值，实际可能更多或更少；点「计数」可换成精确值                    |
| `1-50 / 未知`      | 这个数据库不提供行数；只有「第 N 页」，能否继续取决于当前页是不是满页 |

估算状态下还有两条提示：

- 翻到空页时：「当前页为空。实际行数可能低于估算值——使用『计数』核实。」估算不是事实，允许你走过数据的末尾。
- 请求了估算但这台数据库不会估算时：「此数据库无法估算行数。」——这不是错误，读取已经回落到精确计数。

### 「快速分页 / 偏移分页」标签

页脚有时会出现「快速分页」或「偏移分页」标签，后面的黄色文字说明为什么退化了。逐条含义：

| 提示                                              | 意思                                                   |
| ------------------------------------------------- | ------------------------------------------------------ |
| 此表没有主键，无法按稳定顺序逐页读取              | 表没有可用于定位的键，只能按行数偏移翻页               |
| 按可能为 NULL 的列排序时，无法使用快速分页        | 排序键可能为空，无法确定「下一页从哪里开始」           |
| 此行的排序键为 NULL，快速分页已从精确位置重新开始 | 遇到空排序键，位置已重置                               |
| 当前排序方式无法使用快速分页                      | 这个顺序不满足快速分页的条件                           |
| 此数据库无法为该查询分页                          | 方言不支持分页子句                                     |
| 排序或筛选已更改，分页已从第一页重新开始          | 正常的重置                                             |
| 快速分页已从第 N 页重新开始                       | 你跳到了不相邻的页，位置被重新锚定（页码可能因此变化） |
| 翻页过程中行发生了变化，行数已刷新                | 数据在翻页期间被改动，总数已重新计算                   |

标签只在「发生了退化」或「快速分页且不止一页」时出现；只有一页的表不显示。数据库**本来就不支持**快速分页时也不会出现任何提示——那不是退化，是一直如此，天天提示只会变成噪音。

## 11. 外键跳转

- 属于外键的单元格右侧有一个小箭头，悬停会说明跳到哪张表（复合键会列出全部列）。
- 点箭头：打开（或复用）目标表的标签页，自动按外键值筛选。顶部面包屑显示「来自 orders.customer_id → customers.id」，可以返回、前进或隐藏。
- `⌘/Ctrl + ⌥ + ←/→` 在跳转历史里后退 / 前进。
- 复合外键**整组一起跳**；只要有一个成员是 NULL 就跳不了（NULL 表示「没有引用」，不是「引用空值」）。
- 目标表读不到时（不存在、在另一个数据库里、或没有权限），点箭头会报错并留在原表，不会打开一个空标签页。
- 目标行已经不存在时，会照常打开目标表并显示「被引用的行已不存在」——这是真实状态，不是故障。
- 跳转历史最多保留 32 步，超出会丢弃最早的，面包屑会说明。

## 12. 为什么这里不能改

表数据网格的常见原因（显示在单元格提示、条或状态里，下列为界面原文）：

| 提示                                              | 含义                           |
| ------------------------------------------------- | ------------------------------ |
| 安全模式下不能编辑表格单元格。                    | 安全模式开着，先关掉           |
| 只读连接或驱动不支持编辑表格数据。                | 整张表只读，看具体原因见下     |
| 此连接为只读，因此无法编辑单元格。                | 连接配置为只读                 |
| 此数据库驱动不支持写入。                          | 驱动没有实现写入               |
| 视图与物化视图在表格中为只读。                    | 换到基表                       |
| 此表没有主键，因此无法识别要更新的行。            | 加主键，或改用 SQL             |
| 无法唯一识别此行（其键值为 NULL 或重复）。        | 行标识不唯一，不能安全定位     |
| 自增列无法就地编辑。 / 生成列无法编辑。           | 列本身的限制                   |
| 此列类型无法在此数据库中就地编辑。                | 该库不支持对这种类型的原地更新 |
| 二进制列无法就地编辑。 / 此值过大，无法就地编辑。 | 内容不适合内联编辑             |

没有主键的表（连接本身可写时）数据标签页顶部会显示一条横幅：**「该表没有主键——无法安全定位行，网格为只读。」** 右侧的**「用 SQL 编辑」**按钮会打开一个新的查询页签，预填一段带注释的模板：

```sql
-- This table has no primary key: the grid cannot safely address a row.
-- Select the rows first, then write the UPDATE/DELETE against the same predicate.
SELECT * FROM "schema"."table" WHERE /* e.g. id = 123 */;
```

思路是「先读后写」：先把想改的行用 `WHERE` 条件选出来确认，再对着同一个条件写 `UPDATE` / `DELETE`——网格不敢替你定位行，但条件是你自己写的，行由你来框定。模板不会自动执行，改完需要自己点运行。只读连接上不显示这个按钮（连接本来就不允许写，横幅只保留默认排序的说明）。

查询结果网格的原因（显示在网格上方的提示条或只读单元格的悬停提示里）：

| 提示                                         | 含义                                          |
| -------------------------------------------- | --------------------------------------------- |
| 无法确定此结果的来源，因此为只读。           | 这条 SQL 读的是算出来的东西，或驱动没说清来源 |
| 驱动报告此结果的列来源不一致。               | 来源信息自相矛盾                              |
| 此结果关联多个表；每一行都无法编辑。         | 跨表结果                                      |
| 此结果是聚合结果；每一行都无法编辑。         | 聚合（COUNT/SUM 等）                          |
| 此结果已排除重复的行；行无法匹配回表中的行。 | `DISTINCT`                                    |
| 此结果是集合运算 (UNION)；行无法编辑。       | 集合运算                                      |
| 此结果来自子查询；行无法匹配回表中的行。     | 派生来源                                      |
| 此结果来自视图；不支持编辑视图。             | 来源是视图                                    |
| 来源的表没有主键，因此无法标识行。           | 表没有主键                                    |
| 此结果没有包含所有主键列。                   | SQL 里没选出全部主键列                        |
| 当前连接为只读。                             | 连接只读                                      |
| 此行的主键值为 NULL，无法定位。              | 该行主键为空                                  |
| 此页面包含重复的行标识；编辑功能已禁用。     | 页内有两行标识相同                            |
| 此行已不属于此结果。                         | 数据被改过，这行已经找不到了                  |

查询结果还有一条容易误会的规则：**一次执行只能改一格**。改完一格后，这个结果就变成只读，界面会提示「请先重新执行查询，再编辑这个保留的结果。」这不是权限问题——那份结果已经不再是「活」的写回目标，继续改可能落到另一份数据上。

## 13. 常见问题

**改完以后刷新就没了？**
表数据标签页的改动是暂存的，必须「提交」才写库；刷新不会丢掉暂存（刷新后看到的仍是「库里的值 + 你的改动」，改动标记还在），只有「提交」或「回滚」才会清空它们。查询结果标签页的改动是立刻写入的，刷新后看到的就是库里的值。

**为什么提交后新行没被选中/高亮？**
见 §7 最后一条：没有回读主键的能力时，界面无法确认哪一行是新行，只会提示「页面已刷新」。

**怎么把数据拷到 Excel？**
用右键菜单的「复制行 / 复制选中行」（制表符分隔），或「复制为 CSV」。见 §4。

**为什么翻到第 5 页，行数和之前对不上？**
行数可能是估算值（显示「约」），或者翻页期间数据变了（会提示「行数已刷新」）。点「计数」可以拿到精确值。

**为什么排序点不回去？**
单击只在升序/降序之间循环。用页脚里的「排序」下拉选择「不排序」。

**为什么有时候翻页会有黄色提示，有时候没有？**
只有发生退化时才提示；数据库本身不支持快速分页时不会提示，见 §10。
