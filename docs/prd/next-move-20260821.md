## 3. P0：实现 Data Synchronization V1（强烈建议作为下一主线）

### 3.1 目标一句话

在现有 **Data Sync 单例窗口** 内，把「选表覆盖拷贝」彻底换成：

**Compare → Review（表/行/单元格）→ Generate SQL → Preview → Execute**

对标 Navicat Data Synchronization，且严格遵守 PRD 硬门闸。

### 3.2 建议分期交付

#### Phase A — 引擎与硬门闸（后端优先）

- [ ] Source / Target：连接、Database（多库）、Schema；Swap；禁止同连接同库同表自同步
- [ ] `normalize_sync_family`：仅同方言族（如 MySQL↔MariaDB、PG↔PG）；异构直接拒绝并文案引导 **Data Transfer**
- [ ] 表映射：同名自动 + 手工映射；状态：`MATCHED` / `UNMAPPED_*` / `DISABLED` / `INCOMPATIBLE`
- [ ] 硬门闸（表级）：
  - 双方存在且列集合、类型等价、可空、**PRIMARY KEY 列集与顺序完全一致**
  - 无 PK / 结构不一致 / 非基表 → `INCOMPATIBLE`，不进入 Compare
- [ ] Compare：可取消、表级进度；输出 Insert / Update / Delete 行计数（与 Unchanged **表** 口径分离）
- [ ] Change Set：按 Table → Operation → Row 勾选；默认选中全部 INSERT/UPDATE；DELETE 仅在选项开启后可选
- [ ] 参数化 SQL 生成 + 只读 Preview（复制/保存文件）；**V1 不支持改 Preview 文本再执行**
- [ ] Execute 前校验：Target 非 `read_only`、表仍存在、结构/PK 未变、权限粗检；事务（支持则 BEGIN/COMMIT，否则 Partial 确认）
- [ ] 专用 IPC；**不**复用已删除的 legacy compare/sync 路径；**不**与 Schema Diff Deploy 的 DDL 计划混用

#### Phase B — Diff Workspace UI

- [ ] 复用 `openDataSyncWindow()` / `data-sync-singleton` / 菜单与右键「比较数据」
- [ ] 工作区步骤：端点选择 → Options（Insert 默认开 / Update 默认开 / Delete 默认关+确认）→ Mapping → Compare → 结果摘要 → 表详情（左右单元格新旧值）→ SQL Preview → Execute → Result
- [ ] 行级 Diff 分页（建议默认 ≤500 行/页）；表名搜索与按操作筛选
- [ ] INCOMPATIBLE 提示：引导 Schema Diff 或「改用 Data Transfer」（即使 Transfer 尚未实现，文案需正确）

#### Phase C — 质量与回归

- [ ] 单测：门闸矩阵、PK 复合键、类型等价、Change Set 过滤、事务回滚路径
- [ ] E2E：至少一条 PG 同库不同 schema 或两连接、一条 MySQL 路径；Compare → 勾选 → Execute → 再 Compare 为 0 差异
- [ ] 文档：更新 `schema-diff-guide` 交叉链接、用户手册、英文版（若有）
- [ ] 确认架构文档中 `transfer/` 与未来 Sync 模块命名不冲突

### 3.3 明确不在 V1 做（PRD 已列）

- 列级映射、WHERE 过滤、CDC、定时、CLI、Workflow 步骤化 Sync、手改 Preview SQL 执行
- 无 PK 表、视图/临时表、跨方言行同步
- 把 Transfer 的 Drop+Create 重新塞回 Sync

### 3.4 验收标准（建议写进 PR / 测试计划）

1. 结构不一致或无 PK 时无法生成 Change Set，且提示正确产品路径。  
2. 仅勾选的行进入执行；未勾选行 Target 不变。  
3. Delete 默认关闭；开启与执行各有确认。  
4. Target `read_only` 可 Compare、禁 Execute。  
5. 成功 Apply 后再 Compare，选定范围内行差异为 0。  
6. 安装包仍保持轻量路线（无不合理依赖膨胀）。

## 4. P1：同步主线之外的高价值补齐

### 4.1 查询历史（模块级）

右键差距分析多处依赖「历史查询」子菜单，当前缺失的是**产品能力**而非仅菜单项。

建议最小集：

- 按连接/库记录最近 N 条（语句、耗时、行数、时间、成功/失败）
- 搜索、再次打开到编辑器、清空
- 与 AI「从历史再诊断」可选联动

### 4.2 执行 SQL 文件

- 文件选择器 → 按语句拆分/顺序执行 → 进度与错误定位  
- 连接 / Database / Schema 右键入口与主工具栏一致  

### 4.3 Schema / Database 管理命令

- `CREATE DATABASE` / `CREATE SCHEMA` / `DROP SCHEMA`（按 Driver capability 暴露）  
- 执行后刷新导航树（main 上已有 DDL 刷新相关修复，可复用）

### 4.4 Data Sync 与现有能力的薄集成（可选，仍属 P1）

- AI：对 Compare 摘要做自然语言说明；或根据错误建议是否应先 Schema Diff  
- Workflow：暂不把 Sync 做成步骤类型（PRD 列在后续）；可仅「从 Sync 任务导出只读报告」  
- MCP：高风险写入工具默认关闭；若暴露，必须复用同一权限模型与 `read_only` 门闸

## 5. P2 及以后

### 5.1 Data Transfer V1（独立窗口）

在 Sync 稳定后再立项。PRD 已定义：异构、字段/类型映射、目标建表、Insert / Truncate+Insert / Drop+Create（显式）、Preview、分批流式写入。  
实现时应新建 `data-transfer` 窗口 kind，**不要**塞进 Data Sync Diff Workspace。

### 5.2 Driver 与生态

- 可选 Driver（MongoDB、ClickHouse、DuckDB、SQL Server）能力对齐：Schema 浏览、查询、导出等与默认 SQL 驱动体验一致  
- 独立插件文档与 `drivers-registry.json` 示例持续维护  

### 5.3 体验与发布

- macOS 公证 / 签名（社区反馈「已损坏」需 `xattr`）  
- Linux 包渠道与自动更新文档（`docs/updater.md`）  
- 看板：调度/共享等若有二期需求，在 Dashboard 已稳定基础上增量  

### 5.4 低优先级运维能力

进程列表、用户权限、服务器仪表盘、全库备份、对象过滤器、置顶等——仅在 P0/P1 闭环后再考虑。
