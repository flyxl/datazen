## 1. 概述

### 1.1 背景

查询构建器（Query Builder，下文简称 QB）是一种可视化工具，让用户通过拖拽表、勾选字段、设置关联与条件来生成 `SELECT` 语句，无需手写 SQL。

Navicat 的 QB 是业界成熟参考实现，覆盖 MySQL / PostgreSQL / SQLite / MariaDB。DataZen 已在代码中包含一版**初版可视化构建器**，但布局与交互尚未定型（详见 [§5](#5-datazen-代码基线与差距分析)）。本文档在 Navicat 参考实现的基础上，定义 DataZen QB 的最终形态。

### 1.2 产品愿景

QB 是 **SQL Editor 的可视化伴随视图**：不新建窗口、不复制左侧连接树，而是在同一个查询面板内，让用户在「可视化画布」与「SQL 编辑器」之间一次点击往返。

> 核心原则：**QB 只负责产出 SQL，不负责执行 SQL。** 执行永远由 SQL Editor 承担。

### 1.3 与 Navicat 的差异化

| 特性     | Navicat           | DataZen (目标)                                       |
| -------- | ----------------- | ---------------------------------------------------- |
| 承载形态 | 独立模态对话框    | **查询面板内的整区视图**（无模态）                   |
| 对象浏览 | QB 自带一栏       | **复用宿主 `ConnectionNavigatorTree`**（零重复实现） |
| 底部区域 | 语法区固定平铺    | **「构建 / 预览」双 Tab**（省垂直空间）              |
| 提交动作 | OK / Cancel       | **OK 写回 SQL Editor 并聚焦 / 取消丢弃**             |
| 运行环境 | 原生 C++，Win/Mac | Tauri v2（Rust + React），Win/Mac/Linux              |
| SQL 方言 | 各产品线分支      | 集中在 `src/lib/sqlDialects/queryBuilder.ts` 适配器  |
| AI 辅助  | 无（18 起集成）   | 预留：JOIN 路径推荐、条件补全                        |

## 2. 目标与范围

### 2.1 目标

| 优先级 | 目标                                                                    |
| ------ | ----------------------------------------------------------------------- |
| P0     | 在查询面板内以整区视图打开 QB；左栏复用 `ConnectionNavigatorTree`       |
| P0     | 拖拽 / 点击表 → 画布出现表卡片；勾选字段 → 进入 SELECT                  |
| P0     | 依据外键自动推断 JOIN，支持手动改 JOIN 类型                             |
| P0     | 底部「构建 / 预览」双 Tab；预览 Tab 实时显示生成的 SQL                  |
| P0     | 底部 **OK** 按钮：写回 SQL Editor、关闭 QB、编辑器聚焦；**取消** 丢弃   |
| P1     | WHERE 条件（AND/OR + 分组）、ORDER BY、GROUP BY、DISTINCT、LIMIT/OFFSET |
| P1     | 表别名、字段别名、聚合函数                                              |
| P2     | 从已有 SQL 反向解析初始化画布                                           |
| P2     | QB 状态序列化 / 恢复（关闭再打开不丢画布）                              |
| P3     | AI：JOIN 推荐、条件补全、优化建议                                       |

### 2.2 不在范围内

- DML（INSERT / UPDATE / DELETE）的可视化构建
- 存储过程 / 触发器可视化编辑
- 从 QB 直接执行查询（执行权归 SQL Editor，见 §6.4）
- ER 图（已有独立模块 `windows/connection/er/`）

## 4. Navicat Query Builder 实现分析

### 4.1 布局

Navicat QB 是独立模态窗口，**两段式**结构：

```
┌──────────────────────────────────────────────────────┐
│ Query Builder                          [ OK ][Cancel] │
├──────────────┬───────────────────────────────────────┤
│ 对象浏览器    │  图表设计区（Diagram）                 │
│ 数据库/表/视图│  ┌────────┐  ┌──────────┐  ┌────────┐ │
│              │  │actor(a)│──│film_actor│──│ film(f)│ │
│              │  └────────┘  └──────────┘  └────────┘ │
│              ├───────────────────────────────────────┤
│              │  语法区（Syntax）                      │
│              │  SELECT <Distinct> <加字段>            │
│              │  FROM   actor AS a INNER JOIN ...      │
│              │  WHERE  <加条件>                       │
│              │  GROUP BY / HAVING / ORDER BY          │
└──────────────┴───────────────────────────────────────┘
```

### 4.2 核心机制

| 机制        | Navicat 做法                                                                       |
| ----------- | ---------------------------------------------------------------------------------- |
| 添加表      | 从对象浏览器**拖拽**到图表区，或**双击**表名                                       |
| 表别名      | 双击表名旁 `<alias>` 就地编辑                                                      |
| 自动 JOIN   | 依据已声明的**外键约束**自动连线并生成 `ON` 条件                                   |
| 选择字段    | 勾选字段左侧复选框；点表标题复选框全选                                             |
| WHERE 条件  | 点 `<Click here to add conditions>` → 生成默认 `<--> = <-->`，三段各自可点         |
| 左/右表达式 | 弹窗含 **List 标签**（选字段）与 **Edit 标签**（手输入值）                         |
| 运算符      | 点 `=` 弹出运算符列表（`=`、`<>`、`>`、`<`、`LIKE`、`IN`、`BETWEEN`、`IS NULL` …） |
| 条件组合    | 条件间 `AND` / `OR`                                                                |
| 提交        | **OK** 关闭窗口，生成的 SQL 落入 Query Editor；用户随后自行执行                    |

### 4.3 可借鉴与不可借鉴

| 决策点         | Navicat     | DataZen 取舍                                            |
| -------------- | ----------- | ------------------------------------------------------- |
| 独立模态窗口   | ✅ 空间充裕 | ❌ 改为**面板内整区视图**，避免窗口跳转与状态割裂       |
| QB 自带对象栏  | ✅ 自洽     | ❌ **复用宿主连接树**，避免第二套树与状态同步           |
| 语法区固定平铺 | ✅ 一眼可见 | ❌ 垂直空间不足 → 改**底部双 Tab**                      |
| 三段式条件弹窗 | ⚠️ 多点几次 | ⚠️ 保留心智模型，但改为**行内 grid 编辑**（无嵌套弹窗） |
| OK 只交 SQL    | ✅ 职责单一 | ✅ **完全采纳**：QB 不执行查询                          |
| 无法保存画布   | ❌ 关闭即丢 | ✅ P2 增加状态持久化                                    |

### 5.2 三个必须修正的差距

| #      | 现状问题                                                                                                                     | 按要求的目标形态                                                                                                          |
| ------ | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **G1** | 左侧对象来源不统一：宿主已有 `ConnectionNavigatorTree`，QB 却带了一个从未被挂载的 `ObjectTreePanel`                          | **删除 `ObjectTreePanel`**；QB 不渲染任何自有左树，对象浏览一律走宿主 `ConnectionNavigatorTree`（`onSelectTable` / 拖拽） |
| **G2** | 三段式垂直堆叠（画布 + CriteriaGrid + SQL 预览）同时渲染，垂直空间不足；且 QB 只是编辑器上方的一条面板，画布高度被编辑器挤占 | **右区改为：画布（上）+「构建 / 预览」双 Tab（下）**；QB 打开时**整区替换** SQL Editor，独占查询面板内容高度              |
| **G3** | 提交按钮文案为「应用 SQL」(`query.visualBuilder.applySql`)，语义与位置不明；且 QB 与编辑器同屏，缺少明确的「返回」心智       | 按钮改为 **OK**（主）/ **取消**；点击 OK 写回 SQL → 关闭 QB → **恢复并聚焦 SQL Editor**；取消 = 丢弃画布改动              |

### 5.3 差距影响

- **G1** 若保留 `ObjectTreePanel`，会出现“两棵表树、两套选中态”，且 `ObjectTreePanel` 的 `tables` 需由调用方自行注入（现无注入方），必然腐化。
- **G2** 若继续纵向堆叠，1920×1080 下画布可用高度仅 ~200px，拖拽体验不可接受。
- **G3** “同屏”形态下用户无法判断 OK 与编辑器「运行」的区别，容易误执行。

## 6. 本次变更设计（核心）

### 6.1 变更 1：对象浏览器复用 `ConnectionNavigatorTree`

**结论**：QB 不自建左栏。

| 项           | 设计                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| 复用组件     | `src/windows/connection/ConnectionNavigatorTree.tsx`（既有宿主侧栏，含折叠 / 宽度拖拽 / 搜索 / 分组 / 右键菜单） |
| 与 QB 的接口 | 宿主 `onSelectTable(table, schema?, database?)` 是 QB 的“加入画布”入口；`viewActions.newQuery` 保持原有语义      |
| 拖拽         | 复用连接树已有的 HTML5 drag（`dataTransfer.setData('table', name)`），`DiagramCanvas` 的 drop 处理器按此约定解析 |
| 删除项       | `src/components/query-builder/ObjectTreePanel.tsx` 及其 props 类型（零引用，直接删除）                           |
| 不允许       | 在 QB 内新增任何 `Schema → Tables/Views` 树、搜索框或表列表                                                      |

> 说明：连接树已具备 `onSelectTable`、搜索、分组、多库 / 多 schema 展开能力，QB 只需消费其“选中表”事件即可，无需任何新 UI。

```text
┌──────────────────────────────────────────────────────────────┐
│ 宿主连接面板                                                  │
│ ┌───────────────────┐ ┌────────────────────────────────────┐ │
│ │ ConnectionNav     │ │ 查询面板内容区                      │ │
│ │ igatorTree        │ │  ┌──────────────────────────────┐  │ │
│ │ (宿主既有侧栏)     │ │  │ QB 打开 → 整区替换 SQL Editor │  │ │
│ │  · 连接 / 库 / schema│ │ ┌── 画布 ─────────────────┐  │  │ │
│ │  · 表 / 视图      │ │  │ └──────────────────────────┘  │  │ │
│ │  · 搜索 / 右键    │ │  │ ┌── Tab: 构建 | 预览 ──────┐  │  │ │
│ │                   │ │  │ └──────────────────────────┘  │  │ │
│ │  ⟶ onSelectTable  │───→│          [取消]     [ OK ]    │  │ │
│ └───────────────────┘ └────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 变更 2：底部改为「构建 / 预览」双 Tab

**目标**：右区只有两个纵向分区，且底部只占一份高度。

```text
右区结构（自上而下）:
┌──────────────────────────────────────────────┐
│ ① QB Header                                  │
│   [🧩 可视化查询构建器] [☐ DISTINCT] [重置][×] │
├──────────────────────────────────────────────┤
│ ② 画布 DiagramCanvas  (flex-1, 可拖拽调高)    │
│    表卡片 / JOIN 连线 / 缩放 / 平移           │
├══════════ 可拖拽分隔条 ═══════════════════════┤
│ ③ 底部 Tab 区                                 │
│   ┌────────┬────────┐                         │
│   │ 构建 ● │ 预览   │   ← 双 Tab（默认「构建」）│
│   └────────┴────────┘                         │
│   ┌──────────────────────────────────────────┐│
│   │ 当前 Tab 内容（内部独立滚动）             ││
│   └──────────────────────────────────────────┘│
├──────────────────────────────────────────────┤
│ ④ Footer:                     [取消]  [ OK ] │
└──────────────────────────────────────────────┘
```

| Tab      | 对应原有区域   | 内容                                                                           |
| -------- | -------------- | ------------------------------------------------------------------------------ |
| **构建** | `BuildStatement` | Navicat 式子句列表：SELECT（字段 chip + 字段选项弹窗）/ FROM（表 + JOIN 行）/ WHERE（AND/OR + 分组）/ GROUP BY / HAVING / ORDER BY + LIMIT、OFFSET |
| **预览** | `SqlPreview`   | 只读的高亮 SQL 全文、方言标识、复制按钮、空态提示                              |

**关键约束**

1. 两个 Tab **互斥显示**，任一时刻只渲染一个 → 垂直空间省下一整段。
2. Tab 内容区 `flex-1 + overflow-y-auto`；**Footer 常驻**，不随 Tab 滚动。
3. 画布与 Tab 区之间的分隔条**可拖拽**（min 画布 160px / min Tab 区 140px），结果写入 `useResizable`（已有 hook）+ `storageKey: 'qb-split-height'`。
4. Tab 选中态**记住**（同一面板内切换回来仍是上次的 Tab；跨重启可持久化到 settings）。
5. 提供快捷折叠：`Ctrl/Cmd + B` 折叠画布，把高度让给「构建」Tab。
6. 「构建」Tab 存在未决校验错误时，Tab 标题显示红点角标（见 F-05.4）。

### 6.3 变更 3：`OK` 提交行为

**结论**：QB 不执行查询，只回填 SQL。

| 元素                          | 行为                                                                                                                                                                                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **OK**（主按钮，Footer 右侧） | ① 校验画布 → ② 生成 / 取用预览区 SQL → ③ 写回所属 Query Panel 的 SQL（`onUpdateSql`）→ ④ 关闭 QB（`toggleOpen()`）→ ⑤ 恢复 SQL Editor 视图并**聚焦编辑器**（`editorRef.current?.focus()`），光标置于文末 → ⑥ i18n Toast「已写入 SQL 编辑器」 |
| **取消**（次按钮）            | 关闭 QB 并**丢弃本次画布变更**（恢复进入前快照），SQL Editor 内容保持不变；若存在未提交改动，先弹确认「放弃更改？」                                                                                                                          |
| **关闭 ×**（Header 右侧）     | 等价于**取消**（含确认）                                                                                                                                                                                                                     |
| 未选任何表                    | OK **禁用**，Tooltip「请至少选择一张表」                                                                                                                                                                                                     |
| 生成 SQL 为空                 | OK **禁用**                                                                                                                                                                                                                                  |

**回填策略（重要）**

| SQL Editor 当前状态                | OK 行为                                          |
| ---------------------------------- | ------------------------------------------------ |
| 空                                 | 直接写入，无提示                                 |
| 已有内容 且 内容等于本次生成的 SQL | 视为无变化，仅关闭并聚焦                         |
| 已有内容 且 与生成 SQL 不同        | 弹**三选一**确认：`替换` / `追加到末尾` / `取消` |

> 说明：现有实现为无条件覆盖（`onApplySql` → `onUpdateSql`），需补齐上面的确认分支，避免用户手写 SQL 被静默覆盖。

**明确不做**

- ❌ OK 不触发查询执行（不放行 `useQueryExecutionGate`）
- ❌ OK 不自动格式化用户已有 SQL
- ❌ OK 不关闭所属查询 Tab，只关闭 QB 视图

### 6.4 视图切换语义（QB ⇄ SQL Editor）

由于 QB **整区替换** SQL Editor，需要明确状态机边界：

| 事件                 | SQL Editor                                         | QB 画布              | 备注                           |
| -------------------- | -------------------------------------------------- | -------------------- | ------------------------------ |
| 点「可视化构建」开启 | 隐藏（组件保留挂载，避免重建编辑器与丢失 undo 栈） | 显示，按上次状态恢复 | 编辑器内容不丢                 |
| 点 OK                | 显示 + 聚焦                                        | 关闭，画布保留       | 写回 SQL（含回填策略）         |
| 点取消 / ×           | 显示 + 聚焦                                        | 关闭 + 丢弃画布改动  | SQL 不变                       |
| 切到其它查询 Tab     | —                                                  | 关闭                 | QB 状态随面板隔离（见 F-06.4） |
| 面板卸载             | —                                                  | 释放状态             | —                              |

> **必须保留编辑器挂载**：SQL Editor 内含 CodeMirror undo 栈、绑定参数面板状态（`sql-editor-enhanced` EP）与元数据缓存。用 `hidden` / `display:none` 等 CSS 隐藏策略，禁止条件卸载，以免 undo 历史与参数值丢失。

#### F-02 画布（DiagramCanvas）

| ID     | 需求        | 验收标准                                                                                                       |
| ------ | ----------- | -------------------------------------------------------------------------------------------------------------- |
| F-02.1 | 添加表      | 从 `ConnectionNavigatorTree` 拖拽表到画布（**唯一入口**，点击树节点始终打开表数据）；画布出现 `TableCard` 并落在释放点（`tablePositions`） |
| F-02.2 | 表卡片内容  | 表名、别名输入、字段列表（含主键标记）、全选复选框、移除按钮                                                    |
| F-02.3 | 字段勾选    | 勾选进入 `selectedColumns`；取消即移出 SELECT                                                                  |
| F-02.4 | 移除表      | 关闭卡片 → 从 `selectedTables` 移除，同时清理该表相关 `selectedColumns` 与条件引用                             |
| F-02.5 | 缩放 / 平移 | 画布为原生滚动容器（滚轮 / 触控板 / 滚动条滚动），`Ctrl/Cmd + 滚轮` 以指针为中心缩放（`zoom`），中键拖拽或 `Space + 拖拽` 平移 |
| F-02.6 | 空态        | 无表时画布居中提示：拖拽左侧表到此处开始                                                                       |
| F-02.7 | 卡片固定高度 | 卡片高度 = 表头 + `min(列数 × 行高, 200px)`；超出部分由**卡片内列表自身滚动**（Navicat 行为），卡片不随表宽增长；滚动时连线锚点夹取到列表边缘并以「超出可视」图标表示 |

#### F-03 JOIN 管理

| ID     | 需求          | 验收标准                                                                                                          |
| ------ | ------------- | ----------------------------------------------------------------------------------------------------------------- |
| F-03.1 | 自动 JOIN     | 依据缓存外键（`getCachedTableSchema().foreignKeys`）经 `useAutoJoin` 生成 `autoJoins`，以**虚线**呈现，不进入 SQL |
| F-03.2 | 确认自动 JOIN | 点击连线 → 弹出 Popover → 确认后转为 `joins`（实线）并写入 SQL                                                   |
| F-03.3 | 手动 JOIN     | 从一表字段拖到另一表字段 → `addJoin({ isManual: true })`                                                          |
| F-03.4 | 类型切换      | `INNER / LEFT / RIGHT / FULL`（`QbJoinType`）；画布上**不出现任何文字**，类型与 ON 条件只在 Popover 内展示 / 编辑   |
| F-03.5 | 删除 JOIN     | 点击连线 → Popover → 移除（复合外键整组移除）                                                                     |
| F-03.6 | 无外键提示    | 新增第二张表但未检测到 FK 时，画布顶部内联提示「未检测到关系，可手动连线」                                        |
| F-03.7 | 连线几何      | 一律为**正交折线**（每段水平或垂直，无斜线），且**不带方向**（无箭头、无 `marker-*`）；每对端点两端对称画锚点，复合外键先合并为主干再分叉 |

#### F-04 底部「构建」Tab（Navicat 式子句列表）

| ID      | 需求           | 验收标准                                                                                                           |
| ------- | -------------- | ------------------------------------------------------------------------------------------------------------------ |
| F-04.1  | 一条子句一行   | SELECT / FROM / WHERE / GROUP BY / HAVING / ORDER BY 各占一行，左侧 SQL 关键字槽（不翻译），右侧为该子句内容；每行只占自身内容高度 |
| F-04.2  | 统一 chip 规则 | **每个子句的每一项都是 chip**（SELECT 字段 / FROM 表 / WHERE·HAVING 条件 / GROUP BY·ORDER BY 键）：chip 展示该项内容，点击打开该项弹窗，`×` 移除                            |
| F-04.3  | 字段选项弹窗   | 点击字段 chip 打开弹窗，可编辑别名 / 聚合 / 排序 / 分组 / 单条条件；**取消不写入**，仅 OK 落库；表单按字段只播种一次，不受无关 store 更新影响 |
| F-04.4  | FROM 与 JOIN   | FROM 行以 chip 展示驱动表与每条 JOIN（chip 前缀为 JOIN 类型），与应用 `buildJoinSteps` 同源，方向与生成 SQL 一致（`data-join-on`）；未被 JOIN 触及的表标注「尚未关联」；点击表 chip 打开「表选项」（别名可改，JOIN 类型与 ON 只读） |
| F-04.5  | WHERE 条件     | 条件以 chip 展示（非首行带 AND/OR 徽标），点击打开「条件」弹窗；根条件 + 一层嵌套组（组为带 logic 选择器的框）；行的 AND/OR **必须真正生效**；新增条件仅以草稿存在，**OK 才落库**；列级条件以 chip 展示并可移除 |
| F-04.6  | GROUP BY       | 独立子句行 + 选择器；条目为「store 列表 ∪ 列标记」并集，移除时清除真正的归属方                                      |
| F-04.7  | HAVING         | 独立子句行，位于 GROUP BY 之后；条件 chip 与 WHERE 同规则，弹窗内提供**聚合选择器**（默认 SUM），操作数既未聚合也未分组时给出警告但不阻断 OK |
| F-04.8  | ORDER BY       | 独立子句行 + 选择器；点击 chip 打开「排序选项」弹窗设置 ASC/DESC，`×` 移除；聚合列的排序输出聚合表达式               |
| F-04.9  | DISTINCT       | SELECT 行起始处的复选框（`setDistinct`）                                                                            |
| F-04.10 | LIMIT / OFFSET | 构建区顶部常驻工具行，数字输入，`null` 表示不输出该子句                                                            |
| F-04.11 | 垂直空间       | 四个字段已选时 WHERE 与 GROUP BY 仍在可视区内；画布折叠后整条语句无需滚动即可全部可见（E2E D2 断言）                |

#### F-05 底部「预览」Tab

| ID     | 需求     | 验收标准                                                                                           |
| ------ | -------- | -------------------------------------------------------------------------------------------------- |
| F-05.1 | 实时生成 | 画布 / 构建区任意变更 → 预览 Tab SQL 同步更新（`useSqlGenerator`）                                 |

| F-05.5 | 复制 SQL | 一键复制到剪贴板                                                                                   |
| F-05.6 | 空态     | 未选表时提示「请至少选择一张表以生成 SQL」                                                         |

### 9.2 拖拽规范

| 操作                | 触发                                       | 行为                                                                                     |
| ------------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 表 → 画布           | 连接树表节点 `dragstart` → 画布 `drop`     | 解析 `dataTransfer('table')` 表名；落点写入 `tablePositions`；已存在则不重复添加，仅高亮 |
| 字段 → 字段         | 卡片字段 `dragstart` → 另一卡片字段 `drop` | `addJoin({ isManual: true, type: 'INNER' })`                                             |
| 字段 → 构建区列列表 | 卡片字段拖到「已选列」区                   | 等价于勾选该字段                                                                         |
| 画布滚动            | 滚轮 / 触控板 / 滚动条                     | 原生滚动容器滚动（`canvasOffset` 已移除）                                                |
| 画布平移            | 中键拖拽 或 `Space + 拖拽`                 | 即滚动，不改变 `zoom`                                                                     |
| 画布缩放            | `Ctrl/Cmd + 滚轮`                          | 以鼠标为中心，`zoom` 限 0.25–4                                                            |
| 卡片内滚            | 指针在卡片列列表上滚动                     | 只滚动该表字段列表（`overscroll-behavior: contain`），不带动画布                          |
| 分隔条              | 拖拽底部横条                               | 调整画布 / Tab 区高度，持久化                                                            |
| Tab 内容滚动        | Tab 区域内滚轮                             | **不带动画布缩放**，各自独立滚动                                                         |

  | '<='

### 11.1 性能

### 11.4 主题与风格

- 画布背景网格点、表卡片、连线、Tab、Footer 全部使用主题语义 token（`surface` / `edge` / `fg` / `accent`）。

- 组件统一复用 `@datazen/ui`（`Button`、`Select`、`Checkbox`、`cn`），不引第三方画布库。

### 11.5 约束

- 不引入 React Flow 等新依赖：现有 `DiagramCanvas` 为自绘 SVG/DOM 方案，改造保持自绘。
- 不得在 QB 内新增第二套对象树或第二套列元数据缓存（一律读 `useSchemaStore.columnMap` 与 `getCachedTableSchema`）。

#### 13.3.3 Journey C — 高复杂度语句构造旅程（QB-JOURNEY-C）

> 目标：用可视化方式构造一条 **多表 JOIN + 嵌套条件组 + 聚合 + 分组 + 排序 + 分页 + DISTINCT** 的语句，并验证生成 SQL 与执行结果都正确。

**前置**：在 `conn_e2e_pg` 建三张**有真实外键**的表并插入种子数据：

```sql
CREATE TABLE e2e_qb_c_author (id INTEGER PRIMARY KEY, name TEXT, country TEXT);
CREATE TABLE e2e_qb_c_book (
  id INTEGER PRIMARY KEY,
  author_id INTEGER REFERENCES e2e_qb_c_author(id),
  title TEXT, year INTEGER, price INTEGER, rating TEXT
);
CREATE TABLE e2e_qb_c_sale (
  id INTEGER PRIMARY KEY,
  book_id INTEGER REFERENCES e2e_qb_c_book(id),
  qty INTEGER, channel TEXT
);
```

| 步  | 操作                                                                                                 | 断言（生成 SQL 关键片段）                                                                                     |
| --- | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| C1  | 依次加入三张表                                                                                       | `qb-drag-*` ×3；两条 FK 候选以**虚线**出现（`qb-join-line-*`）；此时 SQL **不含** JOIN                        |
| C2  | 确认两条候选 JOIN                                                                                    | SQL 含两条 `INNER JOIN ... ON ...=...`；`qb-join-label-*` 可切换类型                                          |
| C3  | 将 `sale`↔`book` 的 JOIN 改为 `LEFT`                                                                | SQL 含 `LEFT JOIN`                                                                                            |
| C4  | 选列 `author.name`、`book.title`，聚合 `SUM(sale.qty)` 别名 `total_qty`                              | SQL 含 `SUM(...qty...) AS ...total_qty...`                                                                    |
| C5  | 给 `author.name`、`book.title` 打别名 `author_name` / `book_title`                                   | SQL 含两个 `AS` 别名                                                                                          |
| C6  | `author.name`、`book.title` 勾 Group                                                                 | SQL 含 `GROUP BY`，且两字段都在其中                                                                           |
| C7  | 排序 DESC                                                                                            | SQL 含 `ORDER BY ... DESC`                                                                                    |
| C8  | 勾选 DISTINCT                                                                                        | SQL 以 `SELECT DISTINCT` 开头                                                                                 |
| C9  | WHERE 嵌套组：`book.year >= 2000 AND (book.rating = 'A' OR book.rating = 'B')`（用「+ 添加条件组」） | SQL 含 `WHERE`、`>= 2000`、`AND (`、`OR`、`)`，括号嵌套正确                                                   |
| C10 | 追加 `sale.channel IN 'online,store'`                                                                | SQL 含 `IN ('online', 'store')`                                                                               |

| D5  | **联合外键变成笛卡尔积**：2 列 FK 被识别成 4 组列对（`pa→a, pa→b, pb→a, pb→b`），生成带 4 个谓词的 JOIN | 驱动 schema SQL 里 `key_column_usage` 与 `constraint_column_usage` 只按约束名 JOIN，两处 `array_agg` 各自聚合 → 2×2=4 行；宿主按位配对即得笛卡尔积。**根因在 `packages/drivers/postgres/src/schema.rs` 的 FK 查询（应按 pg_constraint 的 conkey/confkey 位置相关）** | 驱动侧按 `conkey/confkey` 位置归一（`normalise_fk_columns`，长度不一致则跳过）；宿主侧再兜底归一。E2E `C16` 断言「1 主干 / 4 桩 / 无箭头 / 无 `marker-*` / 段全轴向 / 2 组对称端点 / 确认后 2 条 JOIN 且 `ON a AND b`」 |

## 14. 附录

### 14.1 术语表

| 术语                | 定义                                                               |
| ------------------- | ------------------------------------------------------------------ |
| QB / Query Builder  | 可视化查询构建器，图形化产出 SQL `SELECT`                          |
| 整区视图            | QB 打开时替换查询面板内容区（而非浮层或上方条带）                  |
| 画布（Canvas）      | 表卡片与 JOIN 连线的自由布局区域，对应 `DiagramCanvas`             |
| 表卡片（TableCard） | 画布中表示一张表 / 视图的卡片，承载别名与字段勾选                  |
| 自动 JOIN / 候选    | 依据 FK 生成的 `autoJoins`，虚线呈现，确认后才进 SQL               |
| 已确认 JOIN         | `joins`，实线呈现，进入 SQL 的 `INNER/LEFT/... JOIN`               |
| 构建 Tab            | 底部左 Tab，承载 `BuildStatement` 子句列表（字段 / 表 / 条件 / 分组 / HAVING / 排序 / 分页） |
| 预览 Tab            | 底部右 Tab，只读展示生成的 SQL，对应 `SqlPreview`                  |
| OK                  | 提交动作：写回 SQL Editor → 关闭 QB → 聚焦编辑器（**不执行查询**） |
| 取消                | 丢弃画布改动并关闭 QB，SQL Editor 内容不变                         |
| 对象浏览器          | 即宿主 `ConnectionNavigatorTree`，QB **不自建**左栏                |
