# DataZen 全应用代码审查报告

- **日期**: 2026-08-01
- **Git 版本**: 958f1b6 (feat/ai-features)
- **审查范围**: Rust 后端、React 前端、共享包、配置文件

---

## 一、整体评价

| 维度 | 评分 | 说明 |
|------|------|------|
| 架构设计 | 良好 | 插件系统（inventory + registry）、元数据驱动 UI、trait 抽象层设计合理 |
| SOLID 遵循 | 中等 | OCP/DIP 在驱动/AI 层表现好，但 SRP 在 lib.rs、aiStore、SqlConnectionView 等处有明显违反 |
| 可扩展性 | 中上 | 新增 DB 驱动/AI 提供者很容易，但新增 IPC 命令需 3+ 处手动编辑 |
| 代码重复 | 需改进 | 多处重复模式（AES 加密、AI 命令样板、行解码、错误提取） |
| 安全性 | 需关注 | CSP 未设置、文件读写无沙箱、导出加密弱 KDF |

---

## 二、Critical 级别（必须修复）

### C1. 不受限的文件系统 IPC 命令
- **文件**: `src-tauri/src/commands/file.rs`
- **问题**: `write_file`/`read_file` 接受任意路径，无沙箱限制
- **建议**: 限制到应用数据目录或使用 Tauri 作用域文件系统 API
- **违反**: 安全最佳实践, SRP

### C2. 无内容安全策略 (CSP)
- **文件**: `src-tauri/tauri.conf.json`
- **问题**: `"csp": null` — 无 CSP
- **建议**: 设置 `default-src 'self'; script-src 'self'; connect-src 'self' tauri:`
- **违反**: 安全最佳实践

### C3. 导出加密使用弱 KDF
- **文件**: `src-tauri/src/commands/config.rs` (lines 39-53)
- **问题**: 使用 SHA-256 双轮哈希，非标准 KDF，易受暴力破解
- **建议**: 使用 Argon2id 或 PBKDF2-HMAC-SHA256
- **违反**: 安全最佳实践

### C4. 行更新无事务边界
- **文件**: `src-tauri/src/commands/data.rs` (lines 33-49)
- **问题**: `commit_row_updates` 逐行 UPDATE，中途失败导致部分提交
- **建议**: 添加事务支持，包裹批量操作
- **违反**: 数据完整性

### C5. 无 React Error Boundary
- **文件**: `src/App.tsx`
- **问题**: 任何渲染错误导致整个窗口白屏，无恢复 UI
- **建议**: 添加顶层和窗口级 ErrorBoundary
- **违反**: 错误处理最佳实践

### C6. deleteSelectedRows 仅内存操作
- **文件**: `src/stores/tableDataStore.ts` (lines 404-408)
- **问题**: 仅过滤内存行，从未调用后端删除命令
- **建议**: 实现后端 delete 命令或移除接口
- **违反**: 数据完整性

## 三、High 级别（应尽快修复）

### H1. AppState 初始化逻辑重复
- **文件**: `src-tauri/src/lib.rs` (lines 271-317, 376-433)
- **问题**: `create_app_state_headless()` 和 setup 闭包重复约 50 行初始化代码
- **建议**: 提取 `async fn build_app_state(data_dir: PathBuf) -> Result<AppState>`
- **违反**: DRY, SRP

### H2. 菜单构建重复
- **文件**: `src-tauri/src/lib.rs` (lines 57-264)
- **问题**: `build_app_menu` 和 `rebuild_menu_for_handle` 近乎相同，约 200 行重复
- **建议**: 提取共享 `build_menu()` 函数
- **违反**: DRY, SRP

### H3. AI 命令样板重复 (8 处)
- **文件**: `src-tauri/src/commands/ai.rs`
- **问题**: 每个 AI 命令重复: load config → 检查配置 → get provider
- **建议**: 提取 `resolve_ai()` 辅助函数
- **违反**: DRY, SRP

### H4. IPC 错误全部使用 String
- **文件**: 所有 `src-tauri/src/commands/`
- **问题**: 领域错误扁平化为字符串，前端无法区分错误类型
- **建议**: 定义 `CommandError`，实现 `From` 转换
- **违反**: 错误处理最佳实践, ISP

### H5. DatabaseType 硬编码映射
- **文件**: `src-tauri/src/commands/connection.rs` (lines 108-122)
- **问题**: 手动 match 映射，新类型需编辑核心代码
- **建议**: 使用 serde 序列化或 trait 方法获取类型名
- **违反**: OCP, DRY

### H6. 中英文混合错误消息
- **文件**: `src-tauri/src/commands/ai.rs` (8 处 "AI 未配置")
- **问题**: 中文错误消息与英文混用，未接入 i18n
- **建议**: 返回错误码，由前端 i18n 显示
- **违反**: i18n 一致性

### H7. aiStore 巨型 Store (700+ 行)
- **文件**: `src/stores/aiStore.ts`
- **问题**: 单个 store 管理 25+ 个 action 组
- **建议**: 拆分为 `aiConfigStore`、`aiChatStore`、`aiNl2SqlStore` 等
- **违反**: SRP

### H8. 巨型组件
- **文件**: `src/windows/connection/SqlConnectionView.tsx` (710行), `src/windows/main/MainWindow.tsx` (864行)
- **问题**: 过多职责集中在单个组件
- **建议**: 提取 hook 和子组件
- **违反**: SRP

### H9. schemaStore N+1 IPC 调用
- **文件**: `src/stores/schemaStore.ts` (lines 76-88)
- **问题**: 逐表串行调用 `getColumns`，200 表需 200 次 IPC
- **建议**: 添加批量后端命令或使用 Promise.all 并发
- **违反**: 性能

### H10. Kiwi 插件逻辑硬编码在共享 hook 中
- **文件**: `src/components/connection/useConnectionForm.ts` (lines 116-167)
- **问题**: 直接 `invoke('kiwi_*')` 并使用 `any` 类型
- **建议**: 移到插件提供的表单组件中
- **违反**: OCP, 零硬编码

### H11. SQL 编辑器硬编码 PostgreSQL 方言
- **文件**: `src/components/SqlEditor.tsx`
- **问题**: CodeMirror 始终使用 PostgreSQL 方言
- **建议**: 根据连接类型动态选择方言
- **违反**: 可扩展性

### H12. ai-api 版本不一致
- **文件**: `packages/ai-api/Cargo.toml`
- **问题**: ai-api 版本 0.1.0，其他包 0.0.7
- **建议**: 统一版本
- **违反**: 版本管理

## 六、值得保留的优秀模式

1. **inventory + register_driver!/register_ai_provider!** — 零代码注册插件
2. **DB_REGISTRY 元数据驱动 UI** — 表单/视图/方言全部数据驱动
3. **Protocol Version** — 运行时版本不匹配检测
4. **resolve-plugins.mjs** — 完整的插件解析和代码生成
5. **TypeScript 严格模式** — strict + noUnused* 全开
6. **Workspace [patch] 机制** — 本地开发不需 fork 插件
