## 1. 背景与目标

当前 DataZen 已有虚拟滚动、多列排序、列重排/冻结/列宽持久化、列统计、结构化筛选、筛选 SQL 预览、矩形单元格复制粘贴、HTML/Markdown/CSV/TSV/JSON 复制、外键导航、特殊值查看以及查询结果查找替换。优化不应重复实现已有能力，重点是补齐高频任务的端到端工作流。

### 1.1 产品目标

1. **可靠导入：** 文件格式解析正确，列匹配可控，错误能定位，导入过程可观察且不会因单条错误静默丢失数据。
2. **高效行操作：** 在已有行选择和暂存写入模型上支持复制现有行、粘贴新增行，不绕过预览、提交、回滚与主键安全检查。
3. **可控的全库查值：** 用户能决定搜索范围、匹配模式和可搜索类型，扫描可暂停、继续、取消，单表失败不影响其他结果。
4. **提升筛选与特殊值效率：** 为熟悉 SQL 的用户提供受控 Raw SQL 筛选；减少日期、NULL、长文本和二进制值的操作步骤。
5. **统一导出体验：** 表级导出和网格导出的列选择、格式语义与大任务处理行为一致。

### 1.2 非目标

- 重写 DataTable、替换虚拟滚动或改变现有分页/排序契约。
- 改变现有表数据“先暂存、预览、再提交”的写入语义。
- 自动修改目标表结构、猜测并执行数据库迁移。
- 在本项目中全面复制 TablePlus 的所有功能或快捷键。
- 未经用户确认，以覆盖、忽略或替换方式处理导入冲突。

## 4. DBR-01：导入向导与可靠解析（P1）

### 4.1 交互流程

1. 从表右键或导入入口选择文件；检测格式并读取可预览样本。
2. 配置文件格式参数。
3. 选择目标表并设置源字段到目标列的匹配方式。
4. 在预览中核对列名、类型/值样本、未映射字段和可能丢弃的数据。
5. 确认冲突策略与执行方式后导入。
6. 显示行数进度、已导入数、失败数；完成后可查看错误并刷新目标表。

~~~text
┌ 导入数据 ─────────────────────────────────────────────┐
│ 文件：orders.csv                         [更换文件]     │
│ 格式：CSV  编码：[UTF-8 ▼]  分隔符：[, ▼]  引号：[" ▼] │
│ [✓] 首行为列名   换行：[自动识别 ▼]                    │
│ 目标表：[public.orders ▼]  匹配：[按列名 ▼]             │
│ ┌ 源列            目标列              样本值 ─────────┐ │
│ │ order_no        order_no     A1001                    │ │
│ │ paid_at         paid_at      2026-10-27 11:30:00      │ │
│ │ unused_note     [不导入 ▼]  legacy                    │ │
│ └──────────────────────────────────────────────────────┘ │
│ 预览 100 行 · 3 源列 · 2 个映射 · 1 个忽略列           │
│ 冲突：[遇到错误即停止 ▼]  [预览导入计划] [开始导入]     │
└────────────────────────────────────────────────────────┘
~~~

### 4.2 功能要求

- **CSV 解析正确性：** 正确处理引号包裹字段、字段内逗号、双引号转义、字段内换行、LF/CRLF/CR 行结束符和末尾空行；不完整引号必须报错，不能默默拆错行。
- **格式配置：** CSV 提供分隔符、引号字符、编码、首行是否为表头、换行检测；JSON 提供编码与对象/数组预览；XLSX 提供工作表选择，并明确当前选中工作表。
- **目标列匹配：** 支持按列名和顺序、仅按列名、仅按顺序；允许将源列映射到目标列或“不导入”。列名匹配默认忽略大小写但显示实际目标列名，冲突时要求用户处理。
- **NULL 语义：** 空字段默认导入为空字符串还是 NULL，必须在向导中有清晰且可预览的策略；对空串和 NULL 使用不同表示，不做隐式猜测。
- **数据预览：** 至少展示前 100 行；预览样本不可代替全量校验。显示列数不匹配、重复列名、无法解析行和未映射列提示。
- **执行安全：** 明确冲突处理（停止、跳过或数据库支持时的更新/替换）；默认“遇到错误即停止”。执行不得通过一次拼接包含全部数据的巨大 SQL 来规避分批。
- **事务与部分失败：** 驱动支持事务时支持事务提交/回滚。事务不支持或用户选择分批提交时，明确告知已提交批次与部分成功状态。错误需包含源文件行号、目标列/错误原因（驱动未提供列信息时至少给出行号与原始错误）。
- **任务控制：** 显示已处理/成功/失败计数；支持取消。取消必须停止后续批次，并汇报已经提交的数据量，不得显示成“全部回滚”。
- **目标表刷新：** 完成后刷新当前表数据；刷新失败不覆盖导入结果，而应显示“导入已完成，刷新失败”。

### 4.3 验收标准

- Golden fixtures 覆盖：字段内换行、逗号、引号、UTF-8/非 UTF-8 编码、CRLF、空行、缺列、多列、重复列名、空串/NULL 和无效引号。
- 同一份 CSV 在预览与实际写入的列映射和行数一致。
- 对错误输入，系统在开始写库前能拒绝或清楚提示；不能悄悄将一行拆成多行。
- 大文件执行有进度与可解释的取消结果；不会把完整文件转换成单个巨型 SQL 字符串。
- 至少在 SQLite 和一个服务端数据库驱动上验证事务/部分成功行为；其余驱动按能力降级并说明。

### 4.4 后续扩展（不阻塞本需求）

- SQL Dump 导入（独立的 SQL 执行向导和安全提示）。
- 创建新表、从样本推断列类型。
- 更复杂的类型转换规则与可保存的导入模板。

## 5. DBR-02：复制已有行与粘贴新增行（P1）

### 5.1 交互约定

- 行选择模式下，复制选中行可保留所有源列值；单元格矩形选择模式仍使用现有区域复制，不改变当前用户习惯。
- 右键菜单增加“复制为新增行”；多选行时一次复制多行。
- 在表网格执行“粘贴行”时，若剪贴板源是 DataZen 识别的行数据，则生成新增草稿行；外部 TSV/CSV 粘贴继续走现有单元格粘贴流程，避免改变既有行为。
- 粘贴到另一张表时，先显示列映射摘要并要求确认；按同名列对齐，未匹配列默认忽略且明确列出。只有显式选择“按位置对齐”时才按位置映射。
- 所有新增行都进入现有草稿与暂存模型，不直接写库。

### 5.2 数据规则

- 复制已有行时**不复制主键值**；数据库生成列/自增列不写入；只有在列可写且复制语义明确的情况下才复制普通字段值。
- 外键、枚举、JSON、NULL、空字符串按实际值保留；列默认值必须能与“显式 NULL”区分。
- 复制多行后，每行作为独立草稿，支持逐格编辑、删除草稿、预览 SQL、一次提交或全部回滚。
- 对没有主键、行标识重复或只读连接，禁止任何可能把暂存修改错误写回源行的行为。
- 对外部剪贴板粘贴新增行先显示确认；列映射未知或目标不同的情况不能静默写库。
- **快捷键兼容：** 当前 Cmd/Ctrl+D 用于复制活动草稿行。新增已有行复制时，只有行选择模式下存在至少一条已选真实行才触发复制；编辑器输入状态不拦截按键；无真实行选择时保留草稿行原行为。

### 5.3 验收标准

- 复制一行/多行后新增行数正确，主键、生成列和默认值符合上述规则。
- 同表复制不要求重复确认，但目标表不同或来源无法识别时先展示映射预览。
- 从 Excel 粘贴矩形数据仍使用现有单元格粘贴，不会因为新增行功能意外插入记录。
- 提交失败时保留可修正的草稿/错误信息；回滚可以丢弃草稿，且不会有任何未确认的数据库写入。
- 为行模式复制、单元格矩形复制、外部粘贴、跨表粘贴、只读/无主键和复合主键建立单元测试及 E2E。

## 6. DBR-03：全库值搜索增强（P1）

### 6.1 交互

~~~text
┌ 搜索数据库中的值 ────────────────────────────────────┐
│ 内容：[customer@example.com________________]          │
│ 匹配：[包含 ▼]  范围：[全部普通表 ▼]                  │
│ 表范围：[选择表…]  类型：[文本与枚举 ▼]                │
│ [开始] [暂停] [继续] [取消]                            │
│ 进度：17 / 83 张表 · 正在扫描 billing_events           │
│ 命中表                   匹配数量      操作             │
│ customers                1             [打开并定位]     │
│ archived_customers       1             [打开并定位]     │
│ 无法搜索：3 张表（展开查看原因）                        │
└───────────────────────────────────────────────────────┘
~~~

### 6.2 功能要求

- 匹配模式增加 **Not contains**；空搜索值、大小写和 NULL 的匹配定义必须写入测试。
- 范围支持全部普通表或用户显式选择的表；列表需显示 Schema，并避免同名表混淆。
- 提供可搜索类型选择。默认保持低风险的文本/枚举/未知类型；数值、日期等类型按驱动可验证的能力逐步开放，并说明是文本表示匹配还是类型化匹配。
- 当前一条查询进行时，暂停仅在当前表请求结束后生效；继续从下一张未完成表开始，不能重复计数或漏表。取消应停止后续查询。
- 排名以真实命中数降序；失败表与零命中表分开显示。单表权限不足或类型不支持不能使整个扫描失败。
- 搜索结果点击后打开对应表并带上搜索定位信息；不得未经用户确认修改数据。
- 扫描启动前显示预计表数和“每张表至少一次查询”的代价提示。

### 6.3 验收标准

- 全部表与指定表范围执行的目标集合正确；同名跨 Schema 表不会串表。
- 对包含/不包含、精确、前缀、后缀、大小写与 NULL 边界建立纯函数与驱动集成测试。
- 暂停/继续/取消与单表失败的测试覆盖运行中状态转换；结果列表不得重复记录同一张表。
- 对大型数据库进行性能实测，记录表数、列数、查询次数和总耗时；在结果中呈现扫描成本，不虚构 ETA。

## 7. DBR-04：Any Column / Raw SQL 筛选（P2）

- **Any Column：** 让用户选择跨可搜索列匹配一个值。列类型不支持文本搜索时明确跳过或提示，不能把类型转换失败伪装成“无匹配”。
- **Raw SQL：** 与结构化筛选并列，用户输入单个 WHERE 谓词，例如 total > 100 AND status = 'paid'；显示当前数据库和 Schema 上下文，可预览最终数据 SQL 与计数 SQL，允许复制预览结果。
- 两种模式切换时保留各自的草稿，不自动执行、不悄悄丢弃当前筛选。应用后统一重置到第一页。
- Raw SQL 必须由后端校验和组装，不能由前端直接把用户文本拼接成可执行的多语句。禁止 DML/DDL、多语句和分页/排序片段；必须在实际执行使用的同一查询构建链上生成预览与读取语句。驱动无法可靠验证该表达式时禁用此模式并说明原因。
- Raw SQL 属于高级功能，UI 显示风险提示；仍须遵守只读连接、安全模式、驱动能力及现有查询执行限制。拒绝项必须有可读错误，不得退化成无筛选读取。

**验收：** 注入/多语句/注释绕过/引号/子查询边界测试；SQL 预览和真实执行的 WHERE 条件相同；清除筛选后恢复原始数据范围；结构化筛选现有行为不回归。

## 8. DBR-05：Set Value 与 Quick Look（P2）

- 现有 NULL、空字符串、默认值和撤销暂存动作继续保留，且明确区分 SQL NULL、空字符串和“不在 INSERT 中写入该列”。
- 根据驱动、列类型及权限提供日期选择器、当前日期时间/数据库原生表达式动作，以及二进制列的“从文件加载”。
- 数据库原生表达式必须用有类型的操作意图表达，不能把 NOW() 或 CURRENT_TIMESTAMP 当作普通字符串值进行参数绑定。对不支持的数据库不显示该选项。
- Binary Quick Look 支持查看与保存已有内容；从文件写入之前显示文件名、大小和目标列；只读、无主键、生成列或驱动不支持写入时禁用写入口。
- 增加更快捷的 Quick Look 入口（快捷键与中键），但先核验当前快捷键表。现有 Cmd/Ctrl+Enter 已用于提交待提交变更，不得复用或改变其含义。
- 快捷动作依然进入既有暂存/预览/提交流程；任何文件读取、转换或写入失败必须保留原值。

**验收：** 每个方言验证日期时间表达式和 NULL/默认值；二进制文件输入覆盖空文件、大文件、取消和失败；快捷键不冲突；只读和身份不明确的行不开放危险入口。

## 9. DBR-06：导出体验一致化（P2）

- 网格 DataExportDialog 增加列选择，默认选择全部列；支持“全选/清空/恢复默认”。列排序顺序遵循当前显示顺序，并在导出预览中显示将导出的列数。
- 明确当前页、选中行、全表、当前筛选结果的作用范围；选中列与选中行不能互相误导，范围变化时自动清理不合法选项。
- 统一网格导出与表级导出的 CSV、TSV、JSON、Markdown、SQL INSERT/UPDATE 等格式显示与空值转义规则。格式不支持当前范围时禁用并解释原因。
- 全表/筛选结果导出必须走流式路径。XLSX 不得通过一次性加载整表来“补齐格式”；需使用流式 XLSX writer 或明确作为单独限制继续保留。
- 大型导出任务显示行数/阶段进度，支持取消且报告部分文件是否已删除或保留。可后台运行的导出应出现在任务/通知入口；若当前任务系统不支持可靠恢复/取消，先完成可取消进度，不要伪装为后台能力。
- 文件命名、覆盖确认、导出失败时原文件保留策略需统一。

**验收：** 网格与表级入口导出相同选择范围时，列、行、NULL 和转义一致；大表测试证明内存不会随总行数线性增长；取消、磁盘写入失败和保存对话框取消均有不同结果状态。

## 10. 测试与发布门槛

### 单元测试

- CSV/JSON/XLSX 解析、映射、空值策略、行号保留、错误恢复。
- 行复制计划、主键/生成列剔除、跨表映射、草稿顺序与回滚。
- 全库搜索的目标规划、类型选择、匹配语义和状态机。
- Raw SQL 校验器及拒绝案例；筛选 SQL 构造与真实查询契约。
- 方言 Set Value 生成、二进制文件输入、导出序列化。

### 集成与 E2E

- SQLite 作为稳定冒烟基线；至少再覆盖 PostgreSQL 和 MySQL 的导入、事务/部分失败和 Raw SQL 行为。
- 驱动能力不一致时使用能力声明与降级提示，不以数据库类型名称硬编码假设。
- E2E 覆盖从导入文件到表格数据出现、复制行到提交、指定表搜索到打开定位、Raw SQL 预览到应用、取消大任务的完整流程。
- 现有 e2e/specs/table-data.ts、table-filter.ts、table-clipboard.ts、export-import.ts 的测试应扩展而非另起一套孤立流程。
- 与现有只读、安全模式、无主键/复合主键、暂存提交、焦点和 IME 规则做回归。

### 性能门槛

- 导入和导出使用固定数据集做基线测试，记录文件大小、行列数、峰值内存、处理速率与失败情况。
- 全库搜索记录总表数、被跳过的表数、失败表数、查询次数、耗时；不因增加类型支持而无提示地扫描所有 BLOB/大文本。
- 不以代码结构或“使用流式”直接宣称性能优于 TablePlus，必须同数据、同驱动、同机器实测。

## 11. 体验和数据安全原则

1. **任何数据写入都有可理解的预览或确认。** 行复制和粘贴新增必须生成草稿；导入冲突和 Raw SQL 必须显式告知风险。
2. **不静默吞错。** 解析错误、单表搜索错误、部分导入、导出取消都需呈现真实结果。
3. **NULL、空字符串、默认值和数据库表达式是四种不同意图。**
4. **驱动能力优先。** 由驱动声明可用类型、表达式和导入/导出能力，不在 UI 中假设所有数据库语法相同。
5. **同一套查询语义。** 筛选 SQL 预览与实际执行、列映射与落库、复制序列化与粘贴解析必须共用规则或共享测试夹具。
6. **不破坏现有路径。** 区域复制、单元格粘贴、排序、分页、外键导航、编辑暂存和查询结果查找替换均需回归。
