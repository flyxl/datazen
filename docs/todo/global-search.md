# 全局搜索待办

## 当前状态

当前存在两个搜索入口：

- 连接导航栏顶部的「查找连接」：搜索连接名称、Host、数据库名、数据库类型，以及已加载的部分 Schema / 表 / 视图 / 数据库对象。
- 右侧「搜索数据库对象」对话框：搜索已加载的表、视图、列和例程。

数据库对象搜索依赖连接已经建立并完成 Schema 加载。未加载时只显示“尚未加载 schema 对象”，用户无法从入口触发加载或得到可操作结果。因此该入口暂时隐藏，导航树中的无用挂载和空索引计算已清理，底层搜索组件（`GlobalObjectSearch.tsx`）和算法实现（`schemaObjectSearch.ts`）保留，待后续统一搜索方案落地后再恢复。

- 状态：待修复

- 前置条件：连接已建立，相关表和 Schema 已加载。
- 期望：搜索列名时返回列结果，并展示所属连接 / 数据库 / Schema / 表；点击结果可以打开所属表或定位到对应列。

## 全局搜索优化方案（仅方案，不在本次实现）

### 目标

提供一个统一入口，覆盖连接、数据库、Schema、表、视图、列和例程；用户不需要先打开连接或手工展开树，也能找到目标对象。

### 交互方案

1. 在主窗口提供统一搜索入口（导航栏搜索框，支持 `Cmd/Ctrl + K` 聚焦）。
2. 输入后展示分组结果：连接 → 数据库 → Schema → 对象；每条结果显示类型和完整路径。
3. 搜索不要求用户先打开连接。对未加载的连接显示“正在加载元数据”，按需加载完成后刷新结果。
4. 点击连接 / 数据库 / Schema 结果定位并展开树；点击表 / 视图打开数据页；点击列打开所属表并定位列；点击例程打开对象详情。
5. 保留当前筛选能力，支持按连接、数据库、Schema、对象类型过滤；结果最多展示前 100 条并提供继续缩小搜索的提示。

### 索引与加载方案

1. 独立建立 `GlobalSearchIndex`，索引项统一包含 `connectionId`、`dbSessionId`、数据库、Schema、对象类型、对象名、所属表和列名。
2. 连接配置和持久化分组可以立即建立基础索引；数据库 / Schema / 表 / 列 / 例程来自 Schema Cache。
3. 建立连接后后台加载轻量级对象清单；列信息按连接或数据库分批加载，避免为每张表逐条请求。
4. 搜索输入触发未加载范围时，异步补齐对应索引；搜索结果必须标明加载中、无结果和加载失败三种状态。
5. 索引只包含当前用户可访问的连接和元数据，不保存密码，不执行用户 SQL。

### 匹配规则

1. 统一大小写、空白和 Unicode 规范化。
2. 对 `order_id`、`order id`、大小写差异进行等价匹配；同时保留精确匹配、前缀匹配和包含匹配的排序优先级。
3. 对列结果优先显示 `table.column`，避免多个表都有 `id` 时结果无法区分。
4. 连接、数据库和 Schema 名称参与上下文匹配，但结果类型必须明确，不能只返回一条模糊的连接结果。

### 验收标准

- 未打开连接时输入连接名、数据库名、表名可以得到结果或明确的加载状态。
- 已加载元数据后，输入 `id`、`order_id`、`order id` 都能命中对应列，并展示完整归属路径。
- 同名列按连接 / 数据库 / Schema / 表分组展示。
- 点击不同类型结果都能进入对应页面或定位目标。
- 断开连接、刷新 Schema、删除连接后索引不会残留脏结果。
- 搜索过程不打印凭据，不执行用户 SQL，且不绕过现有连接权限。
