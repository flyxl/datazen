# DataZen 用户体验优化 PRD

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品 | DataZen 桌面数据库客户端 |
| 版本范围 | 下一季度版本，分 P0 / P1 / P2 交付 |
| 文档状态 | Draft，待产品、设计、研发评审 |
| 目标用户 | 日常使用 PostgreSQL / MySQL / SQLite / Redis 的开发者、数据工程师、技术分析用户 |
| 竞品参考 | Chat2DB Community |
| 依据 | UX 审计 Canvas、DataZen/Chat2DB main 源码、公开界面截图、发行说明 |

## 2. 背景与问题定义

DataZen 已具备 SQL 编辑、schema 浏览、查询历史、收藏、EXPLAIN、图表、AI Chat、错误诊断、Workflow、MCP、安全模式和本地凭据保护等能力。与 Chat2DB 的主要差距不是功能缺失，而是能力在用户旅程中的组织方式：

1. 安装阶段存在 macOS 未公证和 Basic / All / Akulaku 多发行变体，用户在获得产品价值前就需要理解工程概念。
2. 欢迎页主要展示功能卡，缺少从“首次打开”到“首条成功查询”的可完成路径。
3. 工作台同时展示模式栏、连接树、对象操作、查询工具栏、结果工具栏和 AI 侧栏，信息密度高，主次不够明显。
4. DataZen 的 AI 能力很强，但多数入口以“功能名”呈现，而不是围绕当前对象提供下一步任务动作。
5. 结果区已有较完整能力，但大结果集、长字段、编辑状态、取消和恢复等细节还不足以形成 Chat2DB 级别的日常使用信心。

## 3. 产品目标

### 3.1 北极星目标

让第一次安装 DataZen 的 PostgreSQL / MySQL 用户，在 5 分钟内完成：

`成功启动 → 成功连接 → 运行一条查询 → 获得一次 AI 解释、修复或图表结果`

### 3.2 量化目标

以下目标需先采集两周基线，再作为季度验收目标：

| 指标 | 目标 |
|---|---|
| 10 分钟内首条成功查询率 | 基线基础上提升 20 个百分点 |
| 下载到首次成功启动率 | ≥ 95% |
| 新用户首次连接成功率 | ≥ 80% |
| 首次查询到 AI/图表动作完成率 | ≥ 35% |
| 查询失败后成功重跑率 | ≥ 30% |
| 首次任务中的工具栏误点击率 | 较基线下降 30% |
| 大结果集取消响应 | p95 ≤ 500ms |

### 3.3 非目标

- 本期不追求一次性追平 Chat2DB 的 40+ 数据库覆盖。
- 不重写现有 Driver API、AI Provider、MCP 或 Workflow 核心架构。
- 不把用户 SQL、schema、主机、凭据或结果数据上传到产品方服务。
- 不为了增加功能而牺牲 DataZen 的轻量、本地优先和安全门禁定位。

## 4. 用户与关键场景

### 4.1 新用户：首次连接并完成查询

用户下载安装 DataZen，选择 PostgreSQL 或 MySQL，输入连接信息，希望在几分钟内看到真实结果。

成功标准：用户不需要阅读发行说明或文档，不会遇到未解释的驱动不可用状态，能从欢迎页直接进入查询。

### 4.2 开发者：查询失败后快速恢复

用户执行 SQL 失败，希望知道原因并获得可审阅的修复建议。

成功标准：错误面板直接提供“复制错误、解释并修复、查看差异、插入编辑器、重新执行”，不要求用户手工复制 SQL 和 schema 到外部 AI。

### 4.3 数据用户：从结果快速得到图表或摘要

用户查询出销售、订单或日志结果，希望快速生成图表或摘要。

成功标准：结果区提供明确的“生成图表 / 总结结果”动作，AI 生成内容不会绕过安全门直接修改数据。

### 4.4 熟练用户：继续上次工作

用户重新打开应用，希望恢复最近连接、查询、结果状态和收藏。

成功标准：主页统一呈现最近连接、最近查询、固定项目和未完成任务，不需要在欢迎页、连接主页、工作区空状态之间重新寻找入口。

## 5. 方案概述

### 5.1 P0：可信安装与首次激活

#### P0-1 统一推荐下载路径

**需求**

- 官网按操作系统自动选择推荐安装包。
- 默认只突出一个面向普通用户的推荐版本。
- Basic / All / 特定部署版本归入“高级下载”，并解释差异。
- 完成 macOS 签名、公证和自动更新检查。
- 安装页和应用内显示当前发行版包含的数据库驱动。

**验收标准**

- macOS 新用户无需执行 `xattr` 或阅读终端命令即可启动。
- 下载页在 10 秒内能回答“我应该下载哪个包”。
- 用户点击未包含的数据库类型时，看到“当前版本不支持 / 获取支持版本”的可执行提示，而非泛化连接错误。

#### P0-2 三步首次激活向导

**需求**

欢迎页改为可跳过的三步引导：

1. 创建连接或打开示例 SQLite。
2. 运行第一条查询。
3. 选择“AI 解释 / 修复 / 生成图表”之一。

补充：

- 提供一键打开的本地示例数据库，不需要网络和凭据。
- AI 未配置时，展示配置入口，同时允许跳过。
- 每一步显示当前进度、返回和跳过操作。
- 保留“导入连接”作为次级路径。

**验收标准**

- 新用户从欢迎页最多 2 次点击即可打开示例数据。
- 示例查询可以离线运行并看到结果。
- AI 配置未完成时，用户仍能完成 SQL 查询主路径。
- 向导中断后重新打开应用可恢复上次步骤。

### 5.2 P0：工作台信息层级与可发现性

#### P0-3 查询主工具栏重排

**默认可见**：新建查询、运行/停止、保存、AI。

**分组或溢出菜单**：格式化、补全刷新、事务、EXPLAIN、导出、参数历史等。

**需求**

- 图标按钮必须有可访问名称和稳定 tooltip。
- 首次使用时以一次性标签解释高价值动作。
- 左侧模式栏支持“图标 / 图标+文字”两种模式，偏好可持久化。
- Safe Mode、事务状态、连接状态和执行时长固定在状态区域呈现。
- 窄窗口下优先保留运行/停止和当前连接上下文。

**验收标准**

- 新用户无需 hover 全部按钮即可找到运行、停止、保存和 AI。
- 视窗宽度减少时不出现关键按钮遮挡或不可达。
- 所有隐藏动作仍可通过命令面板或键盘快捷键访问。

### 5.3 P1：驱动可用性与连接体验

#### P1-1 连接选择器增加可用性分层

**需求**

- 数据库类型分为“当前版本可用”和“需要其他版本”。
- 每个不可用类型显示原因：未编译、需 All 版本或需安装更新。
- 保留搜索、默认值、测试连接、SSH 和 URI 粘贴填充。
- 连接测试失败时，按网络、认证、驱动、数据库不存在、权限不足分类。
- 对自动读取剪贴板进行可见提示，避免用户不理解字段为何被填充。

**验收标准**

- 用户在选择数据库类型后能立即知道是否需要换版本。
- 测试连接失败时至少提供下一步动作和“复制详细错误”。
- 连接表单不会因驱动不可用而丢失已填写字段。

### 5.4 P1：任务化 AI 闭环

#### P1-2 按对象提供 AI 动作

**入口与动作**

| 上下文 | 主动作 |
|---|---|
| 空查询编辑器 | 描述需求生成 SQL |
| 查询失败 | 解释错误并修复 |
| 查询结果 | 总结结果 / 生成图表 |
| EXPLAIN 结果 | 定位瓶颈 / 给出索引建议 |
| 表或字段 | 解释结构 / 生成查询模板 |
| Workflow 页面 | 从模板生成步骤 |

**统一输出动作**

1. 查看生成 SQL。
2. 查看与当前 SQL 的差异。
3. 插入编辑器。
4. 在安全门确认后执行。

**验收标准**

- 每个高频上下文至少有一个明确 AI CTA。
- AI 输出不会静默替换编辑器内容。
- 写操作继续经过 Safe Mode / 风险等级 / 用户确认。
- AI 请求前继续展示数据出站范围和 provider 信息。
- AI 生成草稿与用户已有输入冲突时，提供替换、追加、取消。

### 5.5 P1：结果区可靠性

#### P1-3 大结果集与编辑状态

**需求**

- 10 万行级结果采用虚拟滚动，避免一次性渲染阻塞界面。
- 查询取消、导出取消和关闭连接时提供明确状态。
- 长字段默认截断，点击后在详情抽屉查看完整内容。
- 单元格编辑显示未提交、提交中、成功、失败状态。
- 筛选、排序、分页与当前结果集绑定，不意外打开新结果标签。
- 导出失败允许重试，不丢失筛选条件。
- 建立 PostgreSQL / MySQL / SQLite / Redis 的连续旅程测试。

**验收标准**

- 10 万行结果可滚动，主线程不出现明显冻结。
- 点击取消后 p95 500ms 内进入取消态。
- 编辑失败保留用户输入和原值差异。
- 切换结果标签后，筛选排序状态可预测且不污染其他结果。

### 5.6 P2：统一主页与继续工作

#### P2-1 统一空状态信息模型

主页按以下顺序呈现：

1. 继续最近连接 / 最近查询。
2. 固定连接和最近结果。
3. 新建查询、导入连接、备份恢复等常用操作。
4. 推荐任务：示例查询、AI 解释、生成图表、Workflow 模板。
5. 快捷键和一次性更新提示。

移除或弱化不能直接触发动作的重复指标卡，避免欢迎页、连接主页和工作区空状态各自讲一套产品故事。

#### P2-2 隐私友好的 UX 观测

**允许记录**：阶段事件、耗时、错误类别、应用版本、操作系统。

**禁止记录**：SQL、schema、主机、数据库名称、凭据、结果数据、AI 内容。

**需求**

- 首次启动说明观测用途并提供关闭开关。
- 设置页展示将发送的字段，并支持导出本地诊断包。
- 错误报告可复制，且默认脱敏绝对路径和凭据。

## 6. 交互流程

### 6.1 首次激活流程

`启动 → 检查发行版/驱动 → 欢迎向导 → 示例库或新建连接 → 测试连接 → 首条查询 → AI/图表动作 → 保存为最近任务`

### 6.2 查询错误恢复流程

`执行失败 → 错误面板分类 → 复制 / AI 修复 → 查看差异 → 插入编辑器 → 用户确认 → 重新执行 → 记录成功恢复`

### 6.3 未安装驱动流程

`选择数据库 → 显示当前版本状态 → 解释差异 → 获取正确版本 / 继续配置其他连接 → 返回时保留输入`

## 7. 优先级与里程碑

### 0–30 天：先堵漏斗

- 完成签名、公证和推荐下载包方案。
- 定义并接入匿名激活漏斗事件。
- 实现三步首次激活向导和示例 SQLite。
- 连接选择器标识已安装 / 不可用驱动。

### 31–60 天：重排工作台

- 完成查询工具栏主次重排和图标+文字模式。
- 统一欢迎页、连接主页和空状态。
- 接入连接、查询、错误修复和图表连续旅程测试。
- 增加快捷键总览或命令面板。

### 61–90 天：放大差异化

- 上线任务化 AI 动作与统一输出动作。
- 完成大结果集、长值、编辑恢复和取消体验。
- 为 Workflow 提供模板和表单创建，默认隐藏 YAML 复杂度。
- 依据漏斗数据决定 All 包、长尾数据库和 driver 分发策略。

## 8. 验收与测试计划

### 8.1 用户测试

- 5–8 名目标用户，至少包含开发者和数据分析用户。
- 任务：首次安装、连接本地 PostgreSQL、执行查询、修复错误、生成图表、恢复最近查询。
- 记录完成率、完成时间、误点击、求助次数和主观信心。

### 8.2 自动化测试

- WelcomePage：向导步骤、跳过、恢复、示例库。
- NewConnectionDialog：驱动状态、测试失败分类、字段保留。
- QueryEditor：工具栏响应式、快捷键、运行/停止。
- AiChatPanel：未配置、草稿冲突、插入/差异/确认执行。
- ResultTable：大数据、长值、编辑状态、取消和导出恢复。
- E2E：PostgreSQL / MySQL / SQLite / Redis 四条连续旅程。

### 8.3 发布门槛

- P0 验收标准全部通过。
- macOS、Windows、Linux 推荐安装包完成真实安装启动验证。
- 关键 E2E 在 CI 通过，失败不得以跳过测试替代。
- 默认不开启 SQL/schema/结果内容采集。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| macOS 签名/公证成本或证书延期 | P0 安装目标延期 | 先统一下载页和应用内提示；签名完成前明确标注临时方案和一键帮助。 |
| All 包增大安装体积 | 轻量定位受损 | 先用推荐包 + 清晰驱动状态验证需求，再决定是否统一 All。 |
| 工具栏重排影响熟练用户 | 迁移成本 | 提供高级用户布局偏好、命令面板和稳定快捷键。 |
| AI CTA 增多导致视觉噪声 | 工作台更复杂 | 只在上下文相关时显示，统一最多一个主 AI 动作。 |
| 大结果集优化触及驱动边界 | 研发周期增加 | 先在结果渲染、取消和状态模型做 Host 层抽象，再逐驱动验证。 |
| 观测引发隐私担忧 | 信任下降 | 默认最小化、可关闭、字段透明、绝不采集 SQL/schema/凭据/结果。 |
