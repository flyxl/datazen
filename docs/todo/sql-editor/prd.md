## 1. 背景与核心设计原则

### 1.1 背景与现状诊断
DataZen 当前的查询编辑面板（`QueryPanel` + `SqlEditor`）已具备基础的执行、多结果集、参数绑定横条、以及基于 AI 的行内诊断与解释能力。但在高频深度 SQL 编写场景下，仍存在以下体验断层：
1. **语句边界不明确**：当前执行逻辑为“无选区即执行全脚本或需手工划选”，写了多条语句时光标所在位置没有视觉边界，极易误执行整个脚本。
2. **补全仅为平铺字典**：补全仅基于当前连接加载的表名/字段名字典，缺乏 AST 级语义推断。无法根据 `FROM table_name t` 中的别名 `t.` 智能过滤字段，编写 `JOIN` 时无法利用外键元数据推荐关联条件。
3. **日常剪贴板与拖拽交互缺失**：从 Excel/CSV 复制成百上千个 ID 无法快速转为 SQL 的 `IN (...)` 语法；从连接树拖拽表/字段进编辑器缺少插入光标与方言引号适配。
4. **参数占位符语法受限**：现有参数解析仅支持 `:name` 与 `$1`，不支持企业中常见的 `@name`、`?`、`${var}` 语法，且缺乏历史输入记忆。

### 1.2 核心设计原则（“不盲从、重整合、高内聚”）
- **延续原生优势，杜绝功能重复**：
  - **错误诊断不重造轮子**：保留 DataZen 现有的 `QueryErrorPanel` 原地诊断（`DiagnosisPanel`）、一键应用修复 SQL 与就地重试的连贯体验；仅在此基础上补充“发送到 AI Chat 深度讨论”的联动入口，绝不重写独立的侧边栏聊天引擎。
  - **参数输入不破坏沉浸感**：保留 DataZen 原生紧凑的内嵌横条 `BindParamPanel` 交互，拒绝打断思绪的模态大弹窗，仅在底层增强多语法识别与历史值记忆。
  - **生产安全轻量化**：升级底层的静态风险识别逻辑（补充无 `WHERE` 的 `DELETE/UPDATE` 拦截），复用既有的 `useConfirmDialog` 机制，不搞冗长繁琐的多重弹窗。
  - **多库分发归位 Workflow**：复杂的跨库批量分发交由 DataZen 统一的 Workflow 编排引擎处理，不在单编辑器内堆砌独立的调度体系。
- **严格遵循代码规模规范（AGENTS.md）**：
  - 严禁出现数千行的巨型单文件，单个文件代码量严格限制在 500 行以内（推荐 200~300 行）。
  - 编辑器拆分为核心容器、扩展层插件、纯前端微型语义模型、工具函数等高内聚子模块。

## 3. 功能特性详细规格说明

### 3.1 语句边界感知与精准执行控制

#### 3.1.1 当前语句视觉边框 (Statement Frame Layer)
- **痛点解决**：多语句编辑时，用户不知道当前快捷键执行的具体代码区间。
- **功能逻辑**：
  - 基于轻量词法分词器，实时计算光标所在活动语句（Active Statement）的起止范围（正确忽略注释与字符串内的分号）。
  - 在当前语句外周绘制一层半透明发光微边框（如 `border-accent/30`，内边距 2px），直观提示即将执行的代码边界。
  - 光标切换到其他语句或出现文本多行选区时，自动重绘或暂时隐藏。
  - **性能保护**：超 500 行的超大语句自动降级绘制，保障编辑输入绝对流畅（60fps）。

#### 3.1.2 行号槽单语句运行按钮 (Statement Gutter)
- **功能逻辑**：
  - 在每条有效 SQL 语句的首行行号旁边，渲染一个极简可交互的“运行”（Play）小图标。
  - 鼠标悬停显示 Tooltip（`运行此语句 (Cmd+Enter)`）。
  - 单击即可仅提取并执行该条语句，结果刷新至下方结果区。
  - 正在执行中状态下，当前语句的行号图标变为微型转圈动画。

#### 3.1.3 多粒度执行快捷键体系
- **`Cmd/Ctrl + Enter`**：
  - 若有选中文本，优先执行选中 SQL。
  - 若无选中文本，**精准执行光标所在的当前语句**（不再默认盲目执行全文件）。
- **`Cmd/Ctrl + Shift + Enter`**：
  - 执行全编辑器脚本（或在新 Tab 中执行当前语句）。

### 3.2 纯前端容错语义 AST 与智能补全增强

#### 3.2.1 纯前端轻量容错语义模型 (Semantic Model)
- **核心定位**：零后端 IPC 依赖、毫秒级响应、容错能力强的 TypeScript 语义提取器。
- **核心能力**：
  - **作用域与表别名提取**：识别 `FROM table_name t`、`JOIN other_table o`，建立别名映射关系表 `t -> table_name`、`o -> other_table`。
  - **CTE (`WITH`) 别名可见性**：识别顶部临时表定义，在主查询中作为虚拟表提供补全。
  - **方言适配器 (Dialect Adapter)**：抽象标识符引用符号（MySQL `` ` ``、PG `"`、SQL Server `[]`）、大小写折叠策略与投影别名可见性。

#### 3.2.2 上下文智能补全 (Context-Aware Autocomplete)
1. **别名感知字段联想**：
   - 当用户键入 `t.` 时，根据已解析的 `t -> table_name`，**仅推荐该表的字段列表**，并在详情区展示字段类型（如 `VARCHAR(64)`）与注释。
2. **外键关联与智能 `JOIN` 补全**：
   - 当键入 `JOIN ` 触发补全时，读取当前连接的 Foreign Key 元数据。
   - 优先推荐与现有表存在外键关系的表名；选中后**自动补齐完整 `ON a.user_id = b.id` 连接条件**。
3. **函数签名与参数提示**：
   - 输入聚合/内置函数（如 `DATE_ADD(...)`、`CONCAT(...)`）时，弹出签名浮层并加粗当前参数。

#### 3.2.3 意图操作 (Intention Actions / Alt+Enter)
在光标处按下 `Alt+Enter`（或点击小灯泡图标）弹出快捷重构菜单：
- **`SELECT *` 一键展开**：将 `*` 替换为对应表的全部物理列名列表，自动根据当前方言决定是否加上表别名与引号。
- **字段智能添加/移除别名前缀**：一键为所选区间的裸字段补全或清除表别名前缀（如 `status` -> `o.status`）。

### 3.3 体验增强与阅读辅助

#### 3.3.1 `INSERT` 字段名内联提示 (Inlay Hints)
- **痛点解决**：编写 `INSERT INTO users VALUES (1, 'Alice', 'admin', 25, true)` 时，难以直观分辨每个值对应哪个字段。
- **功能逻辑**：
  - 编辑器在每个值前面渲染微小的不可编辑内联文本标签（如 `id:`、`name:`、`role:`）。
  - 自动根据当前表元数据的列顺序或显式声明的列清单进行对位推断。
  - 纯视觉辅助，不改变用户实际编辑的文件文本，可由用户在设置中随时开关。

#### 3.3.2 表名悬停预览卡片 (Hover Table Card)
- 鼠标悬停在 SQL 中的表名/视图名上方 300ms 时，弹出简洁实用的轻量浮层：
  - 展示所属库、表注释、主键与索引概况。
  - 核心字段清单（字段名、数据类型、可空性、注释）。
  - 提供快速链接：`查看数据`、`设计表结构`、`复制 DDL`。

#### 3.3.3 `Cmd/Ctrl + Click` 快速定义跳转
- 按住 `Cmd/Ctrl` 悬停于表名或视图名变为下划线链接。
- 单击直接在 DataZen 中打开对应表的数据网格页（DataTab）或结构页，省去在左侧目录树中翻找的过程。

---

### 3.4 生产力与日常剪贴板工具

#### 3.4.1 剪贴板智能转 `IN` 条件 (`Paste as IN Condition`)
- **场景**：日常排查问题时，经常从 Excel、CSV 或告警日志复制一长列 ID。
- **功能逻辑**：
  - 快捷键 `Cmd/Ctrl + Shift + V` 或编辑器右键菜单项“粘贴为 IN 条件”。
  - 自动识别换行符、逗号或制表符，过滤多余空白。
  - 自动转换为合法的 `IN ('1001', '1002', '1003')` 格式，字符串自动转义内部单引号，数字可选择是否保留纯数值。
  - 若光标前已有 `IN` 或 `NOT IN` 关键字，智能省略重复的 `IN` 词项，仅插入 `('...', '...')`。

#### 3.4.2 侧边栏拖拽指示线与方言智能引号 (Drop Caret & Smart Quotes)
- 从左侧连接树拖拽表或列名到编辑器中时：
  - 编辑器渲染精准的字符级指示光标线（Drop Caret），松手即可准确落在目标位置。
  - 根据当前连接类型自动应用引号：
    - MySQL / ClickHouse / Doris 自动补反引号 `` `table` ``。
    - PostgreSQL / openGauss 自动补双引号 `"table"`（严格标识符正则且全小写时可智能免除引号）。
    - SQL Server 自动补方括号 `[table]`。

#### 3.4.3 多光标同词项选择与矩形列选
- 支持 `Mod + D` 连续添加下一个匹配同词光标，方便局部重命名变量或批量修改。
- 支持 `Alt + 鼠标左键拖拽` 激活矩形列选择，便于快速多行对齐编辑。

### 3.5 原生优势功能就地增强（拒绝盲目重构）

#### 3.5.1 参数化输入：强化现有 `BindParamPanel`
- **坚持原生形式**：保留 QueryPanel 顶部的横向轻量参数横条，不改用阻断性的模态弹窗。
- **语法能力扩充**：
  - 升级 `src/lib/sqlBindParams.ts`，由目前的仅支持 `:name` / `$1` 扩展为支持：
    - 命名参数：`:name`
    - 变量形式：`@name` (SQL Server / MySQL 用户常用)
    - 问号占位符：`?`（顺序自动编号为 $1, $2, ...）
    - 模板变量：`${name}`
- **历史值快捷复用**：
  - 自动在 localStorage 中按 `connectionId + paramName` 暂存最近输入的 5 个有效值。
  - 参数输入框聚焦时支持下拉快捷点选历史输入值，避免重复手工录入。

#### 3.5.2 错误诊断与修复：连贯的原地处置 + 深度讨论打通
- **维持原生优势**：
  - 保持 `QueryErrorPanel` 原生的“就地重试 (`Retry`)”与“一键修复 (`Fix SQL`)”能力不变。
  - 点击“修复”后，内联展开现有的 `DiagnosisPanel`，用户可以在面板中直接查验原因并一键将修复 SQL 应用到编辑器中执行。
- **深度会话打通（轻量联动，非新开侧栏）**：
  - 在 `QueryErrorPanel` 按钮栏新增一个操作项：**`向 AI 提问 (Ask in Chat)`**。
  - **联动行为**：点击后直接聚焦或展开主界面的 `AiChatPanel`，自动注入一段结构化 Prompt：包含当前的错误信息、出错 SQL 以及所在 Database/Schema 上下文，方便用户与 AI 进行多轮深度探讨，而不是在编辑器内重造一套独立的 AI 聊天界面。

#### 3.5.3 生产环境安全与高危 SQL 拦截
- **强化 `src/lib/dangerousSql.ts`**：
  - 在现有识别 `DROP` / `TRUNCATE` 的基础上，补充静态词法分析：
    - 识别未携带 `WHERE` 条件的 `DELETE FROM` 语句。
    - 识别未携带 `WHERE` 条件的 `UPDATE` 语句。
- **统一使用 `useConfirmDialog`**：
  - 当触发上述高危语句执行时，唤起原生风格的确认对话框，展示醒目的危险 Badge、受影响语句与操作确认。
  - 若连接配置了“生产环境 (Production)”标签，对一切非只读语句强制执行二次确认。

## 4. 技术设计与代码组织架构（严格执行单文件限长）

为了严格遵循 `AGENTS.md` 中**单源码文件不超过 500 行**的铁律，本次设计将编辑器的各项功能彻底解耦拆分，目录结构规划如下：

```text
src/components/sql-editor/
├── SqlEditor.tsx                        # 核心对外组件（装配 CodeMirror、受控状态，< 300行）
├── extensions/                          # 模块化 CodeMirror 6 扩展包（每文件 < 200行）
│   ├── statementFrame.ts               # 当前语句发光边框 Layer 扩展
│   ├── statementGutter.ts              # 行号槽单语句执行小图标扩展
│   ├── inlayHints.ts                   # INSERT 列名内联提示插件
│   ├── hoverTooltip.ts                 # 表元数据悬停解析与弹层扩展
│   ├── tableDrop.ts                    # 侧边栏拖拽指示线与方言引号处理
│   ├── occurrenceSelection.ts          # Mod+D 同词项多光标选择
│   └── completionKeymap.ts             # 补全确认与 Tab 键行为拦截
├── semantic/                            # 纯前端轻量 SQL 语义分析体系（每文件 < 300行）
│   ├── tokenizer.ts                    # 容错分词器（识别关键字、注释、字符串、括号边界）
│   ├── scopeModel.ts                   # 查询作用域、FROM/JOIN 表与别名映射解析
│   ├── dialectAdapters.ts              # 多方言差异配置（MySQL, PG, SQLite, ClickHouse 等）
│   └── intentionActions.ts             # Alt+Enter 意图操作（SELECT * 展开、别名前缀处理）
├── completion/                          # 智能补全数据源（每文件 < 250行）
│   ├── schemaCompletionSource.ts       # 表名与别名字段补全源
│   ├── foreignKeyJoinCompletion.ts     # 基于外键关系的智能 JOIN 补全源
│   └── functionCompletionSource.ts     # 内置函数与签名补全源
└── utils/                               # 纯工具库
    ├── inListPaste.ts                  # 剪贴板文本自动转 IN 条件算法 (< 150行)
    └── statementRanges.ts              # 光标所在当前语句边界计算 (< 200行)
```

## 6. 验收标准与测试保障

1. **执行边界精准**：在一个包含多条 SQL 的文件中，光标置于任意语句，当前语句必须被发光框准确标示；按 `Cmd+Enter` 或点击行号旁运行按钮，仅执行该单条语句。
2. **智能补全准确**：输入 `SELECT o. FROM orders o`，在 `o.` 之后弹出的候选项必须仅包含 `orders` 表的列，且带类型标识；输入 `SELECT * FROM orders o JOIN users u` 能智能推荐外键 `ON o.user_id = u.id`。
3. **Alt+Enter 展开验证**：在 `SELECT * FROM users` 上触发意图操作，`*` 必须被精确展开为该表的全部物理列名并带有当前数据库正确的转义引号。
4. **原生联动体验**：
   - 输入包含 `:id`、`@tenant` 的 SQL，上方内嵌 `BindParamPanel` 正确捕获并显示输入框；
   - 执行出错时，原地错误面板可直接点“修复”展开诊断或点“重试”就地重新执行；点击“向 AI 提问”能将上下文无缝发送到右侧 `AiChatPanel`。
5. **代码质量与性能底线**：
   - 目录内所有新增 TypeScript 文件均严格低于 500 行，无巨型臃肿单文件。
   - 20,000 行复杂脚本下打字输入完全无延迟（帧率维持 60fps），AST 解析单次耗时 `< 5ms`。
