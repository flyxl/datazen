## 1. 背景与设计目标

### 1.1 背景分析
目前绝大多数轻量级数据库管理工具（如早期的 Navicat、DBeaver 或各类 Web 端 SQL 编辑器）在代码编写阶段体验较为粗糙：
1. **代码感知弱**：缺乏 AST 级别的纯前端语义模型，补全仅停留在简单的前缀字典匹配，无法根据 `FROM` 别名、`JOIN` 依赖及上下文作用域精准推断字段。
2. **生产安全性低**：缺乏针对高危 DML/DDL（如无 `WHERE` 的 `UPDATE/DELETE`、`TRUNCATE`、`DROP`）的静态拦截与事前 Diff 预览能力。
3. **日常交互繁琐**：从外部 Excel/CSV 复制多行数据无法一键转化为 `IN ('...', '...')`，输入参数化查询时缺乏结构化 Bind 对话框，编写多行复杂 SQL 时无法精准感知当前执行边界。
4. **AI 与编辑器割裂**：AI 仅作为外挂聊天侧栏，无法无缝获取当前编辑器的语法上下文、光标选区与数据库元数据。

### 1.2 核心设计目标
- **智能感知（Intelligent & Context-Aware）**：建立纯前端轻量级 SQL 语义分析树（Semantic AST），支持外键智能 `JOIN` 条件推导、`INSERT` 语句内联字段提示（Inlay Hints）、`SELECT *` 一键展开等现代 IDE 体验。
- **安全可控（Safe & Defensive）**：引入高危语句语法级别拦截、DML 执行前变更预览（自动生成 SELECT 比对受影响行）、生产环境多级警示与参数化安全执行。
- **极致交互（Power & Ergonomic）**：支持当前语句动态视觉边框（Statement Frame）、行号槽单语句执行（Statement Gutter）、多光标/矩形列选、Vim 键绑定、剪贴板一键转 `IN` 条件及精美代码快照卡片导出。
- **深度 AI 协同（AI-Native）**：双模 AI 交互（Ask 单任务引导 + Agent 多轮自主执行），支持通过 `@table`、`@sqlFile` 及截图无缝注入上下文。
- **架构解耦（Driver-Agnostic）**：遵循 DataZen 驱动体系，所有 SQL 方言差异、数据类型表示、引号规则均由 Driver 扩展与语义适配层驱动，前端不硬编码驱动专属分支。

## 2. 用户角色与典型使用场景

### 2.1 用户画像
- **业务研发工程师**：日常编写复杂多表关联 SQL，需要高效的自动补全、快速格式化、字段类型提示及别名智能限定。
- **数据库管理员 (DBA)**：频繁操作生产库，高度依赖高危操作拦截、变更前 DML Diff 预览、多库批量任务分发及执行历史回滚审计。
- **数据分析师**：经常从 Excel、报表复制大量 ID 到编辑器中进行 `IN` 查询过滤，需要便捷的剪贴板格式化工具与多库分发执行能力。

### 2.2 典型用例流程
1. **快速编写关联查询**：用户输入 `SELECT * FROM orders o JOIN users u`，编辑器自动弹出外键补全提示，Tab 确认后自动补齐 `ON o.user_id = u.id`；随后按下 `Alt+Enter` 触发意图操作，将 `SELECT *` 自动展开为带有表别名前缀的具体字段列表。
2. **生产安全更新**：用户输入 `UPDATE orders SET status = 'PAID' WHERE id = 101`，点击右键“预览变更”，系统自动生成对应的只读 SELECT 语句并在结果集中展示将要修改的数据旧值与新值对比，确认无误后再执行。
3. **外部数据批量过滤**：用户从电子表格复制了 500 个订单号，在编辑器中右键“粘贴为 IN 条件”，编辑器自动将其处理为合法的 `IN ('ORD001', 'ORD002', ...)` 语法并插入当前光标处。
4. **参数化模板执行**：执行带有 `:startTime` 和 `:tenantId` 的业务排查脚本，编辑器弹出参数填写浮层，自动加载上次输入历史并校验类型，一键安全代入执行。

## 3. 功能特性详细规格说明

### 3.1 核心编辑与多模式执行体验

#### 3.1.1 当前语句视觉边框 (Current Statement Frame Layer)
- **需求描述**：当光标停留在编辑器某一行时，编辑器通过词法分词器动态计算该语句的起始与结束范围（支持处理行注释、块注释、多行文本及嵌套语句）。
- **交互要求**：
  - 在当前语句的文字外缘渲染一层轻量级发光虚线/微实线轮廓矩形（Statement Frame），带有可配置的内边距（如 2px）。
  - 当光标移动到其他语句或产生选区时，边框自适应平滑重绘。
  - 针对多达数百行以上的复杂 PL/SQL 过程或脚本设置阈值保护（如超 500 行自动降级），避免几何探测引起视口卡顿。

#### 3.1.2 行号槽语句执行按钮 (Statement Gutter Marker)
- **需求描述**：在每条独立语句的第一行行号右侧（Gutter）显示可交互的“运行”（Play）图标。
- **交互要求**：
  - 鼠标悬停显示 Tooltip（如“运行此语句 (Cmd+Enter)”）。
  - 单击即可单独提取并执行该条语句，不影响脚本其他部分。
  - 若正在执行中，图标可切换为微型加载动画或停止按钮。

#### 3.1.3 多粒度执行模式 (Execution Target System)
- **执行目标候选**：
  1. **光标当前语句**（Current Statement）：默认快捷键 `Cmd/Ctrl + Enter`。
  2. **当前选区代码**（Selected SQL）：有选区时优先执行选区内容。
  3. **全文脚本执行**（All Statements / Whole Script）。
  4. **在新结果页签执行**（Execute in New Tab）：快捷键 `Cmd/Ctrl + Shift + Enter`，执行结果另起独立 Tab 展示，不冲掉上一次结果。
- **执行候选器选择框 (SqlExecutionTargetPicker)**：当存在模糊边界或用户通过指令面板触发时，在光标处弹出轻量级候选浮层，支持键盘上下键切换并回车确认。

#### 3.1.4 高级文本选择与多光标 (Selection & Caret Ergonomics)
- **同词项多光标选择**：
  - 快捷键 `Mod + D`（macOS 为 `Ctrl + G`，Windows 为 `Alt + J`）高亮下一个匹配词项并追加光标。
  - 支持快捷键一键全选当前词的所有出现位置（Select All Occurrences）。
- **矩形列选择 (Rectangular Selection)**：
  - 支持 `Alt + 鼠标左键拖拽` 激活块选择，适用于批量对齐修改多个字段或批量添加引号。
- **语法选区层级缩放 (Extend / Shrink Selection)**：
  - 参考 JetBrains 体验（`Alt + Up / Down`），以 AST 语法结构逐级向上扩大或缩小选区（标识符 -> 表达式 -> 子句 -> 完整语句 -> 代码块）。

#### 3.1.5 Vim 键位模式 (Vim Emulation)
- 支持在设置中一键开启/关闭 Vim 模式。
- 完整支持 Normal / Insert / Visual / Visual Block 模式、常用移动命令（`hjkl`、`w`、`b`、`ciw`、`dd` 等）及多寄存器操作。

### 3.2 智能代码感知与语义分析 (IntelliSense & Semantic Engine)

#### 3.2.1 纯前端轻量级 SQL 语义模型 (Semantic AST)
- **解析层**：构建零后端依赖、跨方言（MySQL / PostgreSQL / SQL Server / Oracle / SQLite / ClickHouse）的词法分词与微型语义解析器。
- **语义作用域判定**：
  - 精准解析查询的作用域（Scope）、`FROM` / `JOIN` 的主表与别名绑定、CTE (`WITH`) 别名可见性。
  - 解析子查询边界及外部变量引用。

#### 3.2.2 上下文感知自动补全 (Context-Aware Autocomplete)
- **对象补全**：根据输入位置推断需要表名、Schema、Catalog 还是字段名。
- **外键关联与智能 JOIN**：
  - 在输入 `JOIN` 关键字时，自动读取当前已有表的外键约束元数据。
  - 候选列表中高亮显示具有外键关系的关联表，并附带关联路径提示（如 `related by user_id -> users.id`）。
  - 选中后自动补齐完整的 `JOIN users u ON o.user_id = u.id` 结构。
- **批量列补全 (Batch Column Selection)**：
  - 在 `SELECT` 列清单或 `INSERT INTO ... (...)` 中，提供“全部列（逗号分隔）”或“快速勾选多列”的批量补全项。
  - 若已有表别名，自动带上别名前缀（如 `u.id, u.name, u.email`）。

#### 3.2.3 非关系型数据源适配 (NoSQL Completion)
- **Redis**：支持全量 Redis 命令提示、参数格式推导（如哈希表命令提示 `HSET key field value`）、内置 Key 探测与安全语法诊断。
- **MongoDB**：支持 Mongo Shell 方法提示（`find`、`aggregate`、`updateOne`）及查询操作符（`$match`、`$group`、`$in` 等）补全与格式化。
- **Elasticsearch**：支持 REST 路径补全（`GET /<index>/_search`）、DSL Query Body 语法提示及 JSON 校验。

### 3.3 内联提示与实时语法诊断 (Inlay Hints & Diagnostics)

#### 3.3.1 INSERT 值内联字段名提示 (Insert Value Hints)
- **需求描述**：当编写 `INSERT INTO table_name VALUES (1, 'Alice', true)` 等语句时，由于没有显式书写列清单，用户难以将具体值与字段对应。
- **交互要求**：
  - 编辑器在每个值前面渲染不可交互、微小字号的字段标签小气泡（如 `id:`、`username:`、`is_active:`）。
  - 若为带列清单的 `INSERT INTO t (colA, colB) VALUES (...)`，则按照列清单对位推导；若为省略列清单形式，则异步加载该表元数据后动态插入提示。
  - 文本编辑、光标移动及复制操作对提示无感知，不改变实际 SQL 文本内容。

#### 3.3.2 实时语法错误诊断 (Live Diagnostics)
- **基础红波浪线标注**：即时标记括号不匹配、未闭合引号、保留字误用及非法字符。
- **存储过程与例程高级诊断**：针对复杂的 MySQL 存储过程（如缺少 `DELIMITER`、`END` 语句缺失）及 Oracle PL/SQL 块进行专门语法校验。
- **快速修复建议（Quick Fix）**：点击诊断图标可一键查看建议修复方案。

#### 3.3.3 函数参数签名悬浮 (Signature Tooltip)
- 当用户在函数名后输入左括号 `(` 或光标处于参数区间时，弹出浮层显示该函数的完整签名，并高亮加粗当前光标所在参数（如 `CONCAT(str1, [str2, ...])`）。

### 3.4 意图操作与代码重构 (Intention Actions / Alt+Enter)

借鉴现代 IDE（如 DataGrip）的快速修复重构体验：

| 意图操作 (Kind) | 触发条件 | 执行效果 |
| :--- | :--- | :--- |
| **`expand_wildcard`** | 光标停留在 `SELECT *` 或 `SELECT t.*` 的 `*` 通配符上 | 自动将其展开替换为该表的所有物理字段名称列表，并按方言添加引号与别名 |
| **`qualify_identifier`** | 光标停留在无前缀的列名上，且查询中存在明确主表或表别名 | 自动给该列追加表别名前缀（如 `status` -> `o.status`） |
| **`unqualify_identifier`** | 光标停留在带有表前缀的列名上 | 移除其表前缀（如 `o.status` -> `status`） |
| **`batch_qualify_identifiers`** | 用户选中了一段 SQL 文本或在多表查询作用域内触发 | 批量扫描并为选区内所有裸列名添加对应表的别名前缀，消除歧义 |

### 3.5 元数据悬停预览与代码导航 (Navigation & Go to Definition)

#### 3.5.1 表结构 DDL 悬停卡片 (Hover Table Preview)
- **需求描述**：鼠标悬停在 SQL 中的表名、视图名上方约 300ms 后弹出信息丰富的 Hover 浮层。
- **卡片内容**：
  - 目标对象的完整归属（Catalog / Database / Schema / Table）。
  - 对象类型（Base Table / View / Materialized View）。
  - 核心字段清单：字段名、数据类型（含长度/精度）、可空状态、是否主键/外键、默认值、字段注释。
  - **内置快速搜索框**：对于上百个字段的大表，用户可直接在悬停卡片顶部的搜索框输入关键字，即时过滤字段与 DDL。
  - 底部操作按钮：一键复制完整 DDL、在新标签页打开数据。

#### 3.5.2 链接式跳转 (Go to Definition)
- 按住 `Cmd / Ctrl` 并悬停在对象名上，该名称渲染为超链接下划线。
- **单击跳转行为**：
  - **物理表/视图**：直接在侧边栏或主工作区打开该表的结构设计器或数据网格。
  - **CTE 临时表 (`WITH x AS ...`)**：将光标直接定位并高亮到顶部对应 CTE 的声明行。
  - **存储过程 / 函数**：弹出例程源代码查看对话框。

#### 3.5.3 字段元数据侧抽屉 (Column Info Panel)
- 从右键菜单或状态栏可展开独立的字段元数据抽屉，展示当前查询涉及所有列的物理信息、注释及数据库专属类型说明（如 openGauss/GaussDB 专属类型转换展示）。

### 3.6 生产安全与执行控制 (Safety & Defensive Execution)

#### 3.6.1 高危 SQL 静态识别与拦截 (Danger Confirm Dialog)
- **风险等级评定**：
  - **Read（只读）**：`SELECT`、`SHOW`、`DESCRIBE`、`EXPLAIN` 等。
  - **Write（数据写入）**：`INSERT`、`UPDATE`、`DELETE`、`MERGE` 等。
  - **DDL（结构破坏）**：`DROP`、`TRUNCATE`、`ALTER` 等。
- **拦截策略**：
  - 当检测到带有写/DDL 操作，或包含无 `WHERE` 条件的 `UPDATE/DELETE` 时，系统拦截直接执行流程，弹出模态对话框。
  - 弹窗中提供语法高亮的代码摘要、影响表名及醒目的风险等级 Badge。
  - 针对特别高危操作（如删除整库、截断核心表），要求用户手动输入数据库名称或勾选确认框方可解锁执行。
  - 提供“本次会话记住选择”或白名单抑制选项。

#### 3.6.2 DML 变更前安全预览 (DML Change Preview)
- **需求描述**：执行复杂的更新或删除前，用户往往希望确认“到底会改动哪些数据”。
- **机制原理**：
  - 针对 `UPDATE / DELETE` 语句，前端根据语法提取目标表、`WHERE` 过滤条件与 `SET` 赋值表达式。
  - 自动将其转换为只读分析查询：例如对于 `UPDATE users SET role = 'admin' WHERE active = false`，后台构造查询原数据及衍生虚拟列（例如包含原 `role` 以及预期变更后的 `role_new`）。
  - 在结果集面板以 Diff 视图展示变更前后的数据比对，用户核对受影响行数及变更值无误后，再行正式提交。

#### 3.6.3 参数化执行绑定 (SqlParameterDialog)
- **多语法占位符兼容**：
  - 标准 JDBC 占位符 `?`
  - 命名参数 `:id`
  - SQL Server 变量 `@param`
  - Shell / 模板变量 `${tenant_id}`
  - MyBatis 映射 `#{user_name}` 与 `<foreach>`
- **交互要求**：
  - 点击执行含有参数的 SQL 时，自动识别参数列表并呼出参数配置对话框。
  - 支持字段类型选择（String、Number、Boolean、Null、Raw SQL 片段）。
  - **历史记录联想**：自动持久化每个参数名最后一次填写的数值，下次打开默认填充历史值，避免重复手工输入。
  - 对话框底部提供替换后的完整 SQL 实时高亮预览，并支持一键复制。

#### 3.6.4 跨多数据库批量分发 (MultiDbExecuteDialog)
- **需求描述**：DBA 或多租户平台管理员经常需要将相同的 DDL（加字段、建索引）或数据修复脚本同时应用到数十甚至上百个库。
- **功能点**：
  - **多目标选择树**：支持在同一数据源或多个兼容数据源间快速勾选目标 Connection / Database / Schema。
  - **目标分组管理 (Target Groups)**：支持将选中的库保存为常用分组（如“所有华东分库”、“测试环境集群”），支持增删改查。
  - **执行策略**：支持“串行执行（遇错即停）”与“并行执行（并发控制）”。
  - **实时进度监控与导出跟踪**：展示每个子库的执行耗时、状态（成功/失败/跳过/运行中）、受影响行数，支持一键取消排队中或运行中的任务。

### 3.7 交互增强与特色生产力工具

#### 3.7.1 拖拽插入与方言智能引号 (Smart Drag & Drop)
- 从左侧树状结构将数据库、数据表或具体字段拖拽进编辑器时：
  - 编辑器实时展示精确到字符间的插入指示光标线（Drop Caret）。
  - **方言智能引号 (Smart Quoting)**：
    - MySQL / ClickHouse / Doris 自动采用反引号 `` `table_name` ``。
    - PostgreSQL / openGauss 采用双引号 `"table_name"`（智能识别：纯小写合法标识符免加引号，混合大小写或含特殊符号加引号）。
    - SQL Server 采用方括号 `[table_name]`。
  - 多列拖入时支持指定分隔符格式（逗号空格分隔、单行分列或换行对齐）。

#### 3.7.2 剪贴板文本转 IN 条件过滤 (`sqlInListPaste`)
- 用户从外部文件或 Excel 复制了一长串 ID 或编码（换行分隔或制表符分隔）。
- 快捷键（如 `Mod + Shift + V`）或右键菜单触发“智能粘贴为 IN 条件”：
  - 系统自动解析文本，过滤空行与非法字符，自动推导数字或字符串字面量（加单引号并对内部单引号转义）。
  - 自动组装为 `IN ('item1', 'item2', 'item3')`，并贴心地检查光标前缀是否已有 `IN` 或 `NOT IN`，避免关键字重复。
- **高级分隔符列表对话框 (DelimitedListDialog)**：提供独立设置面板，用户可精细配置列分隔符、目标分隔符、前后缀包裹符号及换行阈值（如每 10 个元素换行）。

#### 3.7.3 高级查找与替换 (EditorSearchPanel)
- 浮动贴顶面板，支持快捷键 `Cmd/Ctrl + F`（查找）和 `Cmd/Ctrl + H`（替换）。
- 支持普通文本精确匹配、区分大小写（Match Case）、正则表达式（RegEx）。
- **选区内搜索 (In Selection)**：当用户先圈选了一段代码后再按搜索，自动将搜索限制在该代码段内。
- **性能平滑保障**：在大文档中采用 `requestIdleCallback` 切片异步统计匹配总数，并设立匹配上限保护（如超过 50,000 条终止计数），杜绝 UI 主线程卡死。

#### 3.7.4 格式化与单行压缩
- **多方言代码格式化**：集成 SQL Formatter 核心，支持配置关键字大小写（大写/小写/保留）、逻辑运算符换行位置（前置/后置）、Tabular 对齐排版。
- **SQL 文本压缩 (Compress SQL)**：一键去除所有多余注释、空白与换行，将多行 SQL 浓缩为单行，方便粘贴至业务代码常量或运维日志查询中。

#### 3.7.5 精美代码快照卡片 (CodeSnapshotDialog)
- 选中文本后右键“导出代码快照”：
  - 自动渲染为带有 Mac 风格窗口控制按钮（红黄绿小圆点）、优雅渐变背景、柔和阴影的卡片。
  - 支持调节字体、行号显示、内边距与背景主题色。
  - 支持一键复制图片到系统剪贴板或保存为 PNG 高清文件。

### 3.8 执行历史面板与回滚审计 (Query History)

- **十万级海量历史虚拟滚动**：使用虚拟列表组件保障海量历史记录流畅滚动秒级加载。
- **多维多属性筛选过滤**：
  - 按连接 / 数据库分类筛选。
  - 按时间范围过滤（支持快速选择“今日”、“近7天”、“自定义日期区间”）。
  - 按执行结果（全部、成功、失败）。
  - 按语句性质细分：常规查询、数据变更 (DML)、结构变更 (DDL)。
- **历史记录一键重放**：双击或点击回填按钮将历史 SQL 填入当前编辑器。
- **AI 辅助历史分析与反向回滚**：
  - 支持调用 AI 分析当时语句的报错原因。
  - 针对已成功执行的非事务 DML 语句，结合历史快照尝试智能生成反向逆操作 SQL（如将错误的 UPDATE 生成对应的恢复语句）。

### 3.9 深度 AI 助手集成 (AI Assistant)

#### 3.9.1 双模式运行机制
- **Ask 模式（面向单次指令任务）**：
  - **自然语言转 SQL (NL2SQL)**：根据自然语言描述自动生成满足当前数据库方言的高效查询。
  - **解释 SQL 与执行计划**：自动结合数据库 `EXPLAIN` 输出，剖析索引命中情况与慢查询瓶颈。
  - **SQL 调优建议**：对复杂子查询、隐式类型转换、全表扫描提出重构改写建议。
  - **错误快速修复**：执行报错时，在错误输出区一键点击“向 AI 提问”，自动将报错信息与原始 SQL 上下文送入 AI 诊断。
- **Agent 模式（面向自主分析工作流）**：
  - 具备 Tool Use 能力，可自主调用元数据查询、结构检查及受限查询工具，多轮交互回答复杂的业务数据分析问题。

#### 3.9.2 上下文挂载与生产防护
- **`@` 语法上下文注入**：输入框支持通过 `@table` 挂载表定义及样例数据，通过 `@sqlFile` 挂载已有脚本，支持直接拖拽 CSV/截图至输入框。
- **生产环境醒目感知**：若当前打开的连接被标记为“生产环境 (Production)”，AI 助手顶部常驻红色告警徽标，严格限制生成任何高危或破坏性变更建议。

  - 关键字（Keywords）
  - 字段名（Fields）
  - 函数名（Functions）
  - 字符串（Strings）
  - 数字字面量（Numbers）
  - 注释（Comments）

## 4. 非功能性需求 (NFRs)

### 4.1 性能与响应指标
- **输入平滑度**：万行长文本 SQL 文件中持续打字，输入响应延迟不超过 16ms（保持 60fps），无掉帧与输入法丢词现象。
- **自动补全弹出延迟**：键入触发补全到弹出建议列表，本地元数据命中时耗时不超过 50ms。
- **超长脚本保护**：单文件超过 2MB 或 20,000 行时，自动关闭行内内联提示（Inlay Hints）与复杂 AST 解析，确保基础光标操作与滚动绝对流畅。
- **历史记录滚动流畅**：在 50,000+ 条执行历史记录中，内存常驻合理，虚拟滚动无白屏与丢帧。

### 4.2 跨平台一致性
- 深度适配 macOS、Windows 及主流 Linux 发行版。
- 快捷键平台感知：macOS 采用 `Cmd` (`⌘`) 与 `Option` (`⌥`) 体系，Windows/Linux 采用 `Ctrl` 与 `Alt` 体系，解决国际化键盘（如 AltGr 键冲突）的兼容性问题。

### 4.3 安全与隐私
- **本地优先**：所有 SQL 语法树分析、意图操作、高危拦截、格式化均在本地客户端完成，不向任何第三方服务上报用户查询内容。
- **AI 隐私可控**：向 AI 助手发送元数据或数据采样时，严格遵循用户的配置项与脱敏开关，生产连接操作强制二次提示。

## 6. 验收标准与成功度量指标

### 6.1 核心功能验收矩阵
1. **语句感知**：任意包含复杂注释、分号的 SQL 脚本，光标所在行能够准确框选出对应语句范围，行号栏图标单击仅执行该条语句。
2. **高危拦截**：输入 `DELETE FROM users;` 并点击运行，必须被拦截并弹出风险提示对话框，无法直接静默执行。
3. **参数化执行**：含有 `:userId` 的语句执行时准确弹出填值框，再次打开时能准确记忆上次填写的内容。
4. **智能补全**：在具有外键关系的库表中输入 `JOIN`，首屏推荐必须包含关联表名及精确匹配的 `ON` 字段关联条件。
5. **Alt+Enter 意图**：光标置于 `SELECT *` 时触发意图操作，展开后的字段列表必须包含该表所有列且符合当前连接的保留字引号规范。
6. **剪贴板转 IN**：从外部复制 1000 行字符串，使用转 IN 功能粘贴，能秒级转换为合法的 `IN ('...', '...')` 片段，且内部单引号完成正确转义。

### 6.2 质量与健康指标
- **单元测试覆盖**：SQL 词法分词器、语义模型、参数解析器、转 IN 工具函数的单测覆盖率达到 90% 以上。
- **性能基准**：加载 5,000 行复杂 SQL 脚本，首次渲染完成时间 `< 100ms`，内存增量小于 `30MB`。
- **零严重缺陷**：生产环境下无未经用户确认的非幂等写操作执行漏洞。
