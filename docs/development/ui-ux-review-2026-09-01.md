# DataZen UI/UX 审查（2026-09-01）

## 结论摘要

DataZen 已经形成了清晰的深色数据库工作台骨架：连接树、面板 Tab、SQL 编辑器、结果表格、图表、工作流、看板和扩展管理彼此可用，视觉上也有统一的 slate/blue 方向。当前最大的体验成本不是“缺功能”，而是三个连续性问题：

1. 没有选中连接或面板时，主区域是大面积空白，下一步不够明确。
2. 40px 图标侧栏、密集工具栏和大量图标按钮依赖 hover/title 才能理解，首次使用和无障碍体验偏弱。
3. 主题 token 尚未覆盖所有视觉值；不少页面仍直接写死 `blue/red/green` 或十六进制颜色，主题插件无法完整改变应用观感。

## 审查范围与证据

- 运行方式：项目现有 WebdriverIO runner，使用 `pnpm e2e:screenshot -- --spec e2e/specs/zz-screenshots.ts` 生成视觉状态。
- 截图目录：[`e2e/screenshots/uiux-review/`](../../e2e/screenshots/uiux-review/)。
- 主窗口回归：`e2e/specs/main-window.ts`，8/8 通过并生成连接树折叠状态截图。
- 视觉脚本：成功产出欢迎页、连接管理、连接对话框、SQL/结果/图表、ER、工作流、看板、插件、备份、Redis、数据同步、结构对比、数据传输等 30 张图。
- 视觉脚本有 3 个可复现的流程漂移：`07-ai-chat` 找不到 AI 输入、`23-table-structure` 找不到“打开结构”、`18-data-editor` 找不到首行可编辑单元格。脚本仍会继续产出其它页面截图，建议将这三项纳入下一轮 E2E/信息架构回归。

## 按优先级的建议

### P0：数据安全与当前状态必须一眼可见

**P0-1 统一写操作的“影响 → 预览 → 提交”路径。**

数据同步/传输截图中 Insert、Update、Delete 是同一排复选项；查询面板又用绿色执行按钮和琥珀色 Safe 状态提示。建议所有写操作采用同一套视觉协议：

- 执行按钮显示动作和影响范围，例如“预览 12 条 / 提交 12 条”；
- Delete 默认关闭，并在开启后显示红色影响摘要、目标连接和不可逆提示；
- 提交前固定提供 SQL/变更预览、Rollback/Cancel，完成后显示影响行数和可复制审计信息；
- 把“Safe mode、Auto commit、Read-only”从设置页同步为当前面板的明确状态标签。

**P0-2 连接/查询状态不能只靠颜色。**

连接树使用绿/黄/红圆点，结果和图表也大量依赖颜色。建议所有状态同时提供文字或图标（Connecting、Connected、Failed、Read-only），并保证色盲可区分；错误状态提供“重试、复制错误、查看日志”三个明确动作。

### P1：缩短定位路径、降低认知负担

**P1-1 空白工作区改成上下文首页。**

[`01-main-window.png`](../../e2e/screenshots/uiux-review/01-main-window.png) 显示连接分组折叠后，右侧几乎完全空白，只保留“请在左侧选择一个连接”。建议根据状态展示：最近连接/最近面板、创建连接、导入连接、快捷键提示，以及连接失败时的重试卡片。空状态应是“下一步”而不是纯占位文本。

**P1-2 40px 图标侧栏增加可发现性。**

主窗口侧栏目前只显示图标，`WorkspaceModeButton` 主要依赖 `title`。建议提供“图标 + 文案”的可展开模式（记住用户选择），至少补充 `aria-label`、键盘焦点样式和显式 tooltip；在 1024px/小窗口自动折叠，并保留快捷键提示。

**P1-3 记住侧栏布局。**

连接导航的宽度和折叠状态在 [`ConnectionPage.tsx`](../../src/windows/connection/ConnectionPage.tsx) 中是组件本地 state，刷新后会回到默认值。建议把宽度/折叠状态持久化，并为连接树、结果区、图表配置区提供统一拖拽手柄和可恢复默认值。

**P1-4 收敛工具栏层级。**

[`17-sql-editor.png`](../../e2e/screenshots/uiux-review/17-sql-editor.png) 可见“新建查询/新建表/ER/例程/权限/导出”与多个图标按钮同时出现。建议保留 1 个主动作（执行/新建查询），将连接级动作归入“对象操作”或“更多”，每组动作加分隔和可读 tooltip；在窄窗口只保留主动作。

**P1-5 表格与图表建立稳定的工作区比例。**

[`02-query-chart.png`](../../e2e/screenshots/uiux-review/02-query-chart.png) 中结果表、图表配置和图表本体同时争夺垂直空间。建议保存用户的分割比例，提供“一键最大化结果/图表”，并在列名、轴名被截断时显示完整值；图例、网格、数据类型色应统一走主题 token。

**P1-6 看板空卡片更像可操作入口。**

[`21-dashboard.png`](../../e2e/screenshots/uiux-review/21-dashboard.png) 的“添加报表”虚线卡片占据很大面积，卡片顶部操作主要是图标。建议把添加入口改为按钮组（新建查询 / 选择已有工作流 / 导入），对刷新、历史、全屏、删除提供 tooltip 和确认；空看板同时显示推荐模板。

**P1-7 设置页提供搜索和粘性保存。**

[`20-security.png`](../../e2e/screenshots/uiux-review/20-security.png) 显示左侧设置导航和中间窄表单在大屏上留下大量空白，保存按钮固定在窗口最底部。建议增加“搜索设置”、按风险分组（安全/连接/编辑器/AI）、dirty 状态提示和 sticky save bar；离开有未保存修改时给出明确选择。

**P1-8 多步骤窗口强化步骤摘要。**

数据同步、结构对比、数据传输已经有可读的 stepper 和底部 Back/Next，但内容区仍有大量空白，用户不易判断下一步需要什么。建议在 stepper 下增加“源 → 目标、数据库、对象数、危险选项”摘要，并在 Next 被禁用时就地说明缺少的条件；执行阶段展示可取消、可重试和已完成行数。

**P1-9 Redis 数据库选择应从长列表中解耦。**

[`15-redis.png`](../../e2e/screenshots/uiux-review/15-redis.png) 左侧 `db0`–`db15` 列表占据连接树高度。建议使用可搜索的逻辑库选择器或分组折叠，批量操作栏在未选择行时保持禁用并解释原因；视图切换时自动关闭悬浮菜单，避免菜单遮挡表格。

**P1-10 修复三处视觉脚本漂移。**

AI 对话、结构入口和表格编辑的选择器/入口与当前界面不一致。除了修正选择器，还应确认真实用户路径是否仍然需要多次右键或隐藏入口；优先给“打开结构”和“编辑单元格”增加稳定的可见按钮/快捷键。

### P2：一致性、可访问性与长期维护

**P2-1 完成主题 token 化。**

主题扩展只覆盖 `--c-*`、`--cm-*`、`--dt-*`，但源码仍有大量 `text-blue-400`、`bg-red-500`、`text-green-400`，且 [`ErDiagramView.tsx`](../../src/windows/connection/ErDiagramView.tsx) 直接使用 `#1a1a2e`。建议定义 `--c-focus`、`--c-danger-bg`、`--c-warning-bg`、`--c-icon-*`、`--chart-*` 等语义 token，逐步替换硬编码类名；扩展主题才会真正影响全应用。

新主题如果只提供暗色模式，设置页应明确显示“仅暗色”，并在浅色/跟随系统为浅色时禁用或自动切回宿主主题，避免出现暗色面板与浅色文字混搭。主题边框采用低对比 slate 时，关键焦点仍应使用高对比 accent，而不能只依赖边框颜色。

**P2-2 统一控件尺寸和焦点状态。**

按钮、输入框、图标按钮在连接、设置、工作流、Redis 页面存在不同高度/内边距。建议建立 28/32/36px 三档控件规范，所有交互元素有 2px 以上可见 focus ring，拖拽手柄和图标按钮提供键盘替代。

**P2-3 文案、日期和数字格式按 locale 统一。**

视觉脚本会切换中英文来捕获隐藏窗口；生产路径应确保所有独立窗口读取同一语言设置，并统一数据库类型、时间戳、行数、字节数的格式。对于“无数据/暂无结果/加载失败/权限不足”使用不同文案，避免同一个空状态承担多个含义。

**P2-4 插件管理页补充安装后的引导。**

[`22-plugins.png`](../../e2e/screenshots/uiux-review/22-plugins.png) 的空状态和筛选结构清楚。安装成功后建议直接显示“启用、打开工作区、切换主题”的下一步，并在主题卡片展示 light/dark 模式、预览色板和权限（纯主题应明确显示“无需权限”）。

## 建议的落地顺序

1. 先做 P0 的写操作状态协议和连接状态文字化，降低数据风险。
2. 接着做 P1-1/2/3/4：空状态、导航可发现性、布局持久化和工具栏收敛，收益覆盖所有页面。
3. 再将 P1-5/6/7/8 的分割比例、看板空态和多步骤摘要抽成复用组件。
4. 最后执行 P2 token 化与无障碍/本地化收口，让主题插件和未来扩展真正共享一套视觉系统。
