# DataZen 迁移到 Rune 的任务

目标：用 `crates/datazen-ui` 做出同一套产品界面，桌面和 Web 都能跑。Core、Driver、Server、权限和扩展沙箱不重写。

React 同时保留。`packages/frontend` 里的页面和组件一律不删、不改成空壳、不把入口从 React 摘掉。Rune 是另一条界面。要加入口时单独开任务，只新增，不动现有组件的行为。本计划没有“下线 React”这一步。

## 怎么拆

一个任务最多一天。超过就先拆开再做。一个提交只做一个任务。任务之间不顺手夹带。

每个任务结束时要有：改了哪些 Rune 或端口文件、一条能跑的测试或一条人工点选路径、`progress.md` 里标成完成。不要求 Tester，除非另开要求。

## 不变量

1. Rune UI 只依赖 `datazen-ui-api`。不依赖 Tauri、Axum、React 或某个 Driver。
2. 桌面 Host 和 Web Host 调用现有 application use case。禁止在 Rune Host 里再写一套连接、Runtime 或驱动注册。
3. 异步结果带请求代次。断开连接或关掉面板后，过期响应不能写进新状态。
4. 选择、脏数据和编辑器放在模型里，不放在会被虚拟化拆掉的行节点上。
5. Web 没有第二窗口、系统菜单、文件对话框和 WebGL 退路。这些交互在 Rune 里做面板；React 里的原窗口留着。
6. WAPP 的 iframe 不放进 Canvas。React 插件不嵌进 Rune。
7. 主 SQL Editor 和主 DataTable 的验收没过之前，React 里的 CodeMirror 和 DataTable 继续是正式界面。

## 表数据

端口仍先用内存。桌面适配另开任务，不和这些混在一天。

| 任务 | 一天内做完的事 | 完成标准 |
|---|---|---|
| B1 | `open_table` 接受页码和页大小，内存只返回那一页 | 测：第 2 页不是第 1 页的行 |
| B2 | 网格页脚：上一页、下一页、页大小 | 翻页后列窗口和冻结列还在 |
| B3 | 一个排序列，表头点击轮换无序、升序、降序 | 内存排序，测一行顺序 |
| B4 | 一个文本过滤，作用在单个列，过滤后回到第 1 页 | 测：过滤掉的行不在页里 |
| B5 | 脏标记和显示值分开。状态栏只数脏格 | 改一格再改回原值，脏数为 0 |
| B6 | 端口增加提交和撤销。两个按钮 | 提交后重开表仍是新值；撤销回到原值 |
| B7 | 页上带只读原因。有原因时不能编辑 | 测：只读页提交被拒绝 |
| B8 | 结果页和表页用同一个网格组件，结果页不能暂存 | 测：结果页调用暂存返回错误 |
