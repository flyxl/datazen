# BUG-009 T11 记忆注入的 bidi/格式字符清理与 token 预算失效

- 关联任务：T11 Memory 领域、检索、注入
- 初始被测提交：`51c246027`
- 修复提交：`0eba724de`（`fix: harden memory bidi filtering and token budget`）
- 严重度：已关闭（原阻塞 T11 验收）
- 状态：已验证（`0eba724de`）

## 初始缺陷

1. **bidi/格式清理不完整**：`is_hidden_format_char` 只覆盖 U+200B-200F、202A-E、2060-2069、FEFF；U+061C ALM、U+206A-F deprecated bidi、U+2028/2029 等会进入注入块。现有测试只用 U+202E。
2. **token 低估**：`estimate_tokens` 把非 CJK Unicode 也按 ASCII 0.3 token/字符计算，与注释“其他 Unicode ~1 token/字符”矛盾；emoji 注入块可声称 1500 tokens 但实际约 18KB/4,400+ 字符。原预算测试复用同一估算器，无法发现。

## 修复验证（`0eba724de`）

### 范围

2 文件：`crates/datazen/src/ai/domain/budget.rs`、`crates/datazen/src/ai/memory/injector.rs`；均为 T11 修复/测试，无无关/generated。

### bidi/格式字符

`sanitize_memory_text` 的 `is_hidden_format_char` 现覆盖：

```text
U+061C, U+180E
U+200B..U+200F
U+2028..U+202E
U+2060..U+206F
U+FEFF, U+FFF9..U+FFFB
U+E0000..U+E007F
```

独立探针把全部 16 个要求字符（ALM、206E、2028、200B、200E/F、2029、202A/E、2066/69/6F、FEFF、FFF9、E0041）放进同一条内容，注入块只剩 `XXXXXXXXXXXXXXX`，无任一字符泄漏；原 U+202E 测试保留并通过。

**测试质量备注（非阻塞）**：coder 新增的循环测试只把 061C/206E/2028/2029/200B/E0041 六项真正拼进 content，其余 10 项是空断言；我的独立 all-in-one 探针补上了这个验证，结果通过。

### token 预算

`estimate_tokens` 改为分档保守估算：

- ASCII：`ceil(chars * 0.3)`；
- CJK：`ceil(chars * 1.6)`；
- 其他非 ASCII：`chars * 2`；
- 全部饱和相加。

`MemoryInjector::default()` 仍是 8 条 / **1500**；`HARD_MEMORY_TOKEN_BUDGET=2000` 只经 `MemoryInjector::new(..., 2000)` opt-in（PRD 动态硬上限），不是默认路径。

独立探针（不调用生产 `estimate_tokens` 做断言）：

```text
BIDI_PROBE_TEXT=<memory> ... XXXXXXXXXXXXXXX ... </memory>
EMOJI_BUDGET entries=1 estimate=1499 chars=1003 bytes=3118
```

8×1000 emoji 候选下：块 ≤1500（production estimate 1499）、字符 1003≤1200、字节 3118≤5000；Cyrillic/Arabic 混合测试同样通过。测试中的 `conservative_tokens`（ASCII ceil 0.3 + 每个 non-ASCII 2）是独立度量，不再自证。

### 路径检查

- `MemoryInjector::default()`：max 8 / 1500，严格不超。
- `MemoryInjector::new(8, 0)`：空块；`new(8, 1500)`：1500。
- `MemoryInjector::new(..., 2000)`：仅 opt-in，用户已确认 2000 是硬上限路径；不是默认，也没有其他默认路径能超 1500。
- `new(20, 99_999)` 被 clamp 到 8/2000；默认构造不可变。
