- 关联任务：T11 Memory 领域、检索、注入

- 严重度：阻塞 T11 验收

## 发现 1：bidi/格式控制字符未被完整清理

`injector.rs:359-367` 的 `is_hidden_format_char` 只覆盖：

```text
U+200B..200F
U+202A..202E
U+2060..2069
U+FEFF
```

T11 验收要求“控制字符/bidi 清理”。实际注入中以下字符仍原样保留：

- **U+061C ARABIC LETTER MARK（ALM，标准 bidi 控制符）**
- **U+206A..U+206F deprecated bidi formatting controls**（如 U+206E NATIONAL DIGIT SHAPES）
- **U+2028/U+2029 LINE/PARAGRAPH SEPARATOR**（不是 bidi，但属于可破坏单行边界的格式字符）

临时探针（已还原，未改生产代码）：

```rust
let content = "ALM:\u{061C} DEPRECATED:\u{206E} LINE:\u{2028} end";
let injection = MemoryInjector::default().inject(&[scored("bidi", content)], &MemoryInjectionPolicy::local());
```

实际输出：

```text
- [M1][preference][table:public.orders][confidence=0.50]
  ALM:\u{61c} DEPRECATED:\u{206e} LINE:\u{2028} end
```

现有唯一的 bidi 测试 `html_is_escaped_and_control_chars_removed` 只用了 `\u{202E}`，没有覆盖 ALM/206A-F/行分隔符，因此 happy path 通过但验收不完整。

**期望**：清理所有常见 bidi/format controls（至少补 U+061C、U+206A..206F、U+2028/U+2029，建议同时覆盖 U+180E、U+FFF9..FFFB 和 tag controls），并加入对应断言。

## 发现 2：token 估算对非 CJK Unicode 严重低估，1500 预算可被突破

`crates/datazen/src/ai/domain/budget.rs:55-77` 的估算器把“其他 Unicode”也累加到 `ascii_count`，按 **0.3 token/字符** 计算；但同文件注释写的是“Other unicode: treat as ~1 token per character”。T11 的 `MemoryInjector` 直接使用该估算器做 1500 预算，因此 emoji/Cyrillic/Arabic 等非 CJK 文本会被严重低估。

临时探针（已还原）：

```rust
let entries: Vec<_> = (0..8)
    .map(|i| scored(&format!("u{i}"), "🙂".repeat(1000)))
    .collect();
let injection = MemoryInjector::default().inject(&entries, &MemoryInjectionPolicy::local());
```

实际：

```text
PROBE_UNICODE_ENTRIES=5 TOKENS=1500 BYTES=18422
```

即注入块声称 `token_estimate=1500`，但实际文本 18,422 bytes、约 4,400 个 emoji/Unicode 字符；按该文件注释的“其他 Unicode ~1 token/字符”也远超 1500，按常见 tokenizer 同样会超出。现有 `total_block_stays_within_1500_tokens` 用同一个 `estimate_tokens` 断言，等于自证，无法发现低估。

`MemoryInjector::new(8, 2_000)` 还允许配置到 2000；PRD 有“硬上限 2,000”的动态说明，但 T11 验收写的是 1500 上限，至少默认路径必须严格 ≤1500。

**期望**：修正非 CJK Unicode 估算或采用更保守上限；注入测试用独立字符/字节/保守 token 度量验证，而不是只复用被测估算器；补 emoji/Cyrillic/阿拉伯文用例。
