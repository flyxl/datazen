# BUG-004 T06 前端未采集编辑器选区，autoContext.selection 没有真实消费者

- 关联任务：T06 自动上下文快照
- 首次被测提交：`4376b519e2567eb1443d1930328376eaa4bef91f`
- 修复提交：`27e1f7708f14322bcee949d0d701ddba2651ebdf`
- 严重度：阻塞 T06 验收（实现文档要求“编辑器 SQL、选区”，选区在真实 UI 中缺失）
- 状态：已验证（`27e1f7708`）

## 现象

T06 的实现文档明确要求 Chat 自动带上“编辑器 SQL、选区、最近错误、结果预览”。后端和 IPC 都有 `selection` 字段，`AiChatPanel` 也有选区 chip 的渲染分支，但唯一的生产 `autoContext` 生产者 `ContentViewDrawers.tsx` 构造快照时只放了 `editorSql`、`lastError`、`resultPreview`，没有 `selection`：

```tsx
// packages/frontend/src/windows/connection/ContentViewDrawers.tsx:186-190
const snapshot: AiChatContextSnapshot = {
  editorSql: editorSql || undefined,
  lastError: activeQueryExec.error || undefined,
  resultPreview,
};
```

前端没有任何生产代码从 SQL 编辑器读取当前选区并写入 `AiChatContextSnapshot.selection`。全仓搜索 `selection:` 在 `packages/frontend/src` 下的非测试结果，只有 `aiStore.ts` 的转发读取：

```ts
// packages/frontend/src/stores/aiStore.ts:490
selection: autoContext?.selection,
```

`AiChatPanel` 能显示 `chat.autoContext.selection` chip（`AiChatPanel.tsx:623-628`），但真实宿主从不传入该字段，因此这个 chip 对用户不可达。后端 `[Editor selection]` 拼装和 `chat_session_tests` 的选区单测都通过，但没有任何真实前端消费者，不能据此判定 T06 的选区验收通过。

## 复现

1. 打开 Query 面板，在 SQL 编辑器中输入 `SELECT * FROM users WHERE id = 1`，选中其中一段 SQL。
2. 打开 AI Chat 面板。
3. 观察自动上下文 chips：会出现 SQL / 错误 / 结果预览，但不会出现“选区 / selection”chip。
4. 发送消息；检查最终 user prompt：没有 `[Editor selection]` 段，`ai_chat` 的 `selection` 实际为 `None`。
5. 在 `ContentViewDrawers.tsx` 中修改编辑器选区并重渲染，选区也不会进入 `autoContext`。

## 期望

- 当前 SQL 编辑器有选区时，`autoContext` 包含 `selection`，前端显示可移除的选区 chip。
- 发送时把该选区冻结进 `ai_chat.selection`；后端 prompt 出现 `[Editor selection]`，顺序在 `[Current SQL]` 之后、错误之前。
- 选区与当前 SQL 相同或已被 `@` 文件/用户消息包含时按现有去重规则不重复。
- 选区为空时不产生空块/chip。
- 已有 `QueryEditorSection` 的 `editorRef.current?.getSelection()` 可作为真实来源，但当前只用于右键菜单的执行选区，没有接入自动上下文。

## 实际（4376b519e，修复前）

## 验证（27e1f7708）

复测通过，选区已从真实编辑器贯通到 provider prompt：

- **编辑器 → 更新监听**：`SqlEditor.tsx:70,106-107,508-512` 把 `onSelectionChange` 放入 ref 并交给 `createUpdateListener`；`editorExtensions.ts:743-745` 在 `docChanged || selectionSet` 时用 `update.state.sliceDoc(selected.from, selected.to)` 上报。`editorExtensions.test.ts` 用真实 CodeMirror dispatch 选中 `SELECT 1`，回调收到 `SELECT 1`；折叠选区收到空串。
- **QueryEditorSection → QueryPanel**：`QueryEditorSection.tsx:57,655-661` 透传 prop；`QueryPanel.tsx:127-132,752` 以 `panelId` 写入 `editorSelectionStore`，并在卸载时 `clearEditorSelection(panelId)`。
- **ContentViewDrawers → autoContext**：`ContentViewDrawers.tsx:155-157` 订阅当前 query panel 的选区，`:190-198` 写入 `selection: activeEditorSelection.trim() || undefined`，并把 `activeEditorSelection` 加入 memo 依赖；`ContentViewDrawers.autoContext.test.tsx` 预置带首尾空格的选区，断言传给 `AiChatPanel` 的 `data-auto-selection` 为 `WHERE id = 1`。
- **chip / 发送冻结**：`AiChatPanel.tsx:119-123,623-628` 同步/移除选区 chip，`:279` 只在快照有内容时附带 `autoContext`；`AiChatPanel.test.tsx` 新增“显示、移除、发送选区”测试；提交内的发送冻结/重渲染不复活用例以 SQL 字段覆盖同类逻辑，本次复测另以 selection 专项临时用例确认。
- **ai_chat → prompt**：`aiStore.ts:490` 转发 `selection`；desktop `chat.rs:91,182` 接收并构造 `ChatSessionInput`；`mock_provider_tests.rs:327,347-351` 以 `selection: Some("WHERE id=1")` 断言最终 user prompt 含 `[Editor selection]\nWHERE id=1`。
- **清理/隔离**：`editorSelectionStore.test.ts` 验证不同 panel 的选区互不覆盖、空选区删除、`clearSelection` 只清指定 panel；`QueryPanel` 卸载 cleanup 已接。空选区由 `setSelection` 删除 key，不会产生空 chip/空块。
