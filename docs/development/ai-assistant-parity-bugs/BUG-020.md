# BUG-020 T22 插件模板参数未转义：审批 SQL 泄漏凭据，且 SQL 字面量可被参数改变

- 关联任务：T22 插件/Workflow 工具桥
- 被测提交：`fc97c8647`（`feat: bridge opted-in plugin and workflow tools`），父 `2366d6dbc`
- 复测时间：2026-11-06
- 严重度：阻塞 T22。安全边界问题，不是测试环境问题。
- 状态：待修复

## 结论

T22 的 opt-in、运行时 disable、命名、schema 校验、只读直跑、非只读审批、Stop、
64 KiB 截断、结果 gate 脱敏和审计主路径均通过；但插件 `input` 模板参数是**原始字符串
直接替换**，没有转义，也没有在审批 SQL 预览前用脱敏后的参数重渲染。

这产生两个可复现问题：

1. 插件模板把凭据参数放进 SQL 时，`McpApprovalRequest.sql` 原样包含密码；审批事件
   泄漏凭据（`arguments` 本身虽已脱敏）。
2. SQL 模板中的字符串参数含单引号时可改变 SQL；例如 `O'Brien` 被渲染成未转义的
   `O'Brien`，而不是 `O''Brien`。只读插件可在无审批的情况下改变查询条件；非只读
   插件在审批后会执行被改变/注入的 SQL。

## 复现 1：审批 SQL 泄漏凭据

临时最小插件 fixture 声明非只读工具：

```json
{
  "name": "delete_by_password",
  "readOnly": false,
  "command": "execute",
  "input": { "sql": "SELECT '{{password}}'" }
}
```

调用：

```text
authorize_bridge_tool_with_port(..., r#"{"password":"hunter2"}"#, ...)
```

实际：

```text
requests[0].arguments["password"] == "[REDACTED]"
requests[0].sql == Some("SELECT 'hunter2'")
```

`arguments` 已脱敏，但 `sql` 未脱敏，审批载荷泄漏了明文密码。根因是
`crates/datazen-desktop/src/commands/ai/bridge.rs:264` 先用原始参数渲染
`preview_args.sql`，再交给 `approval_preview`；后者的凭据规则只能识别带
`password=`/`token=` 等键名的文本，无法知道模板中裸替换的凭据值。

## 复现 2：模板参数未转义

直接调用 `render_input_template`：

```text
template = {"sql": "SELECT * FROM users WHERE name = '{{name}}'"}
args     = {"name": "O'Brien"}
```

实际：

```text
SELECT * FROM users WHERE name = 'O'Brien'
```

期望（SQL 字面量转义，或改用安全的绑定参数）：

```text
SELECT * FROM users WHERE name = 'O''Brien'
```

当前 `crates/datazen/src/ai/application/tool_bridge.rs` 的
`display_argument`/`render_value` 把参数值直接写入模板，没有 SQL 字面量转义。
把参数改成 `x' OR '1'='1` 会改变 `WHERE` 语义；只读插件因此可以读到模板作者未预期的
行，非只读插件会执行被改写的 SQL。

## 影响

- 审批 UI/事件不满足“审批载荷不泄漏凭据”。
- 模型可控制插件 SQL 模板中的字符串，突破模板作者固定的 WHERE 条件；这是 T22
  “模板参数转义”验收项未实现。
- 结果 gate 只处理执行后的结果，无法修复审批载荷或执行前的 SQL 注入。
