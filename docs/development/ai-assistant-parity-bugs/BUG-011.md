## 初始缺陷

1. `MemorySection.tsx` 在云策略、连接、类型、状态四处使用原生 `<select>`，违反仓库既有 `noNativeSelect` 规则；全量 Vitest 因此新增失败。
2. 默认 `memory.enabled=false` 时，`Chat` 的“记住这条”在前端被拦截，但 `ai_memory_create` 仍能直接写入 candidate，和“关闭后不产生候选 / 关闭时 create candidate 被拒绝”的验收要求不一致。

### 关闭记忆时创建

`crates/datazen-desktop/src/commands/ai/memory.rs:491` 的 `ai_memory_create` 现在先读取 `resolve_memory_settings`，`enabled=false` 时直接返回 `CommandError::Validation("memory is disabled; ...")`，不会进入写入/审计路径。

独立临时探针（已还原，不在提交中）覆盖 `status=None/Active/Candidate`：关闭状态下三种新建都返回 Err 且 `list_all() == 0`；随后 `enable_memory`，同一路径创建 active 成功且 `list_all() == 1`。结果通过。

旧测试没有被削弱：所有依赖创建的既有 Rust 用例只增加了 `enable_memory(&app).await` 前置条件，原有创建/更新/拒绝/确认/删除/导出/作用域/secret 拒绝断言全部保留；`chat_auto_is_forced_off_when_memory_setting_is_disabled` 改为先 enable 创建种子、再 disable 后验证不注入。新增的 `memory_create_is_rejected_while_settings_are_disabled` 同时断言关闭时 Err、不落库、开启后 candidate 正常创建。
