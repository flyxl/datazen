## 初始缺陷

1. **notes 在 DB comment 后**：`build_system_prompt` 先追加 schema suffix（含 DB COMMENT），再追加 `User connection notes`，违反 T10“笔记优先于 DB comment（并列显示并标注用户笔记）”；原测试只有 `schema: None`，没有真实 comment 顺序覆盖。
2. **模板无匹配仍注入**：`select_prompt_template` 在无显式 id、无 databaseType 匹配、无 generic default 后仍 `.or_else(|| defaults.first().copied())`，会把 MySQL default 注入 PostgreSQL 请求，违反“无匹配不注入”。

## 修复验证（`1a9c438dd`）

### 范围

3 文件全部 T10 修复/测试：`chat_injection.rs`、`chat_request.rs`、`types.rs`；无无关/generated 文件。

### 注入顺序

`build_system_prompt` 现为：safety/system > global instructions > selected template > **connection notes** > schema suffix（含 DB COMMENT）> 用户消息。notes guidance 改为 `take precedence over any database COMMENT`，同时要求两边都保留、标注为用户笔记。

新增 `connection_notes_precede_schema_comments_while_both_stay_visible`：使用 `pinned_schema_ddl` 中真实 `COMMENT 'OLD_COMMENT_MARKER'`，断言 `NOTES_MARKER` 在 `OLD_COMMENT_MARKER` 前、`User notes (connection)` 在 comment 前、且 `Keep both visible side by side` 存在；通过。

### 模板选择

`select_prompt_template` 删除了 `defaults.first()` 兜底：显式 id → databaseType 匹配 default → generic default（空 `databaseTypes`）→ 否则 `None`。

- `non_matching_database_default_is_not_injected_without_a_generic_default`：只有 mysql default 时，PostgreSQL/None 均 None，mysql 正常选中；通过。
- `generic_default_still_covers_an_unmatched_or_absent_database_type`：generic default 仍覆盖未知/缺失 databaseType；通过。
- 既有显式 id 优先、databaseType 匹配测试保留并通过。

### Typecheck 环境说明

默认 `pnpm typecheck:tsc` 在这个 worktree 仍可能因 `node_modules` 软链到主检出而把 `@datazen/backend-client` 解析到主检出旧的 `LegacyCommandName`。本次用临时 tsconfig 将 `@datazen/backend-client` 映射到本 worktree 后 `tsc` exit 0；临时文件已删除，worktree 与主检出均 clean。这不是 T10 源码类型错误。
