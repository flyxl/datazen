# BUG-008 T10 笔记优先级与无匹配模板选择

- 关联任务：T10 连接笔记、全局指令、Prompt 模板
- 被测提交：`cd17aab8b003e6861b8202d9b1e4a79dc0d80bf9`
- 严重度：阻塞 T10 验收
- 状态：未修复

## 发现 1：连接笔记排在 DB comment 之后，违反“笔记优先”

T10 验收要求“笔记优先于 DB comment（并列显示并标注用户笔记）”，PRD §7.6 还要求连接笔记作为 schema 上下文的一部分、不单独作为 system instruction，冲突时并列显示并标注“用户笔记”。

当前 `build_system_prompt` 的顺序是：

```text
safety/system prompt
→ global instructions
→ selected template
→ schema suffix（可能包含 DB COMMENT）
→ connection notes（独立 system 块）
→ user message
```

对应 `crates/datazen/src/ai/application/chat_request.rs:199-214`：先 `prompt.push_str(&schema_suffix)`，再 push `User connection notes`。代码自己的注释也写 `schema (including DB comments), connection notes`，明确把 notes 放在 comment 后。guidance 还是“do not silently override the schema comment”，效果更接近 comment 优先，而不是验收要求的 notes 优先。笔记也没有进入 schema 注入块，缺少真正的并列/用户笔记标注。

现有 `user_prompt_material_is_injected_in_priority_order_and_redacted` 只测 `schema: None`，只验证 global < template < notes，未覆盖 schema/DB comment 与 notes 的相对顺序，因此没有钉住验收要求。

**期望**：有 schema/DB comment 时，notes 应先于 comment 注入（或进入 schema 块并明确 `User notes` 优先/并列标注），并补有 comment 的顺序测试。

## 发现 2：无匹配模板时仍回退注入第一个 default

`AiSettingsConfig::select_prompt_template` 在显式 id、databaseType 匹配、generic default 都失败后，仍执行：

```rust
defaults
    .iter()
    .copied()
    .find(|template| template.database_types.is_empty())
    .or_else(|| defaults.first().copied())
```

`crates/datazen/src/ai/domain/types.rs:319-323`。因此只有 `databaseTypes: ["mysql"]` 的 default 时，`database_type=postgresql` 仍会注入 MySQL 模板；`database_type=None` 也会注入非 generic 的第一个 default。

这直接违反本次验收的“无匹配不注入”。

临时测试（已还原，未修改生产代码）：

```rust
settings.prompt_templates = vec![template("mysql-only", &["mysql"], true)];
assert!(settings.select_prompt_template(None, Some("postgresql")).is_none());
assert!(settings.select_prompt_template(None, None).is_none());
```

实际：

```
test ai::application::chat_injection::tests::tester_non_matching_database_default_is_not_injected ... FAILED
panicked at .../chat_injection.rs:167
```

## 影响

- T10 的注入优先级验收不成立；模型可能先读 DB comment，再读用户笔记，和“笔记优先”相反。
- 数据库类型不匹配时会把错误的行业务模板注入请求，属于功能性错误。
- 这两项都不是环境/基线失败。
