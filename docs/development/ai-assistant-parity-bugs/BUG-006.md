# BUG-006 T08 RequireConfirm 无桌面确认 UI，宿主固定拒绝，策略无法真正生效

- 关联任务：T08 安全开关真正生效
- 首次被测提交：`6c5ed3828fefee6b641a13d075f2c34b0d62bb5d`
- 修复提交：`bd08f57fdb999019d4c336b007decfb044ddc02a`（实际 HEAD 为同内容的 `5ebc5bc6c`，仅 `chat.rs` timeout future 包裹一行差异）
- 严重度：阻塞 T08 验收（RequireConfirm 无法接受一次调用；require_sql_confirm 同样只能拒绝）
- 状态：已验证（`5ebc5bc6c`）

## 现象

T08 的 `RequireConfirm` 依赖 `AiToolLoopHost::confirm_tool_call`。端口在共享层默认 fail-closed（返回 `false`）是合理的；但桌面宿主 `AppState` 直接固定返回 `false`，注释明确写着 T24 才接 UI：

```rust
// crates/datazen-desktop/src/commands/ai/chat.rs:71-80
async fn confirm_tool_call(&self, tool: &str, _arguments: &str) -> bool {
    // T24 adds the precise approval UI. Until then the desktop host is
    // intentionally fail-closed: a policy that requires confirmation
    // refuses the call instead of silently approving it.
    tracing::warn!(tool, "AI tool confirmation requested but no desktop UI is wired");
    false
}
```

工具循环确实会在需要确认时调用该端口（`tool_loop.rs:524-540`），但桌面端没有任何前端弹窗、IPC 命令或可接受结果的实现；全仓 `confirm_tool_call` 只有 trait 默认、工具循环、测试 Stub、桌面固定 false 和 `AiRequestHost` 委托五处。后果：

- `db_tool_policy=require_confirm` 时所有 DB 工具（包括 metadata）永远拒绝。
- `mcp_tool_policy=require_confirm` 时所有 MCP 工具永远拒绝。
- `require_sql_confirm=true`（默认 `AiSafetyGateConfig::default()` 即为 true）时 `query_readonly` 永远拒绝；桌面默认/企业预设下 Agent 无法读取真实数据。
- 用户无法选择“允许一次”，只能看到工具未执行错误。这不是“安全开关生效”，而是确认策略被固定成 deny-all。
- 实现文档明确要求“桌面实现弹窗，超时拒绝”和“前端确认弹窗测试”（`docs/development/ai-assistant-parity-implementation.md:222,231`）；本次 9 个文件无任何前端文件，也没有桌面确认端口测试或前端弹窗测试。

此外，`host.confirm_tool_call(...).await` 没有超时包装；即使后续宿主实现了会悬挂的弹窗，也没有“超时拒绝”的执行保证。当前桌面固定 false 只是立即拒绝，不能替代超时语义。

## 复现

1. 在 AI 模型配置中选 `RequireConfirm`（或保持默认 `requireSqlConfirm=true`），使用 Agent 模式请求真实数据。
2. 模型发起 `query_readonly` / DB / MCP 工具调用。
3. 观察：没有弹出确认框；工具直接不执行，只回错误；用户没有任何允许入口。
4. 在设置中选择 `RequireConfirm` 后执行 metadata 工具，同样立即被拒绝。

## 期望

- 桌面宿主实现精确确认 UI：显示工具名/参数（安全截断），允许 Allow once / Deny；拒绝、关闭、超时都返回 false，且宿主不执行工具。
- `require_sql_confirm` 对 `query_readonly` 的确认可被用户接受一次；默认 fail-closed 仍保留。
- 增加宿主确认端口测试（approve/reject/timeout）和前端确认弹窗测试；超时必须有明确上限。
- T08 的“安全开关真正生效”应可用，而不是所有 RequireConfirm 路径永久 deny。
