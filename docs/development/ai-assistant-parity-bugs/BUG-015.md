# BUG-015 T17 autoUse 是死设置，listing 无显式选择门控；重名与 2-skill 正文预算不符合 PRD

- 关联任务：T17 Skills 加载与工具
- 被测提交：`2b81245e6`（`feat: add skill discovery and tools`）
- 严重度：阻塞 T17 验收（“自动使用开关”无任何行为；关闭时仍向模型列出全部技能；PRD 硬预算未实现）
- 状态：待修复

## 结论

T17 的发现、frontmatter、按需读取、路径安全和 Agent 工具暴露主体可用，但以下
PRD §8.1 要求未闭环：

1. **`autoUse` 是死设置，且不存在“用户显式选中”路径。**
   - Rust 端 `auto_use` 除了 `AiSkillsSettings` 字段和默认值/序列化测试外没有任何
     读取点；生产逻辑只检查 `settings.skills.enabled`。
   - `ai_chat` 只按 `enabled + Agent + provider.supports_tools()` 注入工具
     （`crates/datazen-desktop/src/commands/ai/chat.rs:269-276`），没有读取
     `auto_use`；`run_chat_session` 也只把 host 传入的 `skill_tools` 追加到工具表。
   - `list_skills` 直接返回 `catalog.list()` 的全部技能
     （`crates/datazen/src/ai/skills/mod.rs:634-648`），没有“用户显式选中”的过滤。
   - 前端只持久化 `autoUse` 开关（`packages/frontend/src/windows/settings/SkillsSection.tsx:79-85`），
     没有 per-skill 选择状态；开关 on/off 对发现、listing、注入、调用均无差异。
   - 因此 PRD “自动使用默认关闭；关闭时只有用户显式选中的 skill 进入 listing”
     （`docs/development/ai-assistant-parity-prd.md:772`）未实现；当前行为等于始终
     向模型暴露全部技能。仅“默认值 false”通过，不能视为开关可用。

2. **默认/自定义目录同名技能没有“并列并按来源标注”。**
   - `entries()` 用 `seen` 按 name 去重，保留 user 根的第一个
     （`crates/datazen/src/ai/skills/mod.rs:265-272`）；现有测试甚至固定了这个行为
     （`custom_directory_is_scanned_and_duplicate_names_keep_the_first_source`）。
   - PRD §8.1 明确两个目录“独立校验，同名并列并按来源标注”
     （`docs/development/ai-assistant-parity-prd.md:770`）。当前 custom 同名技能被
     静默丢弃，`use_skill(name)` 也只能命中 user 副本。
   - 这不只是展示问题：custom 目录中的同名技能无法被模型或用户访问。

3. **“正文注入 ≤ 2 个 skill”的硬预算没有实现。**
   - 只有单文件 `MAX_SKILL_BYTES = 8 * 1024`
     （`crates/datazen/src/ai/skills/mod.rs:20`）；没有 loaded/skill 数量计数或上限。
   - `use_skill` 每次都可成功返回正文；tool loop 没有对 `use_skill` 次数做限制，
     也没有“超出提示”。PRD §8.1 的“正文注入 ≤ 2 个 skill；超出提示”
     （`docs/development/ai-assistant-parity-prd.md:773`）未实现。
   - 由于每次 `use_skill` 结果都会作为 tool result 进入模型上下文，这不是仅 UI
     预算，而是实际正文注入路径。

## 独立复现

临时 Rust 集成测试（已删除）直接调用公共 `SkillCatalog` / `list_skills`：

```bash
cargo test -p datazen --features ai --test t17_retest_temp
```

结果为 3 failed：

- `prd_auto_use_off_lists_only_explicitly_selected_skills`：
  `auto_use=false` 且没有显式选择时，`list_skills` 仍返回
  `[{"name":"alpha"}]`，期望 `[]`。
- `prd_same_name_skills_are_listed_side_by_side_with_source`：
  user/custom 各有一个 `shared`，listing 只有 1 条（user），期望 2 条且来源分别
  为 user/custom。
- `prd_body_injection_is_capped_at_two_skills`：
  连续 `use_skill("one"/"two"/"three")` 三次均成功（loaded=3），期望最多 2。

临时测试已删除；`git status` 仅保留本文档和 test-report 的测试记录变更。

## 已加载技能状态：真实，但只完成展示闭环

不是伪造状态：

- tool loop 在 `use_skill` 成功且结果不是 `Error:` 时调用
  `host.on_skill_used`（`crates/datazen/src/ai/application/tool_loop.rs:603-619`）；
- 桌面 host 发出 `ai:skill-used`（`crates/datazen-desktop/src/commands/ai/grant.rs:282-295`）；
- `aiStore` 只接受匹配当前 `requestId` 的事件，写入 `chatSession.loadedSkills` 和
  `metadata.loadedSkills` 并持久化（`packages/frontend/src/stores/aiStore.ts:907-927`）；
- 新会话/清空会话重置，历史会话恢复时 normalize
  （`packages/frontend/src/stores/ai/sessions.ts:287,313,344`）；
- Chat 面板显示已加载 skill chip（`packages/frontend/src/components/ai/AiChatPanel.tsx:785-800`）；
- 现有测试 `records used skills on the active chat session only` 和
  `shows skills whose bodies were loaded in this session` 通过。

但 PRD 还要求“待加载”一次性提示，以及文件被删/超限后回到未加载并说明原因
（`docs/development/ai-assistant-parity-prd.md:774,776`）。当前没有 pending 提示，
也没有重新校验已加载 skill 的文件；删除/超限后 chip 会保留。这是状态闭环的
剩余缺口，不应被描述为完整实现。

## 影响

- 用户打开/关闭“自动使用技能”看不到任何行为差异；关闭后模型仍能列出并读取
  全部技能，和 PRD 的“只有用户显式选中”相反。
- 自定义目录同名技能被 user 目录静默遮蔽，团队 skill 可能完全不可用。
- 无 2-skill 上限，多个正文可连续进入上下文，绕过 PRD 的注入预算。
- 加载状态 chip 真实但不清理失效文件，可能长期显示已经不存在的 skill。

## 修复方向（仅记录，不在本次测试修改）

1. 给 catalog/listing 增加显式选择集合（或 autoUse 的明确注入策略）：
   - autoUse=false 时，`list_skills` 只返回用户显式选中的 skill；
   - autoUse=true 时，明确自动注入/自动调用的路径与上限；
   - 不要把“开关持久化”当作实现。
2. 同名技能按 PRD 并列：保留两个 `SkillSummary`（source 区分），`use_skill` 需要
   能按来源/复合键选择，不能静默丢 custom。
3. 在 tool loop 或 catalog 增加“本轮/本会话最多 2 个正文”的计数与错误/提示；
   不能只限制单文件 8KB。
4. 补上 pending 一次性提示，并在 `use_skill`/恢复/下次使用前重新校验文件；
   删除或超限时清除 loaded 状态并返回原因。
