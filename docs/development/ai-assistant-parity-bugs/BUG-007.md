# BUG-007 T09 删除连接后 AI 数据清理失败只 warn，留下孤儿且无重试

- 关联任务：T09 AppDb v7 AI 笔记/记忆/FTS/审计
- 被测提交：`34a5b398223e29ecd984eaef47cefa8bd76d2349`
- 严重度：阻塞 T09 验收（删除连接清理关联 notes/memories 的失败路径）
- 状态：未修复

## 现象

`DesktopRepository::delete_connection` 先删除并持久化 `connections.json`，随后调用 `purge_connection_ai_data`。清理失败时只 `tracing::warn!`，仍把 JSON 持久化结果原样返回为成功：

```rust
// crates/datazen-desktop/src/store/connections.rs:204-222
let persisted = self.persist_connections_locked(&snapshot).await;
if persisted.is_ok() {
    if let Err(error) = self
        .app_db
        .purge_connection_ai_data(id, crate::platform::LOCAL_ORGANIZATION_ID)
    {
        tracing::warn!(connection_id = %id, error = %error,
            "connection deleted but AI notes/memories cleanup failed");
    }
}
persisted
```

`purge_connection_ai_data` 内部确实是 notes/memories/audit 的单个 SQLite `Immediate` 事务（`ai_memory.rs:392-420`），但它与 JSON catalog 无法共享事务；当前实现没有补偿、没有 outbox/重试、没有让删除返回错误。只要 SQLite 写入失败（锁、磁盘、表损坏、触发器错误等），连接已经从用户目录消失，AI 笔记/记忆/审计却留在 AppDb，永久孤儿。

T09 实现文档要求“删除连接时同事务清理 notes + memories”，验收要求“删除连接清理关联记忆/笔记”；当前只覆盖成功路径，失败路径违反清理承诺。

## 复现

本次用临时测试注入清理失败（已还原，未修改生产代码）：

1. 创建 `c-fail` 连接、其 AI note 和 connection-scoped memory。
2. 在 `ai_connection_notes` 上创建 `BEFORE DELETE ... RAISE(ABORT)` 触发器，模拟 AppDb 清理失败。
3. 调用 `store.delete_connection("c-fail")`。
4. 实际：`delete_connection` 返回 `Ok(())`，`get_connection` 已为空；`get_ai_connection_note("c-fail")` 仍返回 note，`get_ai_memory(...)` 仍返回 memory。

临时测试输出：

```
test store::tests::connections_tests::tester_delete_connection_purge_failure_leaves_orphan_ai_data ... ok
```

它不是“失败被拒绝”的测试，而是确认当前实现会把失败吞掉并留下孤儿数据。

## 期望

- 删除连接时 notes/memories/audit 与 catalog 删除必须具备可恢复的一致性：要么 durable outbox/重试清理，要么在清理失败时回滚/恢复 catalog 并返回错误；不能静默成功。
- 至少要有失败路径测试（模拟 SQLite 清理失败），断言用户可感知或自动重试，并最终无孤儿；不能只测试触发器和清理成功。
- 明确跨 JSON/SQLite 的实现策略；文档中的“同事务”若无法做到，必须改成可验证的补偿/重试语义。

## 实际

- JSON 删除成功、AppDb 清理失败时 `delete_connection` 仍成功返回；notes/memories/audit 孤儿保留。
- 没有重试、没有补偿、没有失败测试；`deleting_connection_purges_ai_notes_memories_and_audit` 只覆盖成功路径。
