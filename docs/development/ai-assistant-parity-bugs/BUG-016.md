### 新增阻塞一：`#` 被全局当作注释，回归 PostgreSQL 运算符

`#` 在 MySQL 是行注释，但在 PostgreSQL 是合法的位运算/JSON 运算符。新扫描器在
[query.rs](crates/datazen-cli/src/query.rs:182) 对所有连接都执行
`rest.starts_with('#')`，没有数据库类型判断：

```bash
target/debug/datazen --data-dir /tmp/t18b/desktop-data query conn_e2e_pg \
  'SELECT 5 # 3 AS n' --timeout 5s --json
# exit 11 / E_DRIVER: syntax error at or near "AS"

target/debug/datazen --data-dir /tmp/t18b/desktop-data query conn_e2e_pg \
  "SELECT '{\"a\":1}'::jsonb #> '{a}' AS v" --timeout 5s --json
# exit 11 / E_DRIVER: syntax error at or near "AS"
```

`psql` 对同样两条语句分别返回 `6` 和 `1`，确认是 CLI 扫描器把 `#` 之后的内容
截成了注释/后缀，而不是 PostgreSQL 语法问题。**即使不传 `--limit` 也会发生**，
因为默认 limit 仍走 `limited_sql`。这不是只影响 `--limit` 的边缘，而是破坏
PostgreSQL 普通查询和 SQL Server `#temp` 标识符的跨方言回归；MySQL 的 `#` 支持
不能以全局语法为代价。

### 新增阻塞二：CLI 仍会对立即失败的 launcher 假报 `launched:true`

`commands.rs` 在 `desktop_launch::launch` 返回 `Ok` 后无条件写出
`"launched": true`：

```bash
printf '#!/bin/sh\nexit 1\n' > /tmp/t18c/fail-desktop && chmod +x /tmp/t18c/fail-desktop
DATAZEN_DESKTOP_BIN=/tmp/t18c/fail-desktop \
  target/debug/datazen --data-dir /tmp/t18b/desktop-data open conn_e2e_pg \
  --query 'SELECT 1' --json
# rc 0；输出 "launched": true
```

`spawn_direct` 只确认 `Command::spawn` 成功，不等待、不握手；launcher 立即退出
或桌面初始化失败仍会报成功。正常的假 launcher 参数测试、缺失应用 `E_NOT_FOUND`
都通过，但“CLI 不假报 launched”这一条仍未闭环。`-n` 解决了运行中 App 不接收
参数的问题，没有解决“进程启动后是否消费请求”的确认。

### shared execution Runtime 边界判断（不单独决定本次失败）

`RuntimeConnectionUseCases::new` 需要 `ProfileRepository`、`PolicyService`、

### `--limit` 新增边界失败（不能忽略）

```bash
# PostgreSQL dollar-quoted literal：值被篡改
target/debug/datazen --data-dir /tmp/t18b/desktop-data query conn_e2e_pg \
  'SELECT $$a;b$$ AS s -- limit' --limit 1 --timeout 5s --json
# {"rows":[["a LIMIT 2;b"]],"truncated":false}
# 原值应为 "a;b"；LIMIT 被插进了 dollar quote 内部，属于数据损坏。
```

```bash
# MySQL # 尾随注释：LIMIT 被注释掉，查询无界
target/debug/datazen --data-dir /tmp/t18b/desktop-data query conn_gimlk4k4 \
  'SELECT SLEEP(0.2) FROM information_schema.columns # tail' \
  --limit 1 --timeout 2s --json
# exit 10 / E_TIMEOUT，real 2.01s
```

`limited_sql` 的扫描器只识别 `--`、`/* */`、`'`、`"`、`` ` ``；没有 PostgreSQL
dollar quote、MySQL `#` 注释、SQL Server `[]`，也未处理反斜杠转义。MySQL `#` 前置
场景本次能通过（LIMIT 追加在有效 SQL 后），但尾随 `#` 会让追加的 LIMIT 进入注释。
这直接违反“limit 不破坏 SQL / 不产生数据损坏”的验收底线。

**判定**：不能以“共享 driver-api + sql_guard + fail-closed”完全替代 T18 的

## ed5a19d6e 历史 `--limit` 边界（标准路径已在 d36080ce5 修复）

`live_databases` 中 `postgres_limit_is_pushed_into_execution` 也通过。

### 2.2 前置注释：limit 完全不追加，查询无界

```bash
/usr/bin/time -p datazen --data-dir /tmp/datazen-t18-pg query pg \
  '/* leading */ SELECT i, pg_sleep(0.2) FROM generate_series(1,10) AS i' \
  --limit 1 --timeout 2s --json
# exit 10 / E_TIMEOUT；real 2.01s（若 limit 生效应约 0.4s）
```

`limited_sql` 用 `trimmed.to_ascii_uppercase().starts_with("SELECT"/"WITH")` 判断；
`/* leading */` 使其判为非 SELECT，直接返回原 SQL（`query.rs:165-182`）。同样，
`-- leading\nSELECT ...` 也绕过（用 `--` 传 SQL 时实测 2.01s timeout）。

### 2.3 尾随行注释：追加的 LIMIT 被注释掉

```bash
datazen ... query pg \
  'SELECT i, pg_sleep(0.2) FROM generate_series(1,10) AS i -- trailing' \
  --limit 1 --timeout 2s --json
# exit 10 / E_TIMEOUT；real 2.01s
```

`limited_sql` 把 ` LIMIT 2` 追加到 `-- trailing` 之后，整段成为注释，实际仍是
无界查询。尾随块注释 `/* trailing */` 可以正常追加；行注释是明确回归。

### 2.4 `WITH ... UPDATE/INSERT/DELETE` 被错误追加 LIMIT

```bash
datazen ... query pg \
  "WITH x AS (SELECT 1) UPDATE datazen_t18_limit_probe SET note='w' WHERE id=2 RETURNING id" \
  --allow-writes --limit 1 --json
# exit 11 / E_DRIVER
# Query failed: syntax error at or near "LIMIT"
```

`append_select_limit` 把任何 `WITH` 当 SELECT；`limited_sql` 在其后追加 LIMIT，
`WITH ... UPDATE ... RETURNING` 不是 SELECT，语法被破坏。普通 `UPDATE`/`INSERT`/
`DELETE` 已实测正常，但“非 SELECT 不破坏”对 CTE DML 不成立。

## ed5a19d6e 历史判定

- **`open`：仍阻塞**。E_UNSUPPORTED 是诚实的 fail-closed，但不等于 T18/PRD 要求的
  `open` 可用；需要桌面连接路由/启动实现，或正式 descope。
- **shared execution Runtime：仍阻塞**。当前只共享了 connection、driver-api 和
  sql_guard；fail-closed 只能作为安全补丁，不能证明已复用 execution 端口。若产品
  明确修改验收文字为“CLI 仅共享 driver-api”，可作为边界接受。
- **`--limit`：普通路径已修复，但注释/CTE 边界仍失败**；这是本轮新增的独立失败，
  不能标“已验证”。
- SUGGESTED 修复（不修改生产代码）：limit 追加前先剥离/保留前后注释并识别实际主
  动词；对 `WITH` 用 SQL 主语句判断而非前缀；阅读器/解析器应保留行注释分隔；补
  `--limit` 前后注释、`WITH UPDATE RETURNING`、`PRAGMA main.table_info` 测试。
