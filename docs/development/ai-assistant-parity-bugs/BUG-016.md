## 仍阻塞的两项（按本轮要求重点）

### 1. `open` 仍然不可用

```bash
./target/debug/datazen --data-dir /tmp/datazen-t18-p0 open local --json
# exit 14
# {"ok":false,"code":"E_UNSUPPORTED",
#  "message":"opening connection 'prod-db' from the CLI is not wired to a desktop route; no connection URI was emitted"}
```

现在不再伪造 `datazen://connection/<id>`，这是安全上的改进；但 T18 的实现清单包含
`open`，PRD §8.3 明确要求：

```text
datazen open <connection> --query "<sql>"
```

当前没有任何桌面连接路由或启动路径，命令永远返回 `E_UNSUPPORTED`。**失败关闭不能
替代功能实现**；若产品决定 T18 不做 `open`，必须先修改 T18/PRD 验收文字，否则仍是
阻塞项。临时测试 `open_does_not_emit_an_unconsumable_uri` 只断言“不输出 URI”，
没有覆盖“能打开”。

### 2. shared execution Runtime 仍未接

`crates/datazen-cli/src/query.rs:132-205` 仍直接：

```rust
let driver = create_driver(&config.database_type)?;
let handle = driver.connect(config).await?;
let result = driver.query(&handle, sql).await?;
```

`ensure_supported_host_wiring` 只对隧道配置 fail-closed，没有调用
`datazen::execution` Runtime、lease、session 或共享执行入口。T18 实现文档
`docs/development/ai-assistant-parity-implementation.md:438` 明确要求
“复用共享 connection/execution 端口”。

**判定**：不能以“共享 driver-api + sql_guard + fail-closed”完全替代 T18 的
execution 端口要求。fail-closed 解决了“静默直连绕过隧道”的安全问题，平台 vault
也补上了，但：
- 没有共享 Runtime 的会话/资源/租约语义；
- CLI 仍需自己直接组装驱动；
- 若未来共享执行加入取消、审计、连接生命周期，CLI 会再次分叉。

如果产品明确把 T18 改为“CLI 只复用 driver-api，不接 Runtime”，并同步验收文字，
该边界可以接受；按当前文字仍是阻塞项。

## `--limit` 新增边界失败

### 2.1 普通路径已通过

```bash
# 10 行 × 0.1s，limit 1：只执行 2 行，约 0.23s，rows=1 truncated=true
datazen --data-dir /tmp/datazen-t18-pg query pg \
  'SELECT i, pg_sleep(0.1) FROM generate_series(1,10) AS i' \
  --limit 1 --timeout 2s --json

# 100000 行 limit 5：rows=5 truncated=true
datazen ... query pg 'SELECT i FROM generate_series(1,100000) AS i' --limit 5 --json

# 已有 LIMIT 50、--limit 5：外层封顶，rows=5 truncated=true
datazen ... query pg 'SELECT i FROM generate_series(1,100) AS i LIMIT 50' --limit 5 --json
```

`live_databases` 中 `postgres_limit_is_pushed_into_execution` 也通过。

### 2.2 前置注释：limit 完全不追加，查询无界

```bash
/usr/bin/time -p datazen --data-dir /tmp/datazen-t18-pg query pg \
  '/* leading */ SELECT i, pg_sleep(0.2) FROM generate_series(1,10) AS i' \
  --limit 1 --timeout 2s --json
# exit 10 / E_TIMEOUT；real 2.01s（若 limit 生效应约 0.4s）
```

`limited_sql` 用 `trimmed.to_ascii_uppercase().starts_with("SELECT"/"WITH")` 判断；
`/* leading */` 使其判为非 SELECT，直接返回原 SQL（`query.rs:165-182`）。同样，
`-- leading\nSELECT ...` 也绕过（用 `--` 传 SQL 时实测 2.01s timeout）。

### 2.3 尾随行注释：追加的 LIMIT 被注释掉

```bash
datazen ... query pg \
  'SELECT i, pg_sleep(0.2) FROM generate_series(1,10) AS i -- trailing' \
  --limit 1 --timeout 2s --json
# exit 10 / E_TIMEOUT；real 2.01s
```

`limited_sql` 把 ` LIMIT 2` 追加到 `-- trailing` 之后，整段成为注释，实际仍是
无界查询。尾随块注释 `/* trailing */` 可以正常追加；行注释是明确回归。

### 2.4 `WITH ... UPDATE/INSERT/DELETE` 被错误追加 LIMIT

```bash
datazen ... query pg \
  "WITH x AS (SELECT 1) UPDATE datazen_t18_limit_probe SET note='w' WHERE id=2 RETURNING id" \
  --allow-writes --limit 1 --json
# exit 11 / E_DRIVER
# Query failed: syntax error at or near "LIMIT"
```

`append_select_limit` 把任何 `WITH` 当 SELECT；`limited_sql` 在其后追加 LIMIT，
`WITH ... UPDATE ... RETURNING` 不是 SELECT，语法被破坏。普通 `UPDATE`/`INSERT`/
`DELETE` 已实测正常，但“非 SELECT 不破坏”对 CTE DML 不成立。

## P0 复测明细（已通过）

生产 `prod-db`（SQLite）带 `--allow-writes --allow-dangerous-sql`：

| SQL | 结果 |
|---|---|
| `PRAGMA journal_mode=WAL` | exit 9 `E_PRODUCTION_WRITE` |
| `PRAGMA user_version=7` | exit 9 |
| `ATTACH DATABASE ...` | exit 9，未创建文件 |
| `VACUUM` | exit 9 |
| `ANALYZE` | exit 9 |
| `SET search_path = public` | exit 9 |
| `BEGIN` | exit 9 |
| `USE other_database` | exit 9 |
| `REINDEX` | exit 9 |
| `PRAGMA table_info(items); PRAGMA user_version=7` | exit 9 |
| `PRAGMA table_info(items); VACUUM` | exit 9 |
| `SELECT 1; PRAGMA user_version=7` | exit 9 |
| `PRAGMA journal_mode(WAL)` / `PRAGMA writable_schema=ON` / `PRAGMA main.journal_mode=WAL` | exit 9 |

只读放行：`PRAGMA journal_mode`、`PRAGMA table_info(items)`、`PRAGMA user_version`、
`PRAGMA foreign_keys` 均 exit 0。拒绝后 `PRAGMA user_version` 仍为 0；`ATTACH` 文件
不存在。`journal_mode` 显示 `wal` 是 SQLite 驱动连接时默认设置
（`crates/drivers/sqlite/src/sqlite.rs:346-347`），不是被拒绝语句执行的结果。

**小问题（非本轮主阻塞）**：`PRAGMA main.table_info(items)` 被误判为生产状态变更而
拒绝（exit 9）。无前缀的 `PRAGMA table_info` 正常；这是只读放行的限定符误报，
不是安全旁路。

## 判定

- **`open`：仍阻塞**。E_UNSUPPORTED 是诚实的 fail-closed，但不等于 T18/PRD 要求的
  `open` 可用；需要桌面连接路由/启动实现，或正式 descope。
- **shared execution Runtime：仍阻塞**。当前只共享了 connection、driver-api 和
  sql_guard；fail-closed 只能作为安全补丁，不能证明已复用 execution 端口。若产品
  明确修改验收文字为“CLI 仅共享 driver-api”，可作为边界接受。
- **`--limit`：普通路径已修复，但注释/CTE 边界仍失败**；这是本轮新增的独立失败，
  不能标“已验证”。
- SUGGESTED 修复（不修改生产代码）：limit 追加前先剥离/保留前后注释并识别实际主
  动词；对 `WITH` 用 SQL 主语句判断而非前缀；阅读器/解析器应保留行注释分隔；补
  `--limit` 前后注释、`WITH UPDATE RETURNING`、`PRAGMA main.table_info` 测试。
