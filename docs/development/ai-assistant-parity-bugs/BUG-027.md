- 复测时间：2026-11-07
- 严重度：阻塞 T26 的文档验收；不阻塞本提交已通过的功能测试。
- 状态：待修复（本轮只审计，未改代码/文档，未提交）

## 结论

T26 的提交范围与代码门禁均通过，但六份长期文档没有达到 T26 的验收项
“文档链接可达、无未实现声明、与代码一致”：

1. **新增的 security 链接指向不存在的路径。**
2. **`backend/ai.md` 的 MCP/工具面描述仍停留在旧实现。**
3. **`backend/mcp.md` 把 Ask 模式写成了仍注入 MCP 工具。**

因为文档本身就是 T26 的交付物，这些不是历史门禁噪音，而是本轮阻塞项。

## 证据

### 1. `security.md` 新增链接失效

`docs/architecture/security.md:86`：

```markdown
见[持久化模型 §4.1](../platform/persistence-model.md#41-桌面本地持久化现状已实现)
```

从 `docs/architecture/security.md` 解析为：

```text
docs/platform/persistence-model.md   # 不存在
```

实际文件为 `docs/architecture/platform/persistence-model.md`；正确相对路径是
`platform/persistence-model.md`（去掉 `../`）。该链接由 `3833ae919` 新增。

复现：

```bash
python3 - <<'PY'
from pathlib import Path
p = Path('docs/architecture/security.md').parent / '../platform/persistence-model.md'
print(p.resolve(), p.exists())
PY
# /…/docs/platform/persistence-model.md False
```

### 2. `backend/ai.md` §1.11 仍称 DB tools 只有五个只读工具、无写工具

`docs/architecture/backend/ai.md:251`：

```text
DB tools — list_connections、list_databases、list_tables、search_tables、
get_table_schema 五个只读工具（db_tool_definitions() 全集，无写工具）
```

实际共享层在 Agent 模式且绑定连接时会用
`agent_db_tool_definitions(attach_agent_query_tools)` 追加
`query_readonly`、`sample_rows`、`propose_write`：

- `crates/datazen/src/ai/application/chat_session.rs:218-219`
- `crates/datazen/src/ai/application/tools.rs:82-129`

`propose_write` 明确是写入提案工具。同一文档 §1.13（第 316 行）已经写明
Agent 会追加这三个工具，因此 §1.11 与 §1.13 自相矛盾。§1.11 应改写为
“Ask 为零；Agent 至少五个元数据工具，绑定连接且策略允许时追加
query_readonly/sample_rows/propose_write”，或直接删除旧的全集断言。

### 3. `backend/ai.md` §1.11 仍称 MCP 工具面“尚未端口化”

`docs/architecture/backend/ai.md:256`：

```text
MCP 连接发现和调用留在 Tauri adapter（AI 侧的 MCP 工具面尚未端口化……）
```

实际 MCP 工具面已经有共享消费者端口 `McpToolBroker`：

- 端口定义：`crates/datazen/src/ai/application/ports.rs:133`
- 共享装配：`crates/datazen/src/ai/application/mcp_tools.rs`
  （模块头注明 M3、跨形态收敛）
- 桌面实现：`crates/datazen-desktop/src/services/feature_ports.rs:70`

“连接发现/stdio 生命周期仍在桌面”是事实，但“MCP 工具面尚未端口化”与代码
相反。该行应改为“工具定义/路由已通过 `McpToolBroker` 端口共享；stdio 连接
发现和子进程仍在桌面实现”。

### 4. `backend/mcp.md` 把 Ask 模式写成仍注入 MCP 工具

`docs/architecture/backend/mcp.md:198`：

```text
AI Chat（ai_chat）在已连接外部 MCP 时将 MCP 工具与内置 DB tools 一并注入 Provider。
内置 DB tools 在 Ask 模式为零，在 Agent 模式至少有 5 个只读元数据工具……
```

实际 `chat_session.rs:220-224` 在非 Agent 模式把 `mcp_tools` 直接置空：

```rust
mcp_tools: if agent_tools_allowed {
    env.mcp_tools
} else {
    Vec::new()
},
```

所以 Ask 模式既没有内置 DB tools，也没有 MCP 工具；这与
`docs/architecture/frontend/ai.md` §1.9 的“Ask 不挂载 DB/MCP/Skill/插件/
Workflow 工具”一致，但与 `backend/mcp.md` 本句冲突。应改写为“Ask 不注入
MCP/DB；Agent 才注入 MCP 与内置 DB tools”。
