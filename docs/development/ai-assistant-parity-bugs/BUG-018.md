# BUG-018 T20 Redis key_pattern 可被多 key EXISTS 绕过；batch/Redis 拒绝审计与逐语句 rowCount 缺失

- 关联任务：T20 MCP batch 与 Redis 只读工具
- 被测提交：`9b7277f8a`（`feat: add MCP batch and Redis read tools`），父 `25ad7feb0`
- 复测时间：2026-11-06
- 严重度：阻塞 T20 验收。Redis key pattern 边界可被多 key `EXISTS` 绕过；拒绝的 Redis 写/危险命令在审计中记为 allow；batch 没有逐语句审计且审计 rowCount 为空。
- 状态：待修复

## 结论

T20 的主功能路径大部分通过：batch 默认只读、写语句整批拒绝、事务失败回滚、部分失败/stoppedAt/rowCount、
SHOW/scope、Redis GET/MGET/SCAN、写/危险/管理命令拒绝、key pattern、limit、输出体积和参数转义均可用；
15 工具契约和 T19 scope/审批/审计也没有回归。

但以下 3 个验收缺口仍存在：

1. **Redis key pattern 可被 `EXISTS` 多 key 绕过（P0）**
2. **Redis 写/危险/管理命令被拒绝后，审计记为 `allow`（P1）**
3. **batch 只有一条调用级审计，且审计 `rowCount` 为 null，没有逐语句审计/行数（P1）**

## 复现

### 1. `EXISTS` 多 key 绕过 key_pattern

连接 `conn_demo_redis`（127.0.0.1:6379，测试使用 logical DB 15），预置：

```text
t20:key   = hello
other:key = outside
```

调用：

```json
{
  "name": "redis_command",
  "arguments": {
    "connection_id": "conn_demo_redis",
    "database": "15",
    "command": "EXISTS",
    "args": ["t20:key", "other:key"],
    "key_pattern": "t20:*"
  }
}
```

实际返回成功：

```json
{
  "command": "EXISTS",
  "keyPattern": "t20:*",
  "limit": 100,
  "result": {
    "command": "EXISTS t20:key other:key",
    "ok": true,
    "value": "2",
    "resultType": "scalar"
  }
}
```

只传 scope 外 key 时会被拒绝：

```text
Redis key 'other:key' is outside the configured key pattern 't20:*'
```

根因：`crates/datazen/src/mcp/application/redis.rs` 的 `validate_key_args` 对
`EXISTS` 走 `_ => vec![0]`，只校验第一个 key；Redis `EXISTS` 是可变 key 命令，
第二及后续 key 未校验，实际命令被 driver 执行。

### 2. Redis 拒绝命令的审计 decision 为 allow

同一连接依次调用 `SET`、`DEL`、`FLUSHALL`、`KEYS`、`CONFIG`、`EVAL`，全部在
driver 之前被拒绝，Redis 数据保持不变；但 `mcp-audit.jsonl` 中对应记录为：

```text
tool=redis_command databaseName=15 namespace=null
decision=allow rowCount=null requestId=<uuid>
```

期望：被拒绝的写/危险/管理命令至少应记为 `deny`（并且不能让人误以为命令已被允许
执行）。根因是命令分类发生在 `execute_redis_read` 的 tool body，policy 不分类
`redis_command`；随后 `audit_allowed_call` 将 tool body 的校验错误统一记为 allow。

### 3. batch 审计没有逐语句记录，rowCount 为空

调用：

```json
{
  "name": "execute_batch",
  "arguments": {
    "connection_id": "conn_e2e_pg",
    "sql": "SELECT 1 AS a; SELECT 2 AS b"
  }
}
```

执行结果正确：`ok=true`、`transaction=false`、`statements` 有 2 条、`rowCount=2`；
但 `mcp-audit.jsonl` 只有 1 条 `execute_batch` 记录，且 `rowCount=null`：

```text
tool=execute_batch databaseName=postgres namespace=public
decision=allow rowCount=null requestId=<uuid>
```

没有逐语句 `index/ok/rowCount` 或每语句一条审计，无法回答“哪一条 batch 语句被
执行/失败”。根因：`crates/datazen-desktop/src/mcp/server.rs` 的
`audit_allowed_call` 只在 `query | use_session | run_workflow` 时读取 rowCount，
`execute_batch`/`redis_command` 未被纳入；batch 的逐语句结果只存在于工具返回体，
未写入审计。

## 已通过的主路径

- `execute_batch` 默认只读；`SELECT 1; CREATE TABLE ...` 在第一条执行前整批拒绝，
  表未创建；`CREATE` 在第一/第二/注释后均被识别。
- `transaction=false` 不显式开事务；`transaction=true` 返回 `transaction=true`；
  失败返回 `ok=false`、`stoppedAt=1`、`rolledBack=true`，成功语句只保留 1 条；
  非事务失败返回 `rolledBack=false`、2 条 attempted，成功语句保留。
- 部分失败/`stoppedAt`/aggregate `rowCount` 语义正确；`limit=3` 返回 3 行并
  `truncated=true`；51 条被 50 条上限拒绝；空/注释-only 被拒绝。
- 字符串、注释、dollar quote 内的分号没有被当作注入入口；`SELECT '; DROP ...'`
  执行后未产生表。合法的 dollar quote 单语句会被 SafeWrite 多语句分类拒绝，属于
  fail-closed，不构成执行越界。
- 逐语句 scope：PG `information_schema`/`pg_catalog`/`template1` 在 batch 第 2 条
  被拒绝，审计记录实际 namespace/database；scope 内 batch 正常。
- Redis `GET`/`MGET`/`SCAN` 真实执行；scope 外单 key、SCAN MATCH 外 key、MGET
  key 数超过 limit、SCAN COUNT 超过 limit、非数字 cursor、未知命令、换行/NUL
  参数均拒绝；带空格/双引号参数实际执行成功；110000 字节值在默认 limit 下因
  输出体积被拒绝，limit=1000 可返回。
- Redis 逐数据库 scope、namespace 拒绝、`database` 默认值均按预期；写命令
  `SET`/`DEL`/`FLUSHALL`/`KEYS`/`CONFIG`/`EVAL` 未改变测试 DB。
- 工具契约为 15 个工具，`execute_batch`/`redis_command` 的 schema、描述、注解
  在 stdio `tools/list` 中可见；T19 `query`/`list_tables`/scope deny/schema
  resource/审批回归通过。
