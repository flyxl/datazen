# BUG-022 T23 本地 CLI 子进程退出后子孙持有 stdout 时，timeout/cancel 挂起且留下孤儿

- 关联任务：T23 本地 CLI Agent Provider
- 被测提交：`68470a6f5`（`feat: add local CLI agent providers`）
- 复测时间：2026-11-07
- 严重度：阻塞 T23。违反“取消/超时不挂起”和“不能留孤儿”的验收项。
- 状态：已验证（`a3990293e`）

## 结论

T23 的正常路径通过：8 个预设、模型/provider 元数据、缺失可执行文件错误、
stdout 流式顺序、stderr 脱敏、敏感 env 不继承、默认临时 cwd、非 0 退出、
取消仍运行的直接子进程及其子进程、设置页选择/自定义路径/校验均正常。

但当**直接子进程已经退出、它启动的子孙进程仍持有 stdout/stderr 管道**时，
适配器在 `WaitResult::Exited` 分支无超时、无取消地等待 reader EOF。结果：

1. 配置的 `timeoutSecs=1` 不会生效，`complete()` 会一直挂到子孙进程退出；
2. 此时调用 `cancel()` 也不会被观察，`stream_complete()` 同样挂起；
3. 子孙进程没有被 `kill_process_tree` 清理，成为孤儿。

这在实际 CLI 中很常见：CLI 启动 MCP server、语言服务器或后台 helper 后直接退出，
helper 继承 stdout/stderr；适配器不能假定直接子进程退出时所有管道都会立即 EOF。

## 复现 1：timeout 不生效

临时 fake CLI（Unix）：

```sh
#!/bin/sh
sleep 3 & printf 'started\n'; exit 0
```

配置 `timeoutSecs=1`，调用 `complete()`，外层用 2 秒超时保护。实际 2 秒内没有
返回；1 秒 timeout 被忽略。去掉外层保护会一直等到 `sleep 3` 退出。

## 复现 2：cancel 不生效

```sh
#!/bin/sh
printf 'started\n'; sleep 0.2; sleep 3 & exit 0
```

`stream_complete()` 收到 `started\n` 后，等直接 shell 退出（约 0.2 秒），再调用
`provider.cancel(request_id)`。外层 2 秒超时仍然到期；cancel 没有被处理，直到
后台 `sleep 3` 结束。

## 根因

`crates/datazen/src/ai/providers/local_cli.rs:563-575`：

```text
let result = tokio::select! {
    status = child.wait() => WaitResult::Exited(status),
    _ = wait_for_cancel(request_cancel) => WaitResult::Cancelled,
    _ = token.cancelled() => WaitResult::Cancelled,
    _ = tokio::time::sleep(state.timeout) => WaitResult::Timeout,
};

match result {
    WaitResult::Exited(Ok(status)) => {
        let _ = stdin_task.await;
        let content = stdout_task.await.unwrap_or_default();
        let stderr = stderr_task.await.unwrap_or_default();
        ...
```

timeout 和 cancel 只与 `child.wait()` 竞争；直接子进程退出后进入 `Exited` 分支，
这两个信号不再被观察。`stdout_task.await` / `stderr_task.await` 等的是 pipe EOF，
而 pipe 被子孙进程持有，所以不返回。该分支也不调用 `kill_process_tree`。

## 影响

- 配置的 timeout 对“CLI 已退出但 helper 仍持有输出”的常见场景失效。
- 用户点 Stop 无法结束请求；UI/流式循环一直挂起。
- 后台 helper 成为孤儿，可能继续占用模型/网络/文件资源。
- 违反 T23 验收：“取消/超时不挂起”“取消确实 kill 进程（含子进程/进程组，
  不能留孤儿）”。

## 修复建议

- 读 stdout/stderr 的等待必须继续受同一个 deadline 和 cancellation 约束，不能在
  `Exited` 分支变成无界 `await`。
- 直接子进程退出后，用剩余 timeout / cancel 与 reader join 竞争；超时或取消时
  `kill_process_tree`（进程组）并 abort reader，随后 cleanup workspace。
- 正常退出也应确认 descendant 不再持有管道；至少设置有限的 drain 宽限，之后
  杀进程组，避免永久等待和孤儿。
- 补 fake CLI 测试：直接子进程退出 + 后台子孙持有 stdout，验证 complete 在
  timeout 内返回、cancel 在短时间返回、子孙进程被清理。

## 复测（b124878a1，未通过）

`fix: bound CLI pipe drain and kill orphan descendants` 修复了挂起/孤儿主路径：

- 主进程退出、后台 sleep 30 持有 stdout：约 500ms + abort grace 内返回，后台
  PID 消失。
- 直接子进程退出后调用 cancel：快速返回 Cancelled，后台 PID 消失。
- 正常 alpha/beta/gamma 输出完整，不截断。
- 非 0/缺失/早取消/stderr 脱敏/敏感 env/cwd 回归通过。

但用户验收项 1 的 **timeout 结果语义**仍未满足：

```sh
#!/bin/sh
sleep 3 & printf 'started\n'; exit 0
# timeoutSecs=1
```

实际 `complete()` 在约 854ms 返回：

```text
Ok(CompletionResponse { content: "started\n", finish_reason: "stop", ... })
```

后台 sleep 已被清理，但结果不是预期的 `Err(AiError::Timeout(1))`，也不在约 1s
的 timeout 点返回。根因是 `PIPE_DRAIN_GRACE=500ms` 先于 timeout：直接子进程
退出后 drain 只等 500ms，然后杀进程组并**按成功状态**返回；`drain_hits_timeout`
为 false，不会进入 Timeout 分支。

建议：drain 因 pipe 仍被子孙持有而被迫杀进程组时，不应把本次请求当作正常成功；
应在剩余 timeout 到期时返回 Timeout（或至少在该异常 drain 路径返回 Timeout，
item 3 的“约 500ms 返回并 kill 孤儿”仍成立）。只有 reader 自然 EOF、输出完整时
才返回 Ok。

复测数字：datazen ai 1676、ai+workflow+wapps 1742、mcp 1746、desktop 1405/10
ignored、server 361、local_cli 21、T23 定向前端 20、全量前端 8234/8 既有环境失败、
映射 typecheck OK、fmt/diff 0。`b124878a1` 仅改 `local_cli.rs`；独立临时测试已
删除。

## 最终复测（a3990293e，已验证）

`fix: report drained CLI hangs as timeouts` 将“因 pipe 被子孙持有而被迫杀进程组”
的 drain 标记为 timeout，不再伪装成功。独立复测全部通过：

1. `sleep 3 & printf 'started\n'; exit 0` + timeoutSecs=1：返回
   `Err(AiError::Timeout(1))`，约 650–900ms，后台 sleep PID 消失。
2. 主进程退出 + background sleep 30 持有 stdout + timeoutSecs=30：返回
   `Err(AiError::Timeout(30))`，<5s，后台 PID 消失。
3. stream 变体：已收到 `started\n` chunk 后仍以 Timeout 终止；无 done chunk；
   `stream_complete()` 返回 Err。
4. cancel during drain：快速 Cancelled，孤儿清理；自然 EOF 的
   alpha/beta/gamma 完整 Ok；非 0/缺失/早取消/stderr 脱敏/敏感 env/cwd 不回归。
5. 全量复跑：datazen ai 1677、ai+workflow+wapps 1743、mcp 1747、desktop
   1405/10 ignored、server 361、local_cli 22、T23 定向前端 20、全量前端
   8234/8 既有环境失败、映射 typecheck OK、fmt/diff 0。
