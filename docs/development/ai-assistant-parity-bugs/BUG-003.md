# BUG-003 T04 query_readonly/sample_rows 在无绑定连接时默认放行任意连接

- 关联任务：T04 只读查询与采样工具
- 被测提交：`e7f37e78e8d9a9aef72245b928a3e9def18f5edf`
- 严重度：阻塞 T04 验收（连接限制在无 `connection_id` 的 Agent 会话中 fail-open）
- 状态：未修复

## 现象

`AiToolContext.allowed_connection_id` 为 `None` 时，`query_readonly` / `sample_rows` 不会拒绝任何 `connection_id`，而是直接执行到宿主：

```rust
// crates/datazen/src/ai/application/tools.rs
fn allowed_connection_id<'a>(ctx: &AiToolContext, requested: &'a str) -> Result<&'a str, String> {
    let requested = requested.trim();
    if requested.is_empty() {
        return Err("connection_id is required".into());
    }
    if let Some(allowed) = ctx.allowed_connection_id.as_deref() {
        if requested != allowed {
            return Err(format!(
                "connection_id '{requested}' is not allowed; the current session is bound to '{allowed}'"
            ));
        }
    }
    Ok(requested) // None -> 任意 connection_id 放行
}
```

`run_chat_session` 直接把可选的会话连接写入上下文：

```rust
let tool_context = AiToolContext {
    allowed_connection_id: input.connection_id.clone(), // Option<String>
    max_sample_rows: env.gate.max_sample_rows,
};
```

因此只要会话没有持久化 `connection_id`，限制就是 fail-open。当前至少有两条真实路径会走到这里：

1. **Workflow 生成会话（正常 UI 路径）**：`WorkflowChatPanel` 的 `sendWorkflowChatMessage` 不传 `connectionId`；后端 `ai_chat` 对 `scenario=workflow_generate` 默认 `Agent`（T03 收口），T04 又给所有 Agent 挂上 `agent_db_tool_definitions()`（含 `query_readonly`/`sample_rows`）。此时 `allowed_connection_id = None`，模型可以拿 prompt 里列出的任意连接 id 调 `query_readonly` / `sample_rows`，宿主 `execute_target` 会按该 id 执行。
2. **任何未绑定连接的 Agent chat**：`AiChatPanel` 的 `connectionId` 是可选 prop，`ChatSessionInput.connection_id` 也是 `Option`；无连接时同样变成不限制。

另外，`run_sql_generation_session` 使用的是 `AiToolContext::default()`（`allowed_connection_id: None`）。SQL 生成虽只声明元数据工具，但 T03 的未声明 tool_call 执行风险仍在（`run_streaming_tool_loop` 对 `classify_tool` 命中的 DB 调用不核对请求工具面），因此模型若硬发 `query_readonly`/`sample_rows`，也会以“任意连接”执行。T04 没有声称解决 T03 风险，但默认 ctx 让该风险的后果扩大到真实 SQL 读取。

## 复现

- UI：打开 Workflows，不选连接（或选一个连接但请求不带 `connectionId`），发送任意生成请求；请求为 `scenario=workflow_generate, agentMode=agent`，不含 `connectionId`，工具面含 `query_readonly`/`sample_rows`。模型给出 `{"connection_id":"<另一条已保存连接>","sql":"SELECT 1"}` 时不会被拒绝。
- 代码级：`execute_db_tool(host, &AiToolContext::default(), catalog, scope, tool("query_readonly", r#"{"connection_id":"other","sql":"SELECT 1"}"#))` 会进入 `db_tools::query_readonly`，`allowed_connection_id` 返回 `Ok("other")`，`TestDbHost` 会记录到一次 `query` 执行；`sample_rows` 同理。

## 期望

- `query_readonly` / `sample_rows` 必须 fail closed：`allowed_connection_id` 为 `None` 时应拒绝（无当前连接即无权限），或仅在显式绑定当前连接时暴露这两个工具。
- 若 Workflow 生成确实需要跨连接读取，应显式建模 allowlist（所有允许的连接 id），而不是用 `None` 表示“不限制”；同时测试应覆盖“无绑定连接”的拒绝路径。
- SQL 生成的 `AiToolContext` 应绑定到当前连接（或至少拒绝未声明的 query/sample 调用），不要用默认 `None` 放行。

## 测试缺口

- `crates/datazen/src/ai/application/tools_tests.rs` 的跨连接拒绝用例使用 `AiToolContext { allowed_connection_id: Some("conn-1") }`，没有 `None` 用例。
- 宿主集成测试 `execute_db_tool_query_readonly_reads_rows_on_current_connection` / `execute_db_tool_sample_rows_quotes_and_limits` 也使用 `Some(...)`；旧元数据测试用 `AiToolContext::default()`，但元数据工具不读 ctx，所以没有暴露该路径。
- 没有一条端到端测试从 `ai_chat(workflow_generate, agent, connection_id=None)` 经 tool loop 执行 query/sample，因此该 fail-open 未被覆盖。
