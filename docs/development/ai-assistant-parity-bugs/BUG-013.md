# BUG-013 T15 旧 localStorage 会话迁移到 AppDb 后，当前 connectionId 会话无法恢复

- 关联任务：T15 会话持久化、导出、提示历史
- 被测提交：`00a4b6554`（`feat: persist AI chat sessions in AppDb`）
- 严重度：阻塞 T15 验收（旧会话数据在 UI 中不可达，迁移成功提示失真）
- 修复提交：`2abd45cc1`（`fix: bind legacy AI sessions to connection scope`）
- 状态：已验证（`2abd45cc1`）

## 结论

T15 的 AppDb、IPC、状态保留、导出和 UI 主体验证通过，但旧 `datazen.aiSessions.v1` 数据的 key 旋转没有闭环：

- 旧版本 AI Chat 调用 `initChatSession(dbSessionId, database)`，旧 key 是 `dbSessionId::database`；
- T02 后 UI 改为 `computeSessionKey(connectionId, dbSessionId, database)`，当前 key 是 `connectionId::database`；
- `migrateLocalSessionsToBackend()` 把旧 key 原样写入 `session_key`/`connection_id`（`sessions.ts:375-396`）；
- `restoreChatSession(currentKey, currentScope)` 只按当前 key list（`sessions.ts:351-356`、`424-445`），因此看不到旧 key 的已迁移行；
- 迁移后立即写入 `datazen.aiSessions.v1.migratedAt`（`sessions.ts:400`），下次启动不会重试。

结果是 UI 显示“已迁移 N 个旧版本地会话”，但当前连接会话仍为空；旧消息留在 AppDb 的旧 key 下，没有发出查询/导出入口。

## 独立复现

临时 Vitest（已删除）使用旧 key `db-sess::db`、当前 scope `connectionId=conn-1`：

- `migrateLocalSessionsToBackend` 成功，`migrationSuccess=1`，marker 已写；
- 按 `conn-1::db` 调用 `restoreChatSession`，`sessionsList` 只返回新 key 的行（旧行 key 不同，模拟后端过滤）；
- 断言 `restored.session.messages` 为空，实际通过。

复现命令（当时）：

```bash
pnpm vitest run packages/frontend/src/stores/ai/__tests__/t15-retest-migration.test.ts
# 1 passed；断言 migrationSuccess=1 且 restored.session.messages=[]
```

## 影响

- 升级用户的旧会话不能从 UI 导航或恢复，和“旧 localStorage 数据可迁移”验收不符。
- 迁移成功计数会误报成功；用户无法区分“数据已迁移”与“当前连接没有会话”。
- 旧 localStorage 原始 key 仍保留，但 marker 阻止再次迁移；只能人工清 marker/查 AppDb 恢复。

## 修复方向（仅记录，不在本次测试修改）

1. 迁移旧 `dbSessionId::db` 时，如果当前 scope 有 `connectionId` 且 database 匹配，按当前 `connectionId` 重绑（保留原 id/消息），并避免跨连接误绑；或
2. 迁移后 restore 在精确 key 无结果时，按当前 connection/database 查找可识别的 legacy key 并做一次别名迁移；或
3. 在 backend list 增加受控的“未绑定 legacy key”查询入口，由前端完成别名确认，而不是静默标记迁移完成。

必须补测试：旧 key + 新 connectionId scope、迁移后重开仍能看到旧消息、不同 connection 不串。

## 修复验证（`2abd45cc1`）

修复仅改 2 个文件，均在 T15 范围内：

- `packages/frontend/src/stores/ai/sessions.ts`
- `packages/frontend/src/stores/ai/__tests__/sessions.backend.test.ts`

核心改动：

- `legacyTargetKey` 在迁移时通过 active connection store 把旧 `dbSessionId::database` 重绑为当前 `connectionId::database`；没有 active map 时仍保留旧 key，等待恢复时绑定。
- `findLegacyDetailForScope` 按旧 key + database 在 AppDb 查找 legacy 行，确认 database 和 connection 归属后，用同一个 legacy id 写回新 key；不新增第二行。
- `restoreChatSession` 和 `listChatSessions` 在精确 key 无行时调用 legacy 查找并绑定；绑定失败设置可见错误，下一次加载仍可重试。
- 迁移 marker 只在整批迁移成功后写；失败时保留旧 localStorage 和 marker 缺失，重试仍会写入。
- 新增 5 个临时/正式测试覆盖：list 先于 restore、active map 直接重绑、旧 key 恢复消息及 cancelled、重开不重复、无 dbSessionId 时从 active map 解析、跨 connection/database 不误绑。

独立复测（临时测试已删除，2 tests 通过）：

- 旧 key `db-sess::db` + 当前 `conn-1::db`：迁移后消息、`complete`/`cancelled`/`failed`、消息 createdAt、`memoryUsed` 元数据均完整；重开同一 scope 不产生重复行。
- 迁移首次写入失败时 marker 为空；第二次成功迁移后才写 marker，旧数据仍可重试。
