# DataZen UI/UX 独立截图审查（2026-09-01）

## 1. 审查方法与覆盖范围

本审查只以 `e2e/screenshots/uiux-review/` 下的 30 张截图为证据，逐张放大查看；未读取、引用或修改任何既有 UI/UX review。结论关注截图能够直接呈现的信息架构、导航、视觉层级、密度与布局、反馈与状态、安全操作、可访问性、一致性和国际化。

审查采用以下原则：

- 先记录可见事实，再给出影响判断与建议；对交互后续步骤、悬停提示、键盘行为、确认弹窗等截图不可见内容，不推断为“必然缺失”。
- P0 表示可能让用户在错误对象上执行操作、误读数据，或在高风险动作前缺少足够可见上下文；P1 表示显著影响任务成功率、可理解性或可访问性；P2 表示一致性、效率与完成度优化。
- 同一截图可能同时展示优点与问题。现有界面整体暗色视觉基调一致，主按钮、选中态和向导步骤通常可辨，部分运行结果也给出了耗时、行数和成功状态，这些应在改造中保留。

覆盖文件：

- `00-welcome.png` 至 `29-new-connection.png`，共 30 张。
- 包含欢迎页、主工作区、SQL/数据/结构编辑、图表、AI、工作流、Redis、ER、备份、设置、仪表盘、插件、服务器状态、进程、数据同步、结构差异、数据传输和新建连接。
- 截图同时包含中文主界面与三个英文独立工具窗口，分辨率从 1280×820 到 2560×1640 不等。

## 2. 跨页面共性问题

### 2.1 当前操作对象的表达不够可靠

连接、数据库、表、Redis DB、查询标签页和独立工具都可能成为“当前上下文”，但它们分别散落在窗口标题、顶部标签、数据库下拉框、左树和底部状态栏中。标签名又经常截断为相似文本，用户需要在多个位置拼接判断当前目标。

最明显的可见冲突是 `15-redis.png`：顶部标签显示 `db5 · db5`，页面摘要也写 `db5`，底部状态栏却写 `db0`。在数据库工具中，这不是单纯文案问题，而是可能导致用户对真实执行目标失去信任。

### 2.2 全局上下文菜单疑似跨页面残留或语义复用错误

`09-ai-more.png`、`20-security.png` 的设置页上浮着“打开表 / 新建查询 / 复制名称 / 复制 DDL”菜单；`15-redis.png` 也出现相同菜单。菜单与当前页面或 Redis 对象语义不一致，并遮挡内容。无论原因是导航后未关闭，还是复用了错误菜单，这都会造成焦点、作用域和动作目标不清。

### 2.3 导航范式割裂

主工作区使用无文字的窄图标栏、连接树和顶部标签；设置页改用完整文字侧栏；工作流拥有自己的双栏导航；数据同步、结构差异和数据传输又是独立窗口/向导。各范式内部尚可理解，但跨范式缺少统一的“当前位置、返回何处、当前对象”表达。主图标栏仅靠图形区分数据库、工作流、仪表盘和插件，新用户学习成本高。

### 2.4 密度在“过密”和“大面积空白”之间摆动

SQL/图表、服务器仪表盘、Dashboard 等页面同时叠加窗口工具栏、标签栏、编辑器工具栏、结果工具栏和卡片工具栏，许多图标尺寸小、间距近。相反，主空状态、连接首页、工作流未运行页、插件空状态和 Data Sync 初始页留下大量未承载任务信息的空间。建议建立紧凑、标准、宽松三档密度规范，并把空白用于下一步引导、最近任务或上下文摘要。

### 2.5 图标按钮过多，层级与可发现性不足

刷新、导入、导出、历史、收藏、AI、面板开关、图表类型、编辑和删除大量使用图标按钮。截图无法确认是否有 tooltip，但静态状态下多个图标形状相近，且主次动作并未稳定区分。Dashboard 卡片尤为明显：每张卡右上角都有一排小图标，删除图标与普通调整动作距离很近。

### 2.6 低对比度、颜色依赖与小字号影响可访问性

暗色主题中，次要文字、占位符、禁用控件、空状态和状态栏常使用偏灰蓝色，部分文本与背景对比很低。成功、连接、类别、类型和告警又较依赖绿/蓝/黄/红颜色；例如工作流成功、数据库连接、Redis 类型和图表图例并非都提供同等强度的文本/形状冗余。应以 WCAG 2.2 AA 为目标校验正文、辅助文本、图标、边框、焦点环和图表颜色。

### 2.7 中英文及面向实现的术语混杂

中文界面中出现 `Workflows`、`Safe Mode`、`Prompt 管理`、`MCP Server`、`Workspace`、`Token 数`、英文错误消息和 camelCase 图例；备份页直接显示 `--routines`、`--triggers`。三个独立工具窗口则完全是英文。数据库名、SQL 和协议名应保留原文，但产品动作、状态、说明和错误应走统一 i18n，并避免把内部类型或命令行参数直接暴露为主要文案。

### 2.8 高风险动作缺少统一的可见安全层级

截图中可见结构保存、Redis 批量删除、进程终止、历史清理、Dashboard 删除、工作流执行、备份、同步和传输等动作，但确认对象、影响范围、预览、回滚/撤销和运行后审计的表达不一致。部分页面已有好的基础：结构编辑提供“预览 SQL”，数据传输和结构差异有步骤条，工作流结果显示耗时与行数。建议把这些能力抽象为统一的“目标摘要 → 影响预览 → 明确确认 → 进度 → 可追溯结果”模式。

### 2.9 数据可视化默认值可能造成误读

`02-query-chart.png` 和 `10-chart-types.png` 把数量级差异很大的 `total_amount` 与 `total_quantity` 放在同一 Y 轴。折线或柱子的相对高度容易被理解为可直接比较，而轴刻度又出现 `6310 / 708 / 79.4 / 8.9 / 1` 这类不直观序列。系统应在量纲或数量级差异显著时提示、自动分轴，或要求用户选择归一化方式。

## 3. 按优先级排序的建议

### P0：立即处理

#### P0-1 建立单一、不可冲突的执行上下文

涉及截图：`03-ai-nl2sql.png`、`06-ai-explain.png`、`07-ai-chat.png`、`15-redis.png`、`17-sql-editor.png`、`24-server-status.png`、`25-processes.png`。

建议：

- 为所有可执行页面提供固定的上下文条，完整显示“连接 → 数据库/Redis DB → Schema → 对象”，不要只依赖截断标签和底部状态栏。
- Redis 页面首先修复 `db5` 与 `db0` 的可见冲突，并加入自动化断言：标签、页面摘要、执行请求和状态栏必须来自同一上下文。
- 数据库下拉项不要仅显示一串相似的 `datazen_...`；至少同时显示连接名、完整数据库名，并为当前项提供可复制的完整值。
- 执行动作的确认或结果中重复目标上下文，避免用户在切换标签/连接后沿用旧目标。

验收重点：切换连接、数据库、标签页和 Redis DB 后，所有可见上下文与实际请求一致；截断文本不应成为唯一辨识方式。

#### P0-2 修复跨页面菜单残留和错误动作作用域

涉及截图：`09-ai-more.png`、`15-redis.png`、`20-security.png`。

建议：

- 路由/页面/窗口焦点变化时强制关闭上下文菜单；菜单锚点卸载后不得继续存在。
- 菜单命令必须绑定创建菜单时的类型化对象，而不是读取可能已变化的“当前选中项”。
- Redis 对象不要呈现“打开表、复制 DDL”等关系型数据库动作；设置页不得保留任何数据库对象菜单。
- 加 E2E：在连接树打开菜单后导航到设置、Redis、工作流，验证菜单关闭且快捷键不会作用到旧对象。

验收重点：任何动作都能在菜单内或确认层看到目标对象；离开目标页面后旧菜单与旧快捷键失效。

#### P0-3 为高风险操作统一加入目标、影响和恢复信息

涉及截图：`12-workflow-crossdb.png`、`18-data-editor.png`、`20-security.png`、`21-dashboard.png`、`23-table-structure.png`、`25-processes.png`、`26-data-sync-en.png`、`27-schema-diff-en.png`、`28-data-transfer-en.png`。

建议：

- 工作流“执行”前展示每一步的连接/数据库、只读或写入属性、预估影响；跨库工作流尤其需要明确源/目标。
- 结构“保存更改”前默认进入 SQL/diff 预览，并标出可能锁表、丢数据或不可回滚的语句；不要让“预览 SQL”只是容易跳过的并列次按钮。
- 进程“终止”确认中显示 PID、用户、数据库、客户端、已运行时间，并防止误终止当前管理会话。
- 同步/传输/部署前提供最终预览、写入模式、插入/更新/删除数量、事务与失败策略；对 Delete、Drop、覆盖和清理使用更强的二次确认。
- 所有执行结果保留可复制日志、失败明细、重试范围以及可行时的撤销/恢复入口。

说明：截图只显示部分流程，不能确认后续是否已有确认页。本建议要求的是在用户按下当前可见触发按钮前后形成一致、可验证的安全闭环。

### P1：下一迭代处理

#### P1-1 防止图表默认配置误导

涉及截图：`02-query-chart.png`、`10-chart-types.png`、`11-chart-export.png`、`21-dashboard.png`、`24-server-status.png`。

- 检测多指标的单位和数量级；差异显著时默认双轴、分面或阻止直接叠加并解释原因。
- 显示清晰的轴标题、单位、数据范围和 tooltip；服务会话图的非线性刻度要明确说明。
- 图例除颜色外增加线型、点型或直接标签；提供色觉安全配色。
- 导出前让用户确认尺寸、格式、背景、数据范围和是否包含标题/图例。`11-chart-export.png` 只看得到低强调的导出图标，无法确认导出配置流程。

#### P1-2 给 AI 结果增加“依据—解释—确认”链路

涉及截图：`03-ai-nl2sql.png`、`05-ai-diagnosis.png`、`06-ai-explain.png`、`07-ai-chat.png`、`08-ai-filter.png`、`09-ai-more.png`。

- NL2SQL 在写入编辑器前展示目标库、涉及表、生成 SQL 和只读/写入风险；保留原输入以便回看。
- AI 诊断的“应用修正”应展示 diff、替换范围和撤销入口，明确是修改编辑器文本还是立即执行。
- AI 筛选必须把自然语言中的“状态已发货”映射依据显示出来。截图中被解析为 `category eq 已发货`，与用户措辞存在明显语义偏差，应要求确认或提供字段候选，而不是只显示“已解析 2 个筛选条件”。
- AI Chat 回答数据库问题时显示所依据的连接、库、表、查询/工具调用和时间；如果尚未查询数据，应明确标注“未执行查询”。
- API Key 区域增加可见/隐藏控制、存储位置与加密说明、验证结果和错误恢复；本地 AI 上下文路径应说明将向模型发送什么内容。

#### P1-3 统一导航、标签和返回路径

涉及截图：`01-main-window.png`、`04-workflow.png`、`12-workflow-crossdb.png`、`13-workflow-run.png`、`14-multidb.png`、`22-plugins.png`、`26-data-sync-en.png`、`27-schema-diff-en.png`、`28-data-transfer-en.png`。

- 主图标栏支持常驻文字、可展开模式或至少稳定的选中标签；不要把 tooltip 作为唯一识别方式。
- 标签页标题优先显示对象名，连接信息放次级位置；相同工作流的“定义”和“运行记录”应使用明确后缀，避免两个同名标签只靠图标区分。
- 独立工具窗口统一提供来源上下文、关闭/返回目的地和可恢复草稿提示。
- 空状态直接给出主要下一步；连接首页可增加最近 Panel，工作流空白区可显示步骤摘要，插件空状态可在中心区域复用安装 CTA。

#### P1-4 提高可读性和键盘/无障碍基础质量

涉及全部截图，尤见 `00-welcome.png`、`01-main-window.png`、`04-workflow.png`、`09-ai-more.png`、`21-dashboard.png`、`22-plugins.png`。

- 依据 WCAG 2.2 AA 重新校验次要文字、placeholder、边框、禁用态和状态栏；重要说明不使用当前偏低对比度灰蓝色。
- 图标按钮提供可见名称或可展开标签，并保证至少 32×32 px 的命中区；危险按钮与普通按钮拉开间距。
- 键盘焦点环在所有交互控件上保持一致。`28-data-transfer-en.png` 和 `29-new-connection.png` 已有较明显焦点态，可作为统一基线。
- 状态不要只靠颜色：增加图标形状和文本；图表提供数据表或可访问摘要。
- 对树、表格、标签页、步骤条、菜单和对话框补做屏幕阅读器名称、顺序及焦点回收测试。

#### P1-5 统一错误、空状态与运行反馈

涉及截图：`05-ai-diagnosis.png`、`08-ai-filter.png`、`12-workflow-crossdb.png`、`13-workflow-run.png`、`21-dashboard.png`、`25-processes.png`、`26-data-sync-en.png`。

- 错误采用“发生了什么、影响什么、用户能做什么、技术详情”四层结构；技术原文可展开，不直接塞进主表格或首层横幅。
- `25-processes.png` 中 `<insufficient privilege: ...>` 不应伪装成查询值；应显示权限受限状态，并解释哪些列不可见以及如何补权。
- 空结果要区分“查询成功但 0 行”“尚未执行”“筛选后为空”“权限不足”和“加载失败”。
- 长任务显示阶段、已处理数量、预计剩余时间、取消与后台运行；完成后提供带时间和目标的持久结果。

### P2：持续优化

#### P2-1 收敛工具栏和密度

- 将低频动作放入带文字的“更多”菜单，高频主动作保持 1–3 个；减少窗口、标签、编辑器、结果和卡片五层工具栏同时出现。
- 支持用户选择密度，表格和树默认用标准密度；小屏优先保证对象名、主动作与状态完整可见。
- 使用空白呈现最近任务、帮助和上下文摘要，而不是只放一条低对比度提示。

#### P2-2 统一文案与国际化

- 产品文案全部走 i18n；中文界面统一翻译 `Workflows`、`Safe Mode`、`Workspace`、运行状态和错误模板。
- 把 `--routines`、`--triggers`、`Varchar(Some(32))`、`Timestamp(tz=true)` 等实现表达转换为面向用户的名称；需要时在“技术详情”显示原值。
- 术语表统一“连接/端点、数据库/DB、执行/运行、结构/Schema、同步/传输/差异”，并给 Data Sync、Schema Diff、Data Transfer 明确边界说明。
- 检查长英文、长中文、数据库对象名和翻译膨胀时的布局，不依赖省略号隐藏辨识信息。

#### P2-3 统一空状态、卡片和选择控件

- 欢迎页功能卡看起来可点击，但实际主 CTA 位于下方；若卡片可操作则增加悬停/焦点和动词，若仅介绍则降低按钮感。
- 单选方案卡、筛选 chip、选中行、当前标签和当前步骤采用一致的边框、背景、图标与文字组合。
- 表单明确必填、可选、默认值来源和验证状态；数字输入补充单位和合理范围。

## 4. 页面级发现

### [`00-welcome.png`](../../e2e/screenshots/uiux-review/00-welcome.png)

- 优点：品牌、价值主张、四项核心能力和首个 CTA 的层级清楚，首次使用路径明确。
- 问题：四张功能卡的视觉重量和可点击感强于其实际动作语义；说明文字对比度偏低，底部导入来源长句也较难读。
- 建议：明确卡片是否可操作；将“创建连接”和“导入连接”与对应能力卡关联，并提高辅助文字对比度。

### [`01-main-window.png`](../../e2e/screenshots/uiux-review/01-main-window.png)

- 可见状态：已有三条连接，但中间只提示“请在左侧选择一个连接”。
- 问题：最左图标栏与连接标题栏几乎全是无文字图标；空白区域没有最近连接、快捷任务或连接状态摘要。
- 建议：为导航提供可展开标签，把中间空白转为最近打开、失败连接和常用动作入口。

### [`02-query-chart.png`](../../e2e/screenshots/uiux-review/02-query-chart.png)

- 优点：编辑器、表格/图表切换、字段映射和连接状态都在同屏，查询到可视化链路短。
- 问题：页面叠加多层工具栏；多个相似标签被截断；金额与数量共用不直观的单轴，容易误读。
- 建议：突出查询、结果、图表三层，减少低频图标；提供单位/数量级检测和双轴或分面建议。

### [`03-ai-nl2sql.png`](../../e2e/screenshots/uiux-review/03-ai-nl2sql.png)

- 可见状态：自然语言输入位于编辑器上方，目标数据库下拉展开，按钮为“生成 SQL”。
- 问题：数据库名大量截断且缺少连接名；中英混合的 `Safe Mode` 位于另一工具栏，AI 生成的目标与安全属性关联不强。
- 建议：在 AI 输入区直接显示完整执行上下文，并在生成后先给 SQL、涉及对象与风险摘要。

### [`04-workflow.png`](../../e2e/screenshots/uiux-review/04-workflow.png)

- 优点：步骤成功、总耗时、单步耗时、行数和 SQL 均可见，运行反馈较完整。
- 问题：左侧中英文混排且描述被截断；主内容下半部大面积空白；“添加到看板”与“执行”并列但语义层级不清。

## 5. 建议落地顺序

### 第一阶段：消除错误目标与动作作用域风险

1. 修复 Redis `db5/db0` 上下文不一致，并建立跨标签/连接/数据库的一致性断言。
2. 修复上下文菜单跨页面残留、错误对象类型动作和旧快捷键作用域。
3. 为结构保存、跨库工作流、进程终止、同步/传输/部署建立统一的目标与影响确认组件。

### 第二阶段：保证数据与 AI 结果可被正确理解

1. 修正图表多指标量纲/数量级默认策略、轴标题、单位和色觉安全。
2. 为 AI 生成 SQL、诊断修正、自然语言筛选和问答增加依据、置信/歧义、预览与撤销。
3. 统一错误分类、空结果和权限不足状态，避免技术错误伪装成业务数据。

### 第三阶段：统一信息架构与反馈

1. 定义跨主工作区、设置、工作流和独立向导的统一上下文条、返回路径与标签命名。
2. 收敛工具栏和图标按钮，补全运行中、完成、失败、取消、重试和审计反馈。
3. 优化连接首页、工作流、插件与同步初始页的空状态，把空白用于最近项和下一步。

### 第四阶段：可访问性、国际化和视觉系统收口

1. 完成 WCAG 2.2 AA 对比度、键盘、焦点、屏幕阅读器和非颜色状态测试。
2. 统一中文/英文资源、用户术语和内部技术表达；验证长文本与对象名。
3. 建立密度、卡片、表单、危险动作、空状态、图表和独立窗口的设计规范与视觉回归基线。

## 6. 仅由截图无法确认的事项

以下内容不能因截图中“没有出现”就判定产品一定缺失，需要通过交互检查、代码审查或可访问性测试确认：

- 图标是否都有 tooltip、无障碍名称、足够命中区和快捷键提示。
- Tab 顺序、焦点陷阱、菜单关闭后的焦点回收、Esc 行为和屏幕阅读器播报。
- 删除、终止、清理、结构保存、同步、传输、部署、插件安装是否在后续步骤已有确认、权限预览、回滚或审计。
- SQL 执行与 AI 应用是否会自动运行，Safe Mode 的实际保护范围，以及自动提交与事务的真实行为。
- AI 是否实际调用数据库工具、是否把 schema/数据/本地上下文发往第三方、是否脱敏，以及 API Key 的真实存储方式。
- 图表 tooltip、缩放、键盘访问、导出对话框和导出结果质量。
- 响应式布局、缩放 125%/150%/200%、小窗口、超长对象名和多语言膨胀表现。
- 加载、超时、离线、断线重连、取消、部分失败、大数据量和空数据的动态状态。
- 色值的精确对比度、色觉缺陷可辨识度与系统高对比度/减少动态效果支持。
- `18-data-editor.png` 与 `23-table-structure.png` 内容相同的原因：可能是截图命名错误、用例导航错误或确实复用了同一页面，需回看 E2E 步骤确认。
- `09-ai-more.png`、`15-redis.png`、`20-security.png` 中菜单是产品真实残留、测试刻意展示，还是截图时的临时状态；无论来源，都应补充跨页面生命周期测试。

## 7. 结论

DataZen 已具备一致的暗色基调、较清楚的主按钮与选中态、有效的工作流运行信息，以及结构差异/数据传输的向导基础。当前最值得优先投入的是“可信操作上下文”：让用户始终知道正在对哪个连接、数据库和对象做什么，任何菜单与动作都不能越过其作用域。完成这一层后，再处理图表语义、AI 可解释性、错误反馈、导航收敛、可访问性和国际化，能以较低返工成本提升专业数据库工具最关键的安全感与可控性。
