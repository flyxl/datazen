## 1. 背景与目标

用户需要按自己的时区阅读数据库时间，并将明确表示 Unix 时间的 BIGINT 列显示为日期时间。格式应支持全局默认、规则匹配与表列覆盖，且不改变数据库原值。

当前网格的 `CellRenderer` 使用 `formatTimestamp`，右侧行详情 `DetailPanel` 使用另一条展示与编辑路径。时间格式设置必须同时覆盖两者，不能只改网格。

当前带时区文本归一化为 UTC；无时区文本已经原样保留。因此本需求不是把所有日期强行转为带时区时间。

目标：

1. 用户主动开启时间展示能力，旧配置与默认显示行为保持兼容。
2. cell 与右侧 aside 对同一字段使用相同解释、时区、精度与规则来源。
3. 用户能明确指定 BIGINT 为 Unix 秒或毫秒，预览后保存。
4. 建立可追加 URL、图片展示器的贡献机制；首版只交付时间展示器。
5. Desktop 与 Web 共享展示逻辑，配置均能保存、恢复并按用户隔离。

## 2. 范围

### 首版必须交付

- 通用展示贡献点 `data.valuePresentation` 与时间展示器 `datazen.timestamp`。
- 时间展示总开关，默认关闭；安装扩展不自动启用。
- `iso`、`iso-tz`、`locale` 三种格式。
- 本地、UTC、指定 IANA 显示时区。
- 全局默认、全局规则、表列覆盖三个配置层级。
- 网格表头和 aside 字段菜单共用的「显示方式…」面板。
- Unix 秒/毫秒的显式配置、原值与格式化预览。
- 保存恢复、跨窗口更新、扩展停用回退、完整连续旅程测试。

### 本轮不交付

- URL、图片展示器及其网络加载、点击打开能力。
- 任意自定义日期格式字符串。
- 自动把疑似时间的 BIGINT 改成日期显示。
- 按显示文本排序、过滤、写回；复制显示值与按显示值导出。
- 无来源查询列的持久化表级覆盖。
- 普通 Wapp 注入主表格 DOM。

## 3. 用户入口

### 3.1 设置 → 表格数据 → 时间显示

提供：启用开关、默认格式、显示时区、实时预览、可折叠规则列表。

全局默认只自动应用于适用的原生时间值。开启功能不会将所有数字或字符串尝试转换为时间。

规则可新增、编辑、删除、启停和调整顺序。匹配条件包括连接、数据库、schema/namespace、表名、列名和数据库类型名；同一规则内条件为 AND，列表从上到下首条命中生效。连接与数据库等可采用精确选择，名称模式支持受限正则。

例：BIGINT 且列名匹配 `^(created_at|updated_at)$` → Unix 毫秒 → 带时区 ISO → Asia/Shanghai。

规则编辑显示当前样本的命中结果及预览。没有样本时仍允许配置，不编造真实数据。非法表达式或配置禁止保存，并就地说明原因。

### 3.2 表头右键 / aside 字段菜单 → 显示方式…

两个入口打开相同面板，编辑同一份列配置：

- 跟随规则：清除本列显式覆盖。
- 原始值：跳过自定义展示，不继续匹配全局规则。
- 时间：选择时间来源、格式和时区。

BIGINT 选择时间后，必须明确指定 Unix 秒或毫秒，不以位数自动决定。面板同时显示原值与结果，例如：

```text
原值：1705316400000
时间来源：Unix 毫秒
显示格式：带时区 ISO
显示时区：Asia/Shanghai
预览：2024-01-15T19:00:00+08:00
```

时间展示总开关关闭时，允许编辑与保存列配置，但明确提示「尚未启用时间显示」，提供显式开启操作，不静默打开总开关。

没有可靠表列来源的查询结果禁用「保存为表列覆盖」，说明原因；仍可使用全局默认和仅依赖已知元数据的规则。不能从 SQL 别名猜表来源。

### 3.3 生效反馈

- 时间来源为 Unix 时显示「Unix 秒 / Unix 毫秒」标记。
- 提示中可以查看原值和配置来源：全局默认、规则名称、列覆盖。
- cell 可截断，aside 可换行，完整时间文本一致。
- 不支持或无法解析的值显示原值，并提供简短原因；不使整列或整表消失。
- 展示器缺失时保留配置，并在配置面板提示所需扩展不可用。

## 4. 时间语义与优先级

时间总开关是能力门控；关闭时回到既有展示。开启后：表列覆盖 > 全局规则 > 全局默认。

「原始值」表示绕过自定义展示、使用宿主既有默认行为，不承诺对所有原生类型进行逐字节展示；例如原有带时区时间的 UTC 归一化仍属于默认行为。原始数据库值始终可查看。

规则命中后不因某一行解析失败继续寻找低优先级规则，防止同一列逐行切换秒/毫秒解释。

- 带时区时间表示确定时刻，可转换显示时区。
- 无时区 DATETIME 是墙上时间，默认保留；需要转换时必须显式指定源时区。
- DATE、TIME 默认保留，不补日期或时区；首版不提供其独立格式重排。
- 指定源时区遇到夏令时重复或不存在时刻时拒绝猜测，保留原值并说明歧义。
- `iso` 对确定时刻输出 UTC ISO；`iso-tz` 按目标时区输出实际偏移；`locale` 按用户语言及目标时区输出。
- 原生时间输出应保留可支持的源精度，不得悄悄把微秒/纳秒截为毫秒。不支持的精度回退原值并说明原因。
- 数据库已丢失的原始时区信息不能由前端恢复。

校正 Issue 示例：`2026-01-15T14:30:00Z` 转 UTC+8 是 `2026-01-15T22:30:00+08:00`；`1705316400000` 是 2024 年的时间戳。

## 5. 数据与配置约束

- 显示为时间不改变 BIGINT 类型，进入编辑仍使用原始整数。
- 排序、过滤、默认复制、导出和提交继续使用原值。
- NULL 仍为 NULL；0、负 Unix 时间应按有效值处理。
- 不安全整数、非法数字字符串、越界时间不猜测、不截断。
- 列覆盖按当前用户/组织、连接、数据库、namespace、表、列隔离；面板 ID、会话 ID 不能作为持久化身份。
- 未加载完整配置时两处统一使用默认展示；刷新时保留上一份有效配置，不能半更新。
- 保存失败应明确提示，不能显示成已保存；旧配置继续生效。
- 停用扩展时 cell 与 aside 同时回退，重启用后恢复已保存配置。

## 6. 验收标准

1. 新安装或未启用时，现有显示与编辑行为保持不变。
2. 两个入口修改的是同一配置；cell、aside、预览显示结果一致。
3. BIGINT 无显式配置时保持数字；配置 Unix 秒/毫秒后按指定单位展示。
4. 列覆盖优先于规则；「原始值」阻断规则；清除覆盖恢复继承。
5. 规则顺序可调整，禁用规则不参与匹配，错误规则不能保存。
6. 重启恢复配置；不同连接、数据库、schema 的同名表不串配置。
7. 切换选中行、分屏、切换查询结果集时，aside 始终使用正确来源的格式计划。
8. 修改时区、源时区与单位能正确跨日；无时区值不发生隐式漂移。
9. 编辑、复制、排序、过滤、导出仍使用原值；格式变化不产生脏记录。
10. 配置保存失败、扩展缺失、格式化异常均可恢复，不阻断网格交互。
11. Desktop 与 Web 的保存恢复和用户隔离均验证；不能仅凭桌面 extra 字段可保存就宣称双端完成。
12. 注册、停用、重新启用时间贡献后，两处同步更新且无旧缓存残留。

## 7. 交付顺序

1. 统一展示管线、贡献注册、原生时间与全局设置。
2. 列设置入口、Unix 解释、覆盖持久化、aside 一致性。
3. 规则编辑、跨窗口同步、异常恢复与双端完整旅程。

三级配置与测试全部完成后才满足 Issue #32 的完整验收；前三阶段的部分成果不代表 issue 可关闭。
