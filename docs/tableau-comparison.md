# DataZen vs Tableau：功能对比与借鉴分析

> 目的：从 Tableau（全球领先的数据可视化平台）中识别对 DataZen 有价值的功能理念，结合 DataZen 作为**桌面数据库管理工具**的定位，筛选出可行的借鉴方向。

## 一、定位差异

| 维度 | Tableau | DataZen |
|------|---------|---------|
| **核心定位** | BI 分析与可视化平台 | 桌面数据库管理工具 |
| **目标用户** | 业务分析师、数据团队 | 开发者、DBA、数据工程师 |
| **数据连接** | 多源连接 + 数据建模 | 直连数据库（PG/MySQL/SQLite/Redis） |
| **核心价值** | 数据洞察与决策支持 | 数据库操作与查询效率 |
| **部署方式** | Cloud + Server + Desktop | 纯桌面（Tauri） |
| **AI 集成** | Tableau Agent + Pulse + MCP | NL2SQL + 诊断 + 对话 + Skills + MCP |

**关键认知**：DataZen 不应试图成为 Tableau，而是从 Tableau 中提取**适合数据库管理场景**的功能理念。

## 三、值得借鉴的 Tableau 核心理念

### 理念 1：「Show Me」智能推荐

Tableau 的 Show Me 功能根据选中的字段自动推荐最合适的图表类型。DataZen 可以借鉴：

```
用户执行查询 → 分析结果集结构 → 自动推荐
                                    ↓
              ┌─ 1个分类 + 1个数值 → 柱状图
              ├─ 1个时间 + 1个数值 → 折线图  
              ├─ 1个分类 + 1个数值（少量类别）→ 饼图
              ├─ 2个数值 → 散点图
              └─ 纯数值多列 → 表格保持
```

**实现要点**：不需要 Tableau 那么复杂的推荐引擎，基于简单规则 + AI fallback 即可。

### 理念 2：表格与图表的无缝切换

Tableau 的核心体验是表格和图表只是同一份数据的不同视图。DataZen 应该：

- 查询结果区域增加 **表格 | 图表** 切换标签
- 切换时数据不重新加载
- 图表配置记忆（同一查询再次切换不丢失配置）

### 理念 3：对话式分析（Tableau Agent）

Tableau Agent 允许用户在仪表盘上直接用自然语言提问。DataZen 已有的 AI Chat 可以扩展：

```
当前：用户输入自然语言 → AI 生成 SQL → 用户手动执行 → 看表格结果
                                                          
扩展：用户输入自然语言 → AI 生成 SQL + 推荐图表类型 → 自动执行 → 图表+表格
```

### 理念 4：列级统计摘要

Tableau 对每列自动计算统计信息。DataZen 可以在列头右键菜单中加入：

- **数值列**：MIN / MAX / AVG / SUM / COUNT / DISTINCT COUNT
- **文本列**：DISTINCT COUNT / TOP N 值分布
- **时间列**：MIN / MAX / 时间跨度
- **空值统计**：NULL 数量 / 占比

实现方式：后端执行 `SELECT MIN(col), MAX(col), AVG(col), COUNT(DISTINCT col) FROM table`

### 理念 5：可视化查询构建

Tableau 的拖拽构建太重了，但 DataZen 可以实现轻量版：

- **可视化 WHERE 构建器** — 与现有 NlFilter 并列，提供传统下拉式筛选 UI
- **可视化 GROUP BY** — 选择分组字段和聚合函数，自动生成 SQL
- **可视化 ORDER BY** — 查询结果列头可点击排序（客户端排序）

## 四、DataZen 独有优势（Tableau 不具备）

| DataZen 功能 | 说明 |
|-------------|------|
| **直接编辑数据** | 双击单元格直接修改数据库记录，Tableau 只读 |
| **表结构管理** | 创建/修改表、索引、外键，Tableau 无此能力 |
| **SQL 编辑器** | 专业级 SQL 编辑（语法高亮、自动补全），Tableau 有限 |
| **多数据库类型** | Redis KV 操作、SQLite 文件数据库，Tableau 侧重 OLAP |
| **跨库 Skill 工作流** | YAML 定义的自动化跨库操作管道 |
| **MCP Server 模式** | 被其他 AI 工具调用（Cursor / Claude Desktop） |
| **轻量桌面应用** | Tauri 构建，安装包小、启动快，无需服务器 |
| **数据库备份/恢复** | 原生备份还原功能 |
| **数据同步** | 跨库数据迁移（PG ↔ MySQL ↔ SQLite） |

## 五、优先级排序与实施建议

### P1 — 立即可做（增强现有功能，ROI 最高）

| 功能 | 工作量 | 说明 |
|------|--------|------|
| **查询结果导出** | 小 | 复用现有 `exportData.ts`，扩展到查询结果 |
| **查询结果客户端排序** | 小 | DataTable 已有排序 UI，给查询结果也传 `onSort` |
| **列统计摘要** | 中 | 列头右键→统计，后端执行聚合 SQL |
| **手动筛选 UI** | 中 | 与 NlFilter 并列的传统筛选器 |
| **基础图表（柱/线/饼）** | 中 | Recharts + 查询结果标签页 |

### P2 — 近期规划（显著提升体验）

| 功能 | 工作量 | 说明 |
|------|--------|------|
| **图表智能推荐** | 中 | 字段类型规则 + AI fallback |
| **AI 对话生成图表** | 中 | 扩展现有 AI Chat，输出 SQL + 图表配置 |
| **条件格式化** | 小 | 数值列根据值范围着色 |
| **图表导出（PNG/SVG）** | 小 | Recharts 内置支持 |

### P3 — 中期规划（差异化功能）

| 功能 | 工作量 | 说明 |
|------|--------|------|
| **EXPLAIN 执行计划树** | 大 | D3 树状图替换纯文本 EXPLAIN |
| **ER 图** | 大 | 基于外键数据自动生成关系图 |
| **AI 异常检测标注** | 中 | 在图表上标注离群点 |

### P4 — 远期探索（视产品方向决定）

| 功能 | 说明 |
|------|------|
| 仪表盘 | 多图表组合展示，需要布局系统 |
| 数据库监控面板 | 需要后台定时采集 |
| Pulse 式指标流 | 需要持续监控基础设施 |

## 六、总结

**核心结论**：DataZen 应从 Tableau 借鉴的不是它的 BI 平台能力，而是它**让数据更易理解**的设计理念：

1. **可视化是表格的补充，不是替代** — 开发者仍以 SQL + 表格为主，图表用于快速理解分布和趋势
2. **智能推荐降低门槛** — 不要求用户懂图表，根据数据结构自动推荐
3. **AI 是分析的入口** — 自然语言直达可视化结果，而不是中间停在 SQL 上
4. **列级统计是被忽视的高价值功能** — 工程师经常需要快速了解数据分布，这比复杂图表更实用

**DataZen 的差异化路径**：做**开发者友好的数据可视化**，而不是业务分析师的仪表盘工具。保持 SQL-first 的核心，用可视化辅助理解查询结果。
