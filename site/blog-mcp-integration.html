MCP in Practice: Connecting AI Agents to Your Database

From "chat with your data" to "let your agent run your queries" — in one config line.

September 2026 · 8 min read

What is MCP?

The Model Context Protocol (MCP) is a standard for exposing tools, resources, and prompts to AI agents. Think of it as a USB-C port for AI: instead of building a custom integration for every agent, you implement one protocol and any compatible client can connect.

DataZen ships with both an MCP Server (exposing your database to external agents) and an MCP Client (connecting external tools into DataZen's AI chat). This post covers both directions with practical examples.

MCP Server: expose your database to agents

What tools are available?

When DataZen runs as an MCP server, it exposes these tools to any connected agent:

Tool Description
list_connections List all configured database connections
list_tables List tables and views in a connection
describe_table Get column definitions, indexes, and constraints
execute_query Run a SELECT query and return results
explain_query Get the EXPLAIN plan for a query
run_workflow Execute a YAML workflow by name or content

Credentials never leave DataZen. The agent interacts with your database through the server — it never sees raw passwords.

Setup in Claude Desktop

Add this to your Claude Desktop MCP config:

{
  "mcpServers": {
    "datazen": {
      "command": "/path/to/datazen",
      "args": ["--mcp-stdio"]
    }
  }
}

That's it. Restart Claude Desktop, and your agent can now inspect schemas, run queries, and even execute multi-step workflows across databases.

A real example: "Show me the slowest queries"

With Claude connected to DataZen, you can ask:

"List all tables in the orders database, describe the orders table, and find orders from the last 7 days."

The agent will chain list_tables → describe_table → execute_query automatically, using the column types it learned from the schema to write the correct WHERE clause. No manual context injection, no copy-pasting schema dumps.

MCP Client: bring external tools into DataZen

The reverse direction is equally powerful. DataZen can act as an MCP client, connecting to external MCP servers and making their tools available inside the AI chat sidebar.

For example, you could connect:

  • A file system MCP server to let the AI read CSV files for import.
  • A GitHub MCP server to correlate database issues with repository commits.
  • A custom internal API server that the AI can call alongside database queries.

Configure external MCP servers in Settings → AI → MCP Client, and they appear as available tools in the chat sidebar.

The headless mode: --mcp-stdio

DataZen isn't just a desktop app. The --mcp-stdio flag starts a headless MCP server — no GUI, no Tauri, just pure Rust responding to JSON-RPC messages on stdin/stdout.

This opens up server-side use cases:

  • CI/CD pipelines: Let an agent verify schema changes before deployment.
  • ChatOps: Connect a Slack bot to your database through an MCP bridge.
  • Scripting: Pipe agent output into automated database maintenance tasks. 
# Start headless
datazen --mcp-stdio

# Or from a Docker container
docker run -i datazen/datazen --mcp-stdio < config.json

Security model

MCP integration doesn't bypass DataZen's safety model:

  • SQL Guard applies to all queries — including those from the MCP server. If a connection is in Safe Mode, the agent can't run DROP or DELETE without WHERE.
  • Read-only connections stay read-only, even when accessed through MCP.
  • Credentials are encrypted in the OS keychain. The MCP server uses connection IDs, not raw passwords.
  • No file system access. The headless mode can't read or write files — it only communicates via stdio.

What's next

Upcoming MCP enhancements include:

  • Streaming queries for large result sets — the agent gets results incrementally instead of waiting for the full payload.
  • Resource URIs — expose tables and schemas as MCP resources (read-only) alongside tools.
  • Per-tool permissions — fine-grained control over which tools each connected agent can access.
