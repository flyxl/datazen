# Task 10 Report — Pub/Sub backend + UI

**Branch:** `feat/redis-deep-ops-e2-e4`  
**Spec:** §7.1 Pub/Sub  
**Commit message:** `feat(redis): Pub/Sub tab with subscribe and publish`

## Summary

Implemented Redis Pub/Sub as a dedicated connection tab with backend subscription lifecycle, Tauri event streaming, and a full UI panel.

## Backend

| Command | Args | Returns |
|---------|------|---------|
| `pubsub_subscribe` | `connectionId`, `channels[]`, `patterns[]` | `subscriptionId` |
| `pubsub_unsubscribe` | `subscriptionId` | `()` |
| `pubsub_publish` | `connectionId`, `channel`, `message` | `number` (receivers) |

- **`ops_pubsub.rs`**: subscription registry (`Mutex<HashMap>`), validation, dedicated subscribe loop, publish helper.
- **`connect.rs`**: `open_pubsub_connection()` — standalone/cluster use `Client::get_async_pubsub()`; cluster uses first seed node; sentinel resolves master via `Sentinel::async_master_for`.
- **Events:** `redis-pubsub-message` with `{ connectionId, subscriptionId, channel, payload, ts }` (camelCase via serde).
- **Subscribe task:** `tokio::spawn` per subscription; `JoinHandle::abort` on unsubscribe; registry entry removed when task ends.

## Frontend

- **`PubSubPanel.tsx`**: subscribe (channels/patterns), active subscription list, live message table (time/channel/payload), publish form with receiver count.
- **`RedisConnectionView.tsx`**: new **Pub/Sub** tab alongside Items / Console / Monitor.
- Listens to `redis-pubsub-message`; filters by `connectionId`; unsubscribes all on panel unmount.

## Permissions & i18n

- Added `allow-pubsub-subscribe`, `allow-pubsub-unsubscribe`, `allow-pubsub-publish` to `default.toml` + autogenerated TOML (via `build.rs`).
- 22 new `redis.pubsub*` keys in all 10 locale files (en/zh-CN/zh-TW translated; Beta locales mirror English).
