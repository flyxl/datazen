# Locales

All 10 locales (`de` `en` `es` `fr` `ja` `ko` `pt-BR` `ru` `zh-CN` `zh-TW`) are split by **domain** so PRs stay small and low-frequency features can be code-split. `en` is the single translation source of truth.

## Layout

```
locales/
  domains.ts           # EAGER_DOMAINS / LAZY_DOMAINS
  lazyPacks.ts         # dynamic import registry + ensureLocaleDomains() + isDomainLoaded()
  builtinLocales.ts    # ⚠️ GENERATED — do not hand-edit or commit
  fullLocales.ts       # full dict (tests / tooling only)
  <locale>/            # ALL 10 locales: per-domain packs + index.ts (full merge) + eager.ts
  <locale>.ts          # 2-line re-export shim of the full merge (back-compat)
  index.ts             # dictionary registration + public API (lookup delegates to @datazen/ui t)
```

> **Keys go in `<locale>/<domain>.ts`, never in `<locale>.ts`.** The flat `<locale>.ts`
> files are 2-line back-compat shims (`export { default } from './<locale>/index';`);
> adding a key there has no effect. This applies to *every* locale, not just the non-English ones.

> **`builtinLocales.ts` is generated, not tracked.** It is git-ignored and
> regenerated by `scripts/generate-builtin-locales.mjs` (source of truth:
> `src/locales/builtin-locales.json`). Run it explicitly with
> `node scripts/generate-builtin-locales.mjs`, or it runs via `pnpm install`
> (`prepare`) and the CI typecheck step. Never edit or commit that file.

## Lazy domains

| Domain       | Loaded when                                            |
|--------------|--------------------------------------------------------|
| sync         | Migration tools (Data Sync, Schema Diff, Data Transfer)|
| workflows    | Workflow page                                          |
| dashboard    | Dashboard panel                                        |
| mcp          | Settings → MCP sections                                |

```ts
import { useLocaleDomains } from '../hooks/useLocaleDomains';
import { LocaleDomainLoading } from '../components/LocaleDomainLoading';

// inside a feature window: gate the body so it never renders raw keys before
// the lazy pack finishes importing. Call the hook first, then gate after ALL
// hooks (Rules of Hooks) and before any return that uses the lazy domain `t()`.
const localesReady = useLocaleDomains(['sync']);

if (!localesReady) {
  return <LocaleDomainLoading testId="data-sync-locale-loading" />;
}
```

## Adding a key

1. Put it in the matching domain file under `en/<domain>.ts` **only** — during development
   you do not touch the other locales (see the i18n rules in the root `AGENTS.md`).
2. Keep key prefixes stable (`sync.*`, `connWin.*`, …); locate the pack via the table above.
3. Run unit tests (`locales.test.ts` checks en/zh-CN parity on the full dict).
4. Before release: `node scripts/i18n-sync-check.mjs` reports the missing keys for the
   remaining 8 locales; fill them in via the `i18n-sync` skill.
