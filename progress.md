Status: **all gates green.** Two judgment calls escalated below await adjudication.

## Root cause

The P5 refactor split the 1800-line `packages/driver-api/src/traits.rs` into a
`traits/` submodule. That exposed **two independent defects in the guard**, neither of
which is a real breaking change:

1. **A stale rule path.** The `key-value-driver` rule still pointed `file` at
   `traits.rs`, where `KeyValueDriver` now survives only as
   `pub use key_value::KeyValueDriver;` (`traits.rs:31`). A `pub trait` anchor does not
   match a re-export, so the governed contract stopped resolving — the check degraded to
   watching nothing. This is the anchor failure behind 2 of the 4 baseline test failures.

2. **Line-counting cannot see a relocation.** `classifyContractChange` decided
   "breaking" from removed *lines* inside the item's span. P5 moved 11 default-method
   bodies out to free `pub(crate) fn`s in `traits/{sql_text,streaming,command_api}.rs`,
   plus `bytes_to_hex` shifted out of the span above the trait, plus the closing brace
   moved 1111→1020. That read as **12 removed lines** → `breaking`, which then demanded a
   `PROTOCOL_VERSION` bump.

Neither is a protocol break: the signature set is what a downstream implementor compiles
against, and it did not change for `KeyValueDriver` at all (a byte-identical move).

### The crate-version finding was real

After the two false positives were removed, a **genuine** `additive` finding remained:
`DatabaseDriver` gained 2 defaulted methods (`default_host`, `default_port`) without a
crate bump. That is owed and is paid (`0.0.9` → `0.0.10`).

## Open items awaiting adjudication

1. **No `PROTOCOL_VERSION` bump is owed; the threshold stays at 4.** The gate had been
   demanding `4 -> 4`. Both findings that triggered it were false positives, so they are
   gone rather than satisfied. `PROTOCOL_VERSION 4 -> 4` in the gate's own summary line is
   now the correct end state, not an unmet obligation. (`AGENTS.md`: a `PROTOCOL_VERSION`
   change would need all plugins synced — avoided entirely.)

2. **The trait branch is a semantic refinement, and it changes two verdicts.**
   `database-driver` breaking → **additive**; `key-value-driver` breaking → **additive**.
   This is justified by the gate's own definition of breaking (a downstream consumer must
   be edited and recompiled, per the `inspectMemberDiff` header). It is **not** a
   weakening: required additions, signature changes, signature removals and
   required↔defaulted flips all still report `breaking`, and each has a test. Please
   confirm the verdict change is acceptable.

3. **Body-only churn inside a trait with an unchanged signature set is `additive`, not
   `cosmetic`.** Deliberate: something the crate serves moved, so the crate version is
   owed, and `additive` findings are always printed. Honest trade-off — a genuinely
   *edited* default body also lands in `additive` instead of being called out separately.

4. **`Cargo.lock` is outside this track's declared scope.** One line, regenerated by
   `cargo` from the `Cargo.toml` bump. It is the mechanical, unavoidable consequence of
   paying finding 3, and leaving the lock stale would itself be a defect. Flagging loudly
   rather than hiding it; `0.0.x` crates treat every patch as mutually incompatible, so
   the bump is semantically free.

5. **The `e.g. mod key_value; | …` samples in the reasons are noise.** They come from the
   OR-based `inScope` range test counting header insertions once the span shifted. They
   do not affect any verdict. Narrowing `inScope` was deliberately left out of scope.

6. **`pnpm run <script>` cannot execute in this worktree without
   `--config.verify-deps-before-run=false`.** pnpm 12's pre-run dependency verification
   tries to create the workspace hoist directory inside `node_modules`, which is a
   symlink here (dated Oct 7, gitignored), and fails before any script body runs. This is
   a worktree-setup artifact, unrelated to the change — the same script exits 0 when
   invoked directly as `node scripts/check-driver-protocol-compat.mjs`. Worth fixing in
   the worktree bootstrap so CI parity can be checked locally.

## Design notes

- **Repointing `file` increases coverage.** The rule is still governed, still diffed, and
  is now checked where the declaration actually lives. This is deliberately *not* the
  forbidden "point at a path that doesn't exist so a check skips".
- **`previousFile` self-invalidates.** It is read only when `file` has no blob at the base
  ref. Once the base ref moves past the move, the anchor is no longer in `previousFile`
  and the rule reads as a brand-new addition, exactly as it would have without the field.
  A test asserts that invariant against the real tree.
- **`previousFile` was mandatory, not cosmetic.** Repointing alone trips the
  "removed outright" branch, because the base blob for the new path is `null`.
- **Required-ness for traits comes from the signature set, not from diff lines.** Every
  line of a relocated file is an addition, so a line-based required-addition test would
  false-positive on the moved methods. There is a regression test for exactly this.
