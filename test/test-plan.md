## 2. 测试目标

1. 验证 DataZen 所有用户可见功能在正常和边界条件下的正确性
2. 验证 UI 交互的流畅性和一致性（多窗口、主题切换、国际化）
3. 验证各数据库驱动（PostgreSQL、MySQL/MariaDB、SQLite、Redis）的核心操作
4. 验证 AI 辅助功能的可用性和容错性
5. 验证数据同步、备份恢复功能的完整性
6. 发现并记录所有功能缺陷，提供可重现的 Bug 报告

## 5. 测试策略

### 5.1 测试方法

采用 **基于功能的黑盒测试**，结合以下技术：

1. **等价类划分** — 将输入数据分为有效/无效等价类
2. **边界值分析** — 测试输入边界（空值、最大长度、特殊字符）
3. **状态转换测试** — 验证连接状态机（断开→连接中→已连接→错误）
4. **错误猜测** — 基于经验预测可能的故障场景
5. **探索性测试** — 通过自由操作发现未预期的问题

### 5.2 测试类型

| 类型 | 描述 |
|------|------|
| 冒烟测试 | 核心功能快速验证（连接、查询、浏览） |
| 功能测试 | 每个功能点的正向和反向测试 |
| UI 测试 | 界面元素显示、布局、响应式、主题一致性 |
| 兼容性测试 | 各数据库驱动的行为一致性 |
| 容错测试 | 异常输入、网络断开、超时等场景 |

### 5.3 自动化测试工具

通过 **zavora-ai/computer-use-mcp** 实现桌面 GUI 自动化：

- 截图捕获与视觉验证
- 鼠标点击/拖拽操作
- 键盘输入模拟
- 屏幕元素定位

**配置方式**：参见 `test/mcp-setup.md`

## 6. 测试执行计划

### 6.1 阶段划分

| 阶段 | 周期 | 内容 |
|------|------|------|
| **第一轮：冒烟测试** | 0.5 天 | 核心功能可用性验证（TC-CONN-*、TC-QUERY-* 基础用例） |
| **第二轮：功能测试** | 2 天 | 全部 P0/P1 测试用例执行 |
| **第三轮：回归测试** | 1 天 | Bug 修复后的回归验证 + P2 用例 |
| **第四轮：探索性测试** | 0.5 天 | 自由探索 + 边界场景 |

### 6.2 入口标准

- 应用可正常编译并启动 (`pnpm tauri dev`)
- 至少一个数据库实例可用（PostgreSQL 推荐）
- computer-use-mcp 服务器已配置并可连接

### 6.3 出口标准

- 所有 P0 用例通过率 100%
- 所有 P1 用例通过率 ≥ 95%
- 无 P0/P1 级别未修复 Bug
- 所有 Bug 已记录并分配

## 7. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 数据库实例不可用 | 阻塞连接相关测试 | 提前准备 Docker 容器化数据库 |
| AI Provider API Key 未配置 | AI 功能无法测试 | 使用测试 API Key 或 Mock |
| computer-use-mcp 不稳定 | 自动化测试中断 | 保留手动测试回退方案 |
| 多窗口测试复杂度高 | 截图/定位困难 | 逐窗口独立测试 |
