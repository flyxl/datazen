## Bug 描述

### 场景
在 SQL 查询编辑器中执行一个长时间运行的查询后，点击"停止"按钮，UI 显示查询已停止（按钮恢复为"执行"），但后端数据库查询实际上继续执行。

### 预期结果
1. 点击"停止"后，后端向数据库发送取消信号（PostgreSQL: `pg_cancel_backend`, MySQL: `KILL QUERY`）
2. 查询在数据库端被中断
3. 前端显示"查询已取消"提示

### 实际结果
1. 前端 `running` 状态设为 `false`，UI 恢复
2. 后端 `cancel_query` 调用驱动的 `cancel_query()` 方法
3. 所有内置驱动的 `cancel_query()` 为**空实现**，直接返回 `Ok(())`
4. 数据库端查询继续执行直到完成

---

## 根因分析

**文件**：`src-tauri/src/db/postgres.rs` 第 734-736 行

```rust
async fn cancel_query(&self, _handle: &ConnectionHandle) -> Result<(), DriverError> {
    Ok(())
}
```

MySQL、SQLite、Redis 驱动同样为空实现。

**前端**（`src/stores/queryStore.ts` 第 204-210 行）调用后端后直接设置 `running: false`，无取消反馈消息。

---

## 影响范围

- **影响**：用户无法真正取消长时间查询，可能导致数据库资源占用
- **关联测试用例**：TC-QUERY-006

---

## 修复方案

**修复文件**：
1. `src-tauri/src/db/postgres.rs` — 实现 `cancel_query()`：通过 `pg_cancel_backend()` 取消同数据库内活跃查询
2. `src-tauri/src/db/mysql.rs` — 实现 `cancel_query()`：通过 `KILL QUERY thread_id` 取消活跃查询
3. `src-tauri/src/db/sqlite.rs` — 添加 debug 日志（SQLite 为进程内单连接，不支持取消）
4. `src-tauri/src/db/redis_driver.rs` — 添加 debug 日志（Redis 命令为原子操作，不需取消）
5. `src/stores/queryStore.ts` — `cancelQuery` 添加错误容错和取消反馈消息

**PostgreSQL 实现**：
```sql
SELECT pg_cancel_backend(pid)
FROM pg_stat_activity
WHERE pid != pg_backend_pid()
  AND state = 'active'
  AND datname = current_database()
```

**MySQL 实现**：
```sql
SELECT id FROM information_schema.processlist
WHERE id != CONNECTION_ID() AND command != 'Sleep' AND info IS NOT NULL
-- 然后对每个 thread_id 执行：
KILL QUERY {thread_id}
```

## 回归测试验证

| 项目 | 内容 |

| **验证日期** | 2026-08-02 |

| **验证结果** | ✅ 通过 |

**验证步骤**：

### PostgreSQL 验证
1. 在后台启动 `SELECT pg_sleep(30)` 长查询
2. 使用与 `cancel_query` 相同的逻辑查找并取消活跃查询
3. **结果**：`pg_cancel_backend` 返回 `t`（成功），后台查询收到 `ERROR: canceling statement due to user request` 错误并终止

```
 pg_cancel_backend |  pid  |        query
-------------------+-------+---------------------
 t                 | 25958 | SELECT pg_sleep(30)
```

### MySQL 验证
1. 在后台启动 `SELECT SLEEP(30)` 长查询
2. 使用与 `cancel_query` 相同的逻辑查找活跃线程并执行 `KILL QUERY`
3. **结果**：线程 63 被成功找到并终止，`SLEEP(30)` 返回 `1`（被中断）

```
id    info
63    SELECT SLEEP(30)
Killing thread: 63
```

### 前端验证（代码审查）
- `queryStore.ts` 的 `cancelQuery` 已添加 try-catch 错误容错
- 取消后设置 `error: 'Query cancelled'` 提供用户反馈
