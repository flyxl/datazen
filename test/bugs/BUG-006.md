## Bug 描述

### 场景
在新建连接窗口中，标有红色 `*` 必填标记的字段（连接名称、主机地址、端口）没有实际的客户端验证。用户清空这些字段后，点击"保存"或"测试连接"不会报验证错误，而是：
1. 空的连接名称会被自动回填为"未命名连接"
2. 空的主机地址会被回填为 `127.0.0.1`
3. 空的端口会被回填为默认端口

### 预期结果
1. 用户清空必填字段后，保存按钮应禁用或点击时显示验证错误
2. 必填字段应有即时的验证反馈（如红色边框、错误提示）

### 实际结果
1. 必填标记 `*` 仅为视觉装饰，无实际校验逻辑
2. `draft` 构建时会用默认值回填空字段
3. 提交时不检查字段有效性，直接发起连接

---

## 根因分析

**文件**：`src/components/connection/useConnectionForm.ts` 第 200-229 行

`draft` 构建逻辑中自动回填：
```typescript
name: name.trim() || t('newConn.unnamed'),
host: host.trim() || draftMeta.defaultHost,
port: parseInt(port) || draftMeta.defaultPort,
```

`onTest()` 和 `onSave()` 回调中无 `validateDraft()` 检查。

---

## 影响范围

- **影响**：用户可能误保存使用默认值的连接
- **关联测试用例**：TC-CONN-005

---

## 修复方案

**修复文件**：
1. `src/components/connection/useConnectionForm.ts` — 添加 `validate()` 函数和 `validationErrors` 状态
2. `src/components/connection/StandardConnectionFields.tsx` — 显示 host/port 验证错误
3. `src/components/connection/FileConnectionFields.tsx` — 显示 database 文件路径验证错误
4. `src/locales/zh-CN.ts` / `src/locales/en.ts` — 添加 `newConn.required` i18n key

**修复逻辑**：
- `validate()` 检查标准连接的 host/port、文件连接的 database 路径是否为空
- `onTest()` 和 `onSave()` 在执行前调用 `validate()`，验证失败则阻止提交
- 验证失败的字段显示红色边框和错误提示
