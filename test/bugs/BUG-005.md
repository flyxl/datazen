## Bug 描述

### 场景
在 MySQL 连接窗口中，对一条 SQL 查询执行 EXPLAIN 分析后点击"AI 分析"按钮，当 DeepSeek AI Provider 返回包含中文字符的 JSON 响应时，Rust 后端的日志记录代码在截断响应内容时发生线程 panic。

### 预期结果
AI 分析结果正常显示在 EXPLAIN 面板中，包含执行计划瓶颈分析和优化建议。

### 实际结果
1. **后端**：`tokio-rt-worker` 线程 panic，错误信息：
   ```
   thread 'tokio-rt-worker' panicked at src-tauri/src/commands/ai.rs:477:50:
   byte index 500 is not a char boundary; it is inside '定' (bytes 498..501)
   ```
2. **前端**：UI 先卡在"分析中..."状态，随后整个应用窗口消失（进程退出）。
3. **进程**：`tokio-rt-worker` 线程 panic 最终导致整个 DataZen 进程崩溃退出，所有未保存的工作丢失。

## 根因分析

### 直接原因

**文件**：`src-tauri/src/commands/ai.rs` 第 477 行

```rust
tracing::info!(
    response_content = %&response.content[..response.content.len().min(500)],
    "ai_analyze_explain: response content"
);
```

Rust 的字符串切片操作 `[..500]` 使用**字节索引**，而 UTF-8 中文字符占 3 个字节。当字节 500 落在一个多字节字符中间时（如 `'定'` 占字节 498-500），就会发生 panic。

### 系统性问题

**同样的不安全截断模式存在于至少 8 处代码中**：

| 文件 | 行号 | 截断长度 |
|------|------|----------|
| `src-tauri/src/commands/ai.rs` | 397 | 500 |
| `src-tauri/src/commands/ai.rs` | 458 | 300 |
| `src-tauri/src/commands/ai.rs` | **477** | **500** ← 本次触发 |
| `src-tauri/src/commands/ai.rs` | 491 | 500 |
| `src-tauri/src/commands/ai.rs` | 610 | 100 |
| `src-tauri/tests/ai_e2e.rs` | 378 | 200 |
| `src-tauri/src/commands/backup.rs` | 162 | 80 |
| `src-tauri/src/ai/custom.rs` | 346 | 500 |

### 为什么在此场景触发

- DeepSeek 返回的 EXPLAIN 分析结果是**中文 JSON**（如 `"全表扫描且无可用索引，查询存在性能瓶颈。"`）
- 中文字符每个占 3 字节，500 字节约为 ~166 个中文字符
- 在这个响应中，恰好字节 498-500 是字符 `'定'`，导致截断点落在字符中间

---

## 修复建议

创建一个安全的字符串截断辅助函数，确保截断在字符边界上：

```rust
/// 安全截断 UTF-8 字符串到指定字节长度（在字符边界上截断）
fn truncate_str(s: &str, max_bytes: usize) -> &str {
    if s.len() <= max_bytes {
        return s;
    }
    let mut end = max_bytes;
    while end > 0 && !s.is_char_boundary(end) {
        end -= 1;
    }
    &s[..end]
}
```

然后将所有 `&content[..content.len().min(N)]` 替换为 `truncate_str(&content, N)`。

```rust
fn truncate_str(s: &str, max_bytes: usize) -> &str {
    if s.len() <= max_bytes { return s; }
    let mut end = max_bytes;
    while end > 0 && !s.is_char_boundary(end) {

    }
    &s[..end]
}
```
- 使用 `is_char_boundary()` 确保不在 UTF-8 多字节字符中间截断 ✅

**3. 原有不安全截断已全部替换**：
