# e94796bf native formatter baseline

Measured on the unchanged production formatter sources at
`e94796bf12a6f12f7b55f32d39ee5e9e5d0164af`, using rustc 1.100.0 and LLVM
23.1.5 on Linux x86_64. This measures the formatter crate, not the Native
host, syntax compatibility, branch coverage, or every SQL dialect.

| Evidence | Passed | LLVM production lines |
| --- | ---: | ---: |
| Real Native Query UI: SQLite, PostgreSQL 17.12, Oracle MySQL 8.4.11, MariaDB 11.8.9 | 39 journeys / 68 rendered profiles | 1,726/1,895 (91.08%) |
| Separate non-T-SQL public API consumer: 74 conformance + 6 limits + 107 atomic refusals | 187 process cases | 1,773/1,895 (93.56%) |
| Deduplicated E2E union | | 1,833/1,895 (96.73%) |
| Only the three directed T-SQL Rust unit cases, independently | 3 cases in 1 profile | 742/1,895; all 42 T-SQL-only mapped lines |
| **Deduplicated E2E + directed T-SQL units** | | **1,877/1,895 (99.05%)** |

The process cases add 107 lines not hit in the Native UI; the three T-SQL
unit tests add 44 lines beyond the whole E2E union. No generic unit profile,
failed run, reference-JavaScript execution counter, fixture credential CLI
profile or SQL Server E2E run counts. The 68 validated UI profiles were
retained; an additional public-selector repeat verified routing and was not
double-counted. Real SQL server authentication was needed to select the actual
driver, but Format did not execute the authored drafts.

All inputs were mapped against the **same** actual selective-coverage Native
ELF (SHA-256 `a47281f3cec227ad7c6ed7bcb3273554d63c75c341638dbd426204029acab9c5`).
The external consumer and the directed unit harness linked the original
instrumented rlib (SHA-256 `e7b2579af5ecc3c1f433af622bf656c40afaa0a7556af9d9371a40ad9b67f577`).
The verifier checked counter sums for all 302 mapped function records,
all region coordinates, and all ten production source files. The production
files were byte-identical. No counters were imported from a second build.

The unchanged 1,895 denominator is the LLVM file-summary line metric reported
by `llvm-cov report`/`export -summary-only`. In contrast, collapsing LCOV
`DA` rows to distinct (file, source-line) keys gave 1,768/1,783 physical
keys after the final union (99.16%). In this physical-key metric Native alone
was 1,623 and the external consumer alone was 1,671; their union was 1,726,
then the T-SQL units added 42 unique keys for the final 1,768. Both the
physical and LLVM-summary mixed totals pass the 99% threshold. Different
closures or instantiations may map the
same physical location. The [18 LLVM-summary misses](e94796bf-missing-lines.tsv)
include 15 physical zero-hit locations and three additional function contexts
on otherwise covered physical lines. Do not add the percentages or mix
denominators. [Run the complete gate](../../../../e2e/rune/README.md#formatter-only-line-coverage-on-linux).
